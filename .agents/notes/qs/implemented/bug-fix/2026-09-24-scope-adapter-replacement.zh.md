# Agent Note: scope adapter replacement

Status: implemented

[English](2026-09-24-scope-adapter-replacement.md) | 中文

## Problem

连接插件替换会移除并重新安装依赖它的会话适配器。把中间的缺失当作启动错误会在槽条目错误边界之外抛出异常，即使传输恢复，React 应用也已经被销毁。

## Decision

已挂载的作用域提供者在已安装适配器缺失期间保留名单订阅，但卸载适配器拥有的绑定子树及订阅。替代适配器提供新的绑定。首次缺少适配器仍属于装配错误，因而暂停渲染不会掩盖缺失的启动配置。

恢复保持在渲染器既有的[职责层](../../../implemented/architecture/2026-08-20-client-session-conversation-ownership.zh.md)内，不保留陈旧会话数据源，也不让连接传输了解 React。该决策继续有效，没有替代既有活动笔记。被移除子树的组件本地状态会丢失：通过借用已释放适配器保留状态会留下无效所有者。

检查清单发布还有独立的异步所有者，即提供注册表的插件。插件释放时关闭注册表、丢弃排队发布、取消本地查询控制器，并抑制释放后才到达的失败；活动实例的失败仍然可见。让旧注册表向新连接重试可能发布已撤销的能力目录，因此替代插件拥有自己的新注册表。

## Alternatives considered

刷新页面可以恢复应用，但会丢弃文档，不能保留 HMR 生命周期。继续使用旧适配器会通过已释放的所有者渲染。忽略所有缺失适配器会掩盖初始装配错误。吞掉所有发布错误也会隐藏活动注册表的失败。因此采用显式释放所有者，以及已挂载作用域的可恢复暂停。

## Consequences

回归必须证明首次缺失会拒绝、卸载断开旧订阅、旧源更新不能进入恢复后的树，以及后续安装恢复渲染。真实浏览器必须在同一文档通过生产 HMR 路径，观察旧 WebSocket 关闭、新连接打开，并验证业务操作恢复。刷新页面不能证明此行为。
