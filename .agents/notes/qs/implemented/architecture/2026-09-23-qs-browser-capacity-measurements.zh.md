# Agent Note: 奇术浏览器容量测量

Status: implemented

[English](2026-09-23-qs-browser-capacity-measurements.md) | 中文

## Problem

持久事件数、已加载阅读节点和浏览器 DOM 节点代表不同成本。快速投影或通过界面测试，不能证明长历史浏览器延迟和保留内存符合要求。

## Decision

奇术长历史浏览器清单复用官方合成 Session 生成器和 Web scaffold，使用已构建 Client 资源。生成器接受轮数参数并保留原默认值。每个样本创建私有 scaffold 和浏览器，对可观察动作跨渲染机会计时，输出全部样本、实际事件数和机器元信息。

清单在显式 GC 后记录堆和 DOM 指标，包括退出后的即时检查点。该检查点可能包含延后清理，不能证明稳定泄漏或完全释放。源码装配的测试 Host 不构成发布 Host 启动证据。在目标执行环境校准前，测量不设置时间阈值。

工具载荷清单通过官方事件与流式构造器创建一个已完成的两步 Session，将参数和结果字节数与历史长度分别控制，验证完整呈现内容，测量首次展开、内层参数展开、草稿输入与重新展开。各动作记录到最后一次呈现机会为止的浏览器长任务。每档六个独立世界，首个样本单列，其余五个只用于探索中位数，不作为百分位门禁。

## Alternatives considered

**复制夹具生成器。** 独立的事件构造可能偏离官方合法历史，因此不采用。

**把所有持久事件计为已加载 DOM。** 分页有意限制可见历史及测量工作量，因此不采用。

**把延迟格式化视为成本消除。** 展开惰性详情仍会执行解析、格式化及浏览器文字排版，因此不采用。收起状态测试不能证明激活成本符合预算。

## Consequences

三十次样本支持本地探索性比较，不构成 p95 验收结论。流式更新、全量已加载历史、文件上限和稳定卸载状态需要独立证据。既有性能工作流决策继续负责校准和回归政策；本记录仅定义奇术测量清单的证据限制。
