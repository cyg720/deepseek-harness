# Agent Note: 预设重启的绑定所有者

Status: implemented

[English](2026-09-24-preset-restart-binding-owner.md) | 中文

## Problem

空白 Agent 的生存期可能长于预设提供者的 Loader fiber。作用域祖先仍有绑定，但替代服务丢失了私有重绑定句柄。因此目录读取和选择控件正常时，重试选择仍会报作用域已经绑定。

## Decision

以稳定的 Loader 条目身份保留作用域绑定表，条目和 Agent 作用域均使用弱引用键。同一条目中的替代提供者只能恢复原先的能力。直接装配的服务以自身实例为所有者。不同条目即使预设名称相同也互相隔离。

## Alternatives considered

**允许任意作用域重新绑定。** 不采用，因为只有原始绑定能力可以修改作用域祖先。

**共享全局 Agent 绑定表。** 不采用，因为其他注册所有者可能获得从未持有过的重绑定能力。

**提供者重启后刷新浏览器。** 刷新无法修复 Host 丢失的能力，也会让验收绕过中断处理。

## Consequences

此方案支持同一 Loader 条目切换启用状态后，为仍存活的空白会话显式恢复选择。它不在提供者缺失期间维持活动预设注册，不向其他条目转移所有权，也不允许为已开始轮次的会话重新组成。既有按会话组成设计仍负责常驻挂载及选择日志。真实 Host 浏览器证据必须断言 RPC 结果及持久化选择事件，不能仅检查乐观更新的下拉框值。
