# Agent Note: 会话控制流恢复的所有权

Status: implemented

[English](2026-09-23-session-control-recovery.md) | 中文

## 问题

奇术作业列表需要可见的失败状态和重试，但会话目录就绪不能证明控制基线已到达。RemoteSnapshotStream 的终止失败会结束消费者；重启已经中止的物理流不能恢复它。

## 决策

Session Controller 持有唯一 SessionControlOwner，通过 ISessions.control 提供只读状态，保留既有帧接收器。载体中断仍由 Gateway 自动重连。终止失败重试等待旧流处置后再替换，合并并发请求，忽略旧实例回调。插件卸载禁止替换并等待在途处置。原始错误只进入诊断输出，不进入界面可读状态。

baseline 计数标识已接收基线，不是 Connection 身份。它本身不提供完成通知所需的作用域事件流。领域快照保持既有发布时序。

[后台作业呈现决策](../../../implemented/feature/2026-08-08-web-background-job-display.zh.md) 继续负责线协议字段和只读任务呈现；[传输决策](../../../implemented/architecture/2026-08-18-session-history-and-event-transport.zh.md) 继续负责载体恢复及基线规则。两者均保持有效：本记录新增终止消费者替换，不新增传输或任务注册表。

独立 qs-ui-jobs 对应插件通过会话标题动作槽读取该状态，区分已就绪的空基线与等待或加载失败；保留陈旧记录并给出提示，提供终止失败重试。不提供作业修改动作，也不在缺少公开关联时虚构结果位置。

## 验证

可控处置测试覆盖并发重试、迟到回调和卸载竞争。真实 Client 装配测试制造重复基线协议失败，重试后观察到新基线。不引入任务取消或结果接口。

## 后果

功能可以观察控制流就绪状态，无需另开流。终止恢复可能等待异步处置，处置失败时拒绝。作业呈现和带作用域的完成通知仍是独立消费者。

## 考虑过的替代方案

**重启已终止的流。** restart 不能恢复已关闭消费者。

**视图自行再开流。** 这会重复状态权威和清理责任。

**复用会话目录就绪状态。** 这会混淆两份独立到达的数据。
