# Agent Note: 奇术已观察作业通知

Status: implemented

[English](2026-09-23-qs-observed-job-notifications.md) | 中文

## 问题

控制流就绪通知与另行批处理的作业列表可能属于不同基线。立即比较可能将恢复的历史终态误报为新完成。Toast 也需要比权威作业注册表更小的保留范围。

## 决策

ClientSessions 在控制流所有者发布就绪前，同步投影已接收基线；领域增量仍保留批处理。奇术消费这些共享来源，不新建 RPC 流，仅报告已观察到运行中或停止中转为终态的作业。首次终态、基线变化及连接代次变化均静默。

既有作业呈现插件持有观察者及生命周期，外壳持有纯文本 toast 和经验证的 notificationCapacity。默认最多保留 256 个作业身份及 256 个已访问会话身份；这是存储界限，不是经测量的延迟目标。当前可访问目录外的记录被移除。淘汰后因此前活动未知，可能不再通知后续完成，但不会编造完成；作业列表仍是权威来源。

退出、插件卸载及工作台隐藏时停止投递通知。不引入持久已读记录或系统推送。通知显示所属会话及终态，不显示任意作业标签或结果正文。恢复或重新挂载的观察者静默建立初始状态。

## 已考虑的替代方案

**逐视图 effect** 会在多视图同时挂载时重复通知。

**未经协调的快照读取** 在就绪状态与旧列表缺少共同发布保证时，混淆回放与实时转换。

**历史重放或无界保留** 让通知行为依赖历史数据而非已观察变化。

## 影响

恢复不会制造完成通知，保留的通知身份数量受部署配置限制。已淘汰或尚未观察的活动状态不能作为后续通知依据；用户从权威作业列表查看这些结果。基线在就绪前同步完成列表投影，领域增量继续批处理。

## 验证

已接收基线的回归在没有同步投影时失败。可控来源测试覆盖重连发布、会话与尝试身份、容量淘汰、退出和排队回调的卸载。插件生命周期测试覆盖重装及本地化正文。真实 Host／浏览器测试观察三种终态，并验证刷新不重放通知。
