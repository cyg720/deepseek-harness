# Agent Note: 共享呈现基础接口

Status: implemented

[English](2026-09-20-shared-presentation-primitives.md) | 中文

## 问题

二开呈现需要使用官方执行状态，同时避免导入私有组件实现或复制 Session、反馈、导航和触发器控制器。

## 决策

官方 owner 提供共享呈现注入及预览身份。工作台把交互渲染放在固定会话座位，并按有效槽位注册分派转写行。分页由官方执行器报告带请求身份的结果；连接变化使旧结算失效。可见输入消费者取得独占来源策略，释放后的迟到命令仲裁被拒绝。

## 考虑过的替代方案

- 复制官方存储会导致草稿、导航和资源保留状态分叉。
- 把请求执行移到 QS 组件会丢失权威错误，并让视图卸载拥有已经接受的操作。
- 固定转写类型白名单会阻止独立扩展插件贡献行。

## 后果

这些基础接口已经实现，但不代表第二优先完整装配已验收。新的右栏、反馈、预览及目录呈现仍需要对应的真实插件消费者和生命周期验收。可见消费者取得租约前，触发器来源保持禁用。官方和 QS 输入在挂载及卸载时取得与释放各自策略；同步和异步来源返回值均不能跨越租约变更。

现有[工作台插件家族决策](2026-09-17-qishu-workbench-client-plugins.zh.md)仍然有效：插件对应、外观隔离和官方界面切换的理由未被替代。本记录只拥有新增的共享状态决策。
