# 授权中心后端服务验收报告

本报告对应[授权中心产品需求文档 0.4.2](../../../qishu/PRD/2-授权中心/授权中心.prd.md)与[平台公约 1.0](../../../qishu/PRD/平台公约.md)，记录本次接口开发的实现范围、实际执行结果、发现的缺陷与修复、以及仍需产品确认的事项。所有结论都来自本机实际执行，未执行的部分明确标注。

## 一、交付范围

按第五章路径表实现 API-01 至 API-18 中未被删除的全部接口，共 19 组路径：账号、组织、账号组织关联、用户组、用户组成员、参数、字典、操作、权限组、用户权限组关联、组织权限组关联、应用授权、鉴权、会话令牌、场景令牌、密码维护、开放能力、审计日志。委托授权（API-12/API-16）、权限刷新、中心行级数据权限按要求未实现。

代码位于 `services/authority`，使用 Spring Boot 4.1.1、Java 21、MyBatis 4.1.0、Flyway 12、PostgreSQL 18（`services/docker` 提供）；接口文档由 springdoc 3.1.1 生成，Swagger UI 与 Knife4j 界面均可访问。

## 五、发现的缺陷与修复

开发过程中发现并修复的实现缺陷，均已纳入回归用例：

| 缺陷 | 现象 | 修复 |
| --- | --- | --- |
| 生成键映射 | 操作表 id 不是首列，插入后回填主键失败，启动初始化中断 | 插入语句显式声明 `keyColumn="id"` |
| 内置身份未落库 | 超级管理员插入时缺少 `is_super_admin` 列，建成的账号不是内置身份 | 插入语句补齐该列，管理接口固定写 false |
| UUID 字段映射 | MyBatis 不自动映射 `UUID` 类型属性，`session_id` 与 `uuid` 读回为 null，导致退出登录未撤销任何令牌 | UUID 列统一用文本读写（`::text` / `CAST(... AS uuid)`），Java 侧用字符串承载 |
| 审计身份缺失 | 认证拦截器提前清空上下文，审计行缺少账号与应用 | 上下文清理移到请求结束的过滤器，审计可读取身份 |
| 约束错误码 | 按异常文本匹配 SQLState，唯一冲突被返回 40001 | 按 `SQLState` 与 `DuplicateKeyException` 区分 40902/40903 |
| 权限查询截断 | 应用操作超过 1000 条时静默截断 | 改为按应用全量查询，不截断 |
| 子树路径溢出 | 移动子树时只校验自身路径，后代超长落到数据库约束，返回无字段定位的 40001 | 移动前按子树最长路径判定并给出字段错误 |
| 首次改密可读本人信息 | 受限身份读取本人详情返回 40303 | `/users/me` 标注为强制改密阶段可调用 |
| 列表泄露字段 | 应用授权列表返回 `appKey` 字段（值为 null） | 列表改用不含 AppKey 的响应模型 |

## 八、与 PRD 的偏差与自主决策

以下决定在 PRD 未明确处作出，交付时一并说明；如与产品预期不符，可实现调整。

| 事项 | 决定与理由 |
| --- | --- |
| PostgreSQL 版本 | 使用 `services/docker/docker-compose.yml` 固定的 18.4，而非 PRD 文本中的 18.6；数据目录由 Compose 管理，改版本需要单独迁移 |
| Knife4j 集成方式 | 只引入 Knife4j 的静态界面，不引入其 starter：knife4j 4.5.0 固定依赖面向 Spring Boot 3 的 springdoc 2.x，与 Spring Boot 4 不兼容 |
| 管理接口鉴权 | 授权中心把自身 64 项管理操作登记到自己的应用下；管理接口要求“授权中心自身应用对该账号可见”且拥有对应操作，与鉴权接口判定一致。Q-01 的普通管理角色因此可通过权限组与可见范围精确授权，不需要额外的角色模型 |
| 应用中心受控身份 | 用 `AUTH_APP_CENTER_KEY` 配置的 AppKey 认定应用中心，替代 Q-16 未定的初始化方案；未配置时启动失败，不生成无人知晓的凭据 |
| 令牌摘要算法 | 未定项 Q-06 取 SHA-256；只存摘要，明文仅在签发响应返回一次 |
| 口令散列 | 未定项 Q-05 取 BCrypt |
| AppSecret 存储 | 只存摘要、仅在建立授权记录时返回一次；当前鉴权不校验 AppSecret，与 BR-01 一致 |
| 场景令牌 | 完成签发与鉴权，沿用当前登录实例与同一有效期规则；兑换与重连语义仍待产品明确 |
| 账号删除与令牌 | 按 BR-19「删除不连带 token」实现，因此有登录记录的账号会被 40903 阻止删除；从未登录且无其他关联的账号可以删除。如需允许删除带令牌的账号，需要产品确认可否一并删除令牌 |
| 参数值长度上限 | 列类型为 TEXT，接口层限制 65535 字符，避免无界请求体 |
| 审计覆盖范围 | 只记录进入 `/api/v1/auth/**` 路由的请求；方法不匹配等路由级拒绝不产生审计行 |
| 审计写失败语义 | 授权判定在同一事务内写审计，写失败即回滚且不返回许可；其余请求业务已提交，审计失败只记录错误日志并保留真实响应，不把已生效的写入改判为失败。原先的 `authority.audit.blocking` 开关已移除 |
| 应用凭据交付 | AppKey 与 AppSecret 只在建立授权记录的一次性响应中返回；详情、列表、配置与状态同步响应都不包含可用作身份的字段 |

## 十、复现步骤

```bash
# 1. 启动基础服务（首次执行会生成口令并写入 services/docker/.env）
services/docker/start.cmd

# 2. 全量接口验收用例（独立测试库，自动建表）
cd services/authority
AUTH_DB_PASSWORD="$(grep '^POSTGRES_PASSWORD=' ../docker/.env | cut -d= -f2-)" mvn -B test

# 3. 空库启动并做端到端冒烟
AUTH_SUPER_PASSWORD='Admin@12345' AUTH_SELF_APP_KEY='self-console-key-0001' AUTH_APP_CENTER_KEY='app-center-key-0001' \
  scripts/run-local.sh
BASE=http://127.0.0.1:8090 SELF_KEY='self-console-key-0001' CENTER_KEY='app-center-key-0001' \
  ADMIN_PASSWORD='Admin@12345' bash scripts/smoke.sh

# 4. 数据库结构验证
docker exec -i -e PGPASSWORD="$(grep '^POSTGRES_PASSWORD=' services/docker/.env | cut -d= -f2-)" \
  qs-local-postgres-1 psql -U qs -d qs -f - < scripts/verify-schema.sql
```

接口文档：`http://127.0.0.1:8090/swagger-ui.html` 与 `http://127.0.0.1:8090/doc.html`。
