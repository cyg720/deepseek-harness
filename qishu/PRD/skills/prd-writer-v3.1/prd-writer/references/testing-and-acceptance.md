# 测试用例、数据生成与验收编制规范

适用于 create/revise 的第九、十章；review 用此规范指出具体缺口。lite 可缩小适用范围，但不能只给测试方向；生成文档必须保留下面的实际内容，不得仅链接本规范。所有新增业务假设标为建议或 Q，示例程序运行结果与业务验收分开记录。

## 逐条测试用例 TC

先列用例总表，再逐条填写详情；小文档可采用一张包含全部字段的表。每个用例必须使另一位测试人员无需猜测操作与预期即可执行。

| 必填项 | 编制要求 |
|---|---|
| 编号与目标 | 稳定 TC、标题、优先级及理由、验证层级/类型、关联 US/BR/AC/API；无接口写 N/A |
| 角色与准备 | 登录身份或本地模拟身份、动作/对象/字段权限、数据范围、环境、初始状态、依赖可用条件 |
| 测试数据 | TD 编号与记录选择器、准确字段值或可计算边界；非法输入不得先作为合法数据库种子装载 |
| 操作步骤 | 使用 1、2、3 列出准备、操作与观测；API 方法/路径必须有资料依据或标明设计草案 |
| 可观察断言 | UI 提示、HTTP 与业务码分列、响应字段、持久数据/状态/版本、外部动作与审计按适用性写明 |
| 禁止副作用 | 例如无越权数据返回、无版本覆盖、无重复发货；不能只有“正确拒绝” |
| 清理与结果 | 清理对象/顺序、幂等重跑、初始状态恢复、执行状态、实际值、证据位置；未执行不得填通过 |

按具体风险展开正向、空/边界、缺失/null/空串、唯一性、权限/范围/字段、并发、幂等/重试、合法/非法状态、依赖故障/恢复、迁移与性能场景。无删除就不补删除用例；有状态机则每条迁移均有覆盖。参数化用例可以复用步骤，但每组输入和对应预期必须列出。相同业务码不代表全部失败副作用相同。

关键未知项不得藏在“预期成功”中。能确定“不返回无权对象”的断言可以明确，无法确认的 HTTP、码值、唯一范围、审计位置等直接关联 Q；标出哪些用例的执行或放行受阻。

## 可复现测试数据 TD

正文至少给出数据集清单、生成说明、完整可复制脚本或已核验工具配置、准确运行命令、输出样例、生成后校验、装载与清理。交付脚本附件时，正文仍保留重建方法，HTML 离线读者不依赖未交付文件。

| 必填项 | 编制要求 |
|---|---|
| 数据集 | TD、用途、关联 TC、文件/记录选择器、类别、记录数与分布 |
| 字段与关系 | 对照本 PRD 字段、有效类型、外键/父子顺序、唯一范围；标识仅供测试的元数据 |
| 可重复参数 | 工具版本、依赖、固定随机种子、固定参考时间/时区、隔离命名空间、生成数量和边界算法 |
| 生成过程 | 前提、工作目录、完整命令、脚本/配置与输出路径；同参数产生相同业务数据，动态项单列 |
| 具体样例 | 合法基线及适用非法/超限/越权/重复/冲突样例；显式区分故意违反规则的请求与合法装载数据 |
| 校验 | 记录数、必填、类型、引用完整性、唯一性、哈希或断言；故意非法样例按预期违规分类，不能误报为基线坏数据 |
| 装载与清理 | 隔离环境、身份配置、依赖顺序、审批范围、执行者、命名空间精确定位、删除依赖顺序、重跑行为 |

优先复用核验过的工厂、种子脚本或测试 API；不得为了让步骤看似可运行而创造项目命令。有 DDL 时与真实字段/约束一致；缺少实际 API/DDL 时生成独立 JSON 等本地合成夹具，明确夹具元数据并非业务列，将业务装载适配列 Q。未知性能规模不自行承诺目标，可提供参数化生成器，规模与分布仍待决策。

脚本只写获准的本地输出目录，不连接业务服务、上传数据或读取秘密。同目录重跑的覆盖策略必须说明；清理不能泛删数据库、其他命名空间或整个共享目录。纯本地生成器在临时目录验证成功，只能记为“测试数据生成检查通过”。

## 逐项验收 AC

第十章复用第二章的 AC 编号，逐项列出功能、权限、安全、字段/数据、状态、接口集成、异常恢复、适用非功能与迁移/发布检查。不得把多个未具名标准藏在“功能验收通过”一行，也不得另造无法追溯的验收编号。

每行至少包含：AC 与需求来源、明确放行标准、验证步骤/方法、TC/TD、期望证据、实际结果、状态、环境/构建版本、执行人/时间、实际证据位置、失败后的重验范围。表格过宽可拆“验收标准表”和按相同 AC 关联的“执行结果表”；未执行的公共环境等可在表前统一说明。

放行标准要能判定，例如“一次成功更新使版本从 1 变为 2，旧版本重试不再次修改”，而非“系统稳定”。性能必须有环境、数据分布/规模、负载、时间窗口、分位数/错误率及阈值；未批准阈值写 Q、状态阻断。文档生成、勾选或演示脚本自检不能构成业务结果。

## 交叉核对

1. 每个适用 US/BR、API 操作、状态转移和非功能条款都有 AC 和 TC；每个 TC 的 TD 均存在。缺口列出具体编号与影响，不以覆盖百分比掩盖。
2. 第二章 AC 的 Given/When/Then、第九章 TC 的预期、第十章放行标准一致；失败副作用、错误码、权限范围不互相冲突。
3. 同参数在两个临时目录生成夹具，核对内容/哈希和分类断言；记录实际命令、环境与结果。未知装载适配不得记为已装载。
4. 增量修改保留编号，列受影响的 TC/TD/AC 及重验范围；旧通过记录保留其版本与证据，新规则标待重验。
5. 状态仅为未执行、阻断、通过、失败、N/A（原因）；所有“通过”有环境、版本、执行者/时间与证据。各层验证分开报告。
