# 第一优先工作台：代码质量、安全与性能审查

审查日期：2026-09-18。范围为当前未提交开发，重点检查七个 QS 包及官方接入、转写呈现和相关测试变更。本轮不修改产品代码，不提交、不推送。

## 结论

发现 3 项需要修复的 P2 交互缺陷；QS 定向覆盖率检查不通过。依赖审计报告 38 条告警，受影响版本均已存在于 HEAD，不能归为本次新增漏洞。另有 3 项尚未测量的性能风险及媒体展示能力缺口。本轮没有足够证据认定新增 P0/P1 安全漏洞，也不能据此宣布安全验收完成。

## 确认缺陷

### P2：单选切换后夹带旧的自由文本

位置：[answer.ts](../../../../packages/qs/qs-questions/src/client/answer.ts) 第 44 行；官方对照：[QuestionComposer.tsx](../../../../packages/client/ui-user-questions/src/client/QuestionComposer.tsx) 第 196 行。

触发：单选问题先输入“其他”回答 A，再点击选项 B，最后提交。`toggleOption` 在单选分支保留 `draft.custom`，`buildAnswer` 将二者一起提交。本轮用实际导出函数执行了合成输入，输出为 `{"answers":[{"id":"q1","selected":["B"],"custom":"A"}]}`。反向操作“先选 B 再输入 A”则会清空选项，两个方向行为不一致。

影响：模型收到用户已放弃的文本，可能把两份互斥回答一起理解。官方单选选择选项时会清空 custom，多选则允许两者共存。

建议：单选选择选项时清空 custom；保留多选并存行为。增加“其他→选项”“选项→其他”“多选+其他”三个方向的回归，检查最终提交载荷，而非只检查选中样式。

### P2：旧菜单异步操作会关闭新的菜单

位置：[SessionMenu.tsx](../../../../packages/qs/qs-sessions/src/client/SessionMenu.tsx) 第 63 行；[SessionList.tsx](../../../../packages/qs/qs-sessions/src/client/SessionList.tsx) 第 136 行。

触发：打开会话 A 的菜单并提交重命名；请求尚未返回时关闭菜单，再打开会话 B 的菜单并编辑。A 请求成功后，旧组件的异步函数仍调用 `close()`，继而执行父组件的 `setMenuFor(undefined)`，关闭 B 菜单。

影响：B 菜单及其中未提交的编辑被意外关闭。忙碌期间关闭按钮仍可用，Escape 也可关闭，因此不是不可达路径。本结论来自异步闭包及父组件状态更新链的静态核对，本轮未运行对应浏览器竞态复现。

建议：使用组件生命周期或请求代次约束完成回调；父组件关闭动作也应限定所属菜单实例。不要因为界面关闭就误报后端操作已取消。回归用可控 Promise 覆盖 A 请求完成时 B 菜单仍保留，并覆盖失败、卸载和 Escape。

### P2：上滚后主动发送消息不会恢复跟随

位置：[Transcript.tsx](../../../../packages/qs/qs-transcript/src/client/Transcript.tsx) 第 139—143 行；官方对照：[ChatView.tsx](../../../../packages/client/ui-chat/src/client/chat/ChatView.tsx) 第 524—534 行。

触发：用户上滚阅读历史，使 `followRef=false`，随后在固定输入框发送消息或追加说明。内容尺寸变化回调直接返回，没有主动提交信号恢复跟随，也没有“跳到最新”入口。

影响：自己的新消息和后续回复留在视野外，容易误以为没有发送成功。官方实现区分被动更新和主动 user、steering、submission 追加，并在主动追加时滚到底部。

建议：接入官方投影中可识别的本人提交信号，主动提交后恢复跟随；被动流式更新继续尊重用户上滚。现有 [scroll.client.spec.tsx](../../../../packages/qs/qs-transcript/tests/scroll.client.spec.tsx) 验证了上滚停止跟随，但没有覆盖随后主动提交。本轮为静态逻辑核对，没有将其表述为浏览器实测。

## 安全检查

本轮执行 `pnpm audit --prod --json`，返回 38 条告警：18 高、19 中、1 低、0 严重。审计命令退出码 1。它是依赖公告匹配结果，不是 38 个已验证可利用漏洞。

对照 HEAD 锁文件，审计列出的全部受影响安装版本均已存在；当前锁文件 diff 只有 importers 区域新增依赖声明，没有新增包解析版本。因此本轮没有证据把这些版本归因于新开发。新增入口是否扩大某个依赖的可达性，仍需按实际发布组合分析。

受影响包包括 brace-expansion、js-yaml、protobufjs、fast-uri、postcss、undici、ip-address、hono、nanoid、@hono/node-server、qs、vitest、@vitest/mocker、sharp。同一包可对应多个公告；js-yaml 有两个受影响安装版本。`--prod` 扫描工作区依赖仍包含测试支持工作区引入的工具，不能把所有告警当成生产 HTTP 服务暴露。

建议按真实 Host/API 路径、可接收外部输入的解析器、测试工具链分别核实可达性并升级；先确认公告对应的受影响版本和修复版本，再运行所属包与启动组合回归。不要直接对整个锁文件执行无差别强制升级。

本轮检查到审批和提问继续通过官方交互接口提交，没有发现 QS 新增自动批准或通过显示状态绕过宿主判定的明确证据。静态登录是用户明确批准的当前阶段范围，不能作为服务端认证能力使用；“隐藏官方入口按钮”也是显示配置，不能当权限边界。此结论不包含渗透测试、跨源攻击模拟或部署网络隔离验收。

## 性能静态风险

以下结论有代码依据，但未做合成长会话基准，不能据此宣称实际页面已经卡顿。

| 位置 | 已确认的计算行为 | 可能影响与验证方向 |
| --- | --- | --- |
| [rows.tsx](../../../../packages/qs/qs-transcript/src/client/rows.tsx) 第 146 行 | 未知节点的 details 即使折叠，也立即 JSON.stringify 完整负载并创建文本内容 | 大工具结果仍消耗序列化与 DOM 内存；用合成大负载测量打开历史和展开详情，决定按需构建及受控预览 |
| [Transcript.tsx](../../../../packages/qs/qs-transcript/src/client/Transcript.tsx) 第 45、91 行 | 行座席未 memo，父列表状态变化和追加行会重新执行座席 | 测量长历史追加节点的渲染成本；官方 ChatNodeList/ChatNodeSeat 已使用 memo。现有逐行订阅避免了每个文本 delta 重转全量历史，不应夸大 |
| [SessionList.tsx](../../../../packages/qs/qs-sessions/src/client/SessionList.tsx) 第 50 行起 | titles、running、pending 选择器产生新的对象/集合，分组和列表随之重建 | 测量大量会话及后台状态更新时导航响应，再决定稳定选择结果、拆分行订阅或 memo |

性能验收建议使用合成会话规模与工具结果大小的组合，分别记录首次进入、追加用户消息、持续输出、切换会话的耗时和内存变化，并与官方实现同机比较。本轮没有进行这些基准，也没有使用用户私有会话作为基准数据。

## 展示能力与维护性缺口

[adapter.ts](../../../../packages/qs/qs-transcript/src/client/adapter.ts) 的 assistantLines 只保留 text/reasoning；已知 assistant-step 内的 image 或未知块不会进入节点级 unknown 兜底。用户消息的 contentText 也只保留文字。第一优先若明确仅支持文本，这属于需要清楚说明的能力限制；读取官方已有含图片的历史时，则会静默缺失内容。建议至少给非文本块提供可辨认的占位或复用官方附件呈现，避免空白消息。

[rows.tsx](../../../../packages/qs/qs-transcript/src/client/rows.tsx) 第 62 行直接使用 MarkdownText，未传官方 AssistantMarkdown 使用的 pathImages 和 fileMentions。官方 Windows 本地图片路径修复不能自动覆盖 QS 的独立渲染路径；后续媒体验收必须在 QS 页面执行，而不能只引用官方页面测试。本轮将其列为展示能力缺口，没有执行图片浏览器复现。

源码注释仍有“待 M1 实测”、旧审查编号和未来占位导出等残留。它们应在对应行为修复时核实、清理，以免维护者把过期开发计划当成有效约定。此项不应优先于提交载荷和异步生命周期缺陷。

## 处理顺序与验收条件

1. 修复单选回答污染，增加真实答案载荷断言。
2. 修复菜单旧请求影响新实例，增加可控异步时序回归。
3. 修复主动发送后的滚动跟随，增加 DOM 测试及真实浏览器场景。
4. 补齐关键业务分支覆盖率，重新执行 QS 测试及覆盖率命令；明确仍未满足的逐文件门槛。
5. 单独处理可达的高风险依赖公告，再开展合成性能基准；按数据决定优化范围。
6. 明确非文本历史与本地媒体的支持范围，补展示或补可见的限制提示。
