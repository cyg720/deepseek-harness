# 物理重连旧分页占用修复

2026-09-24，dev-workbensh。本轮承接 T41/G08，修复真实网络载体恢复后的旧分页占用；官方改动登记及逐文件差异见[第107批](../../../官方源码改动记录清单/107-物理重连分页窗口隔离登记.md)。未提交 Git，未接真实登录。

## 根因与复现

真实浏览器先暂缓一个已经从 Host 读取的历史分页响应，断网并关闭实际 remote.mux WebSocket，再恢复网络。连接已显示 connected，但仍只有旧请求，分页按钮保持 Loading earlier records，无法发起新分页。首次失败日志 repair-v1-history-epoch.log；诊断日志 repair-v1-history-epoch-diagnostic.log 中 received=[0]、finished=[]、无 alert。故障不等同正常自动发起第二页。

官方 RemoteJournalStream 的 prepend 使用整体生命周期 signal，窗口随物理流重连或连续性修复替换时，该信号并未结束；旧回包可继续提交。Session 的 openGeneration 只覆盖显式 resync/销毁等，自动流重连并未取消 loadingOlder。因此只验证 Session.resync 不足以证明物理重连安全。

## 实现

Journal 在每次 replace 递增窗口版本，prepend 捕获发起窗口，响应返回后窗口已变化则丢弃，不修改 entries 或 hasMore。Session 在收到 replace 时使历史请求代次失效并释放旧 busy/跳转目标，新请求的状态不受旧 finally 影响。loadThrough 采用相同历史代次中止旧循环。没有添加另一套 QS 分页服务，没有改持久化格式或接口参数。

connectionEpoch 仍为 Session 实例内本地标识，重连、修复、显式重新打开和销毁都使旧身份失效；它不表示物理重连次数。QS 辅助类型注释、两官方包双语 README 及既有 QS Agent Note 已同步。
