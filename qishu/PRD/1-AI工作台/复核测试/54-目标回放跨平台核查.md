## Windows 失败原因及影响

`packages/preset/agent-presets/presets/standard/agent.cordis.yml` 在 Windows 禁用 tool-bash，使用 tool-pwsh；`packages/bundle/base/cordis.patch.yml` 同时禁用 bash-sandbox 并启用 pwsh-sandbox。`goal-multi-turn-actions` 的录制及 override 明确调用 Bash，并使用 find、sed、printf、python3 等命令。override 修改模型回放块，不是工具执行结果模拟器。

因此，在 Windows 直接执行该 POSIX 录制会出现 unknown tool "bash"。只打开 tool-bash 开关不能补齐执行器；不能据此改动正常 Windows 产品装配。`vitest.web.config.ts` 明确说明 Linux PR CI 执行浏览器录制回放，仓库此前第 04 份记录也已登记同一平台差异。本次在当前源码的 Linux 隔离环境重跑原始用例通过，排除了本次共享目标接口改动在这三个场景中的回归；不据此宣称 Windows 原失败已经修复。

ACP 的已跟踪符号链接在 Windows 工作树中是路径文本，Linux 源码副本按 Git 索引的 120000 模式恢复链接后，Cordis config 及全部 hygiene 检查通过。媒体引用的文件符号链接用例在 Linux 通过。两项 Windows 权限/检出条件仍未改变，不能将 Windows 结果改记为通过。

## 新确认的目标错误码限制

`packages/goal/goal/src/runtime.ts` 的 GoalError 继承 HarnessError；过期 ref 在 `packages/goal/goal/src/index.ts` 抛出 GOAL_STALE_REVISION。`packages/api/gateway/src/index.ts` 的 rpcFailure 仅对 remoteErrorOf 识别的错误保留 code/details，其余变为 gateway/internal。源码运行探针确认 GoalError 的 domainCode 为 GOAL_STALE_REVISION，但 recognizedRemoteFailure 为 false。

这是源码调用链与构造器探针证据，尚未补真实 Goal CAS 经 Gateway 的端到端错误载荷断言。后续 QS 目标界面不能直接比较远程 error.code === GOAL_STALE_REVISION，也不能解析英文错误信息冒充稳定协议。须验证并确定类型化领域错误传输方案，或用权威目标版本核对呈现冲突；失败时保留草稿，禁止自动升级 ref 重试覆盖新版本。该项仍待解决，不标记为已实现。
