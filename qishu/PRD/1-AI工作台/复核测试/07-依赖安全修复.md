# 依赖安全修复

## 摘要

2026-09-18 对上一轮 `pnpm audit --prod --json` 的 38 条公告进行运行路径分级。本批优先处理宿主 YAML 解析和附件图像解码；审计数量不等于已证实可利用漏洞数量。两个包的受影响版本均存在于原 HEAD，不属于 QS 新引入依赖。

## 处理范围

| 依赖 | 实际路径与影响 | 处理 |
|---|---|---|
| js-yaml 4.x | CLI、app-boot、agent-presets 读取 YAML；恶意合并键或有序映射可消耗 CPU。通常需要引入不可信配置，并非已证实匿名网络入口 | 将受影响 4.x 解析统一约束为 4.3.2 |
| sharp 0.35.3 | 默认 base 装配 attachment-local，图像入库先执行原生 metadata 解析，再检查支持格式。因此拒绝 HEIF 类型不能证明原生解析风险不可达 | 约束为 0.35.4，使用更新的预编译 libvips/libheif |

js-yaml 修复版本来自 [维护者发布页](https://github.com/nodeca/js-yaml/releases/tag/4.3.2) 与 [合并键预算公告](https://github.com/advisories/GHSA-2883-xcg3-v3hh)。sharp 修复版本来自 [维护者安全公告](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c)；其中 Linux 原生利用条件不能直接当作当前 Windows 已遭利用的证据。

在根 `pnpm-workspace.yaml` 使用仅匹配受影响版本的 overrides，使直接和间接依赖一致更新。没有跨主版本升级、改动 vendored 包源文件或执行 `audit --fix --force`。根文件是 pnpm 实际读取的统一解析入口，放入自有 qs 子目录不能改变解析行为。上游已彻底提升版本下限后可移除这两条约束并重新安装验证。

## 未纳入本批升级的路径

| 依赖族 | 核对结果与边界 |
|---|---|
| fast-uri / AJV | MCP Client 会执行 AJV 校验；当前 SDK 使用同步 compile，不提供远程 loadSchema。公告要求把规范化 URL 用作出站请求或主机策略判断，未发现该利用链；不能把未证实利用等同于包没有漏洞 |
| ip-address / Hono / qs | 审计路径经过 MCP SDK 的服务端框架依赖；本仓 MCP 消费端导入 client/stdio、client/streamableHttp，不因依赖树存在就代表工作台启用了这些服务端 middleware |
| brace-expansion | e2b SDK 的 glob 入口属于模板文件构建；本仓 e2b provider 使用沙箱生命周期，没有调用该模板构建接口 |
| undici | e2b 有 HTTP dispatcher 路径，但本批高危公告针对 cache interceptor 特定指令处理；未找到启用该缓存 interceptor 的调用。其他 cookie/blob/retry 公告仍需按功能单独确认 |
| PostCSS / nanoid / Vitest | 上轮 prod 审计仍包含 test-support 工作区的依赖，这些不能算作工作台后端生产请求漏洞；构建和测试处理不可信输入时仍需独立升级验证 |
| protobufjs | 来自可选 pi-ai/Google provider，未在本次默认工作台流程确认不可信 proto 文本解析入口 |

上述结论限定于本次检索到的默认装配及调用点，不是所有插件组合的安全担保。启用自定义 MCP 服务端、E2B 模板构建或可选模型 provider 时必须重新核对。fast-uri 的具体前提见 [维护者公告引用](https://github.com/advisories/GHSA-f65p-4m7j-42xc)。
