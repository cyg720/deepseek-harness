# 权限插件 Web 装配与官方界面恢复

日期：2026-09-23。完成独立 qs-ui-permission-presets 的 Web 装配，验证新会话默认权限保存与官方界面恢复；未提交 Git，第二优先整体仍未完成。

## 命令呈现所有权

官方 commandUi 仍是唯一命令服务。CommandDecoration 增加可选 priority，默认值 0；同名同优先级保持重复注册报错，显式不同优先级共存时选择当前可用的最高值。QS 权限呈现使用优先级 1，并绑定 qs.settings.general.item 槽的生命周期。退出奇术根界面释放 QS 装饰器后，官方装饰器恢复；官方 Host 命令目录、参数认领和执行路径不变。

最初试验只绑定两套设置槽，交叉测试发现覆盖根视图不撤销全部官方子槽声明，仍会重复注册。该临时官方权限文件改动已恢复，最终实现不修改 ui-permission-presets。新增共享命令服务测试证明官方先加载、QS 先加载、不可用回退、覆盖贡献卸载、基础贡献先卸载、重新挂载及同级重复拒绝。没有放宽普通注册的重名约束。

## 真实浏览器证据

通过 dsh 隔离测试 profile 启动真实 Host 和浏览器，使用测试独占的配置存储及种子会话。

- 选择完全访问但未勾选确认时提交按钮禁用；取消确认后 permission 设置写入次数为 0。
- 勾选并确认后实际 settings.mutate 请求包含 permission、defaultPreset 单字段操作及 expectedRevision，Host 回执确认 danger-full-access，页面显示已保存值。
- 刷新并重新进入设置后默认值仍为 danger-full-access，证明持久化恢复。
- 连续两轮奇术→官方→奇术切换，各自裸 `/permission` 菜单可打开和关闭；奇术菜单显示“只读”，官方显示“仅可查看”，验证恢复对应贡献而非沿用同一数据源。无 pageerror，设置写入总数保持 1。
- 原有转写跟随场景复跑通过，其中包括当前会话权限命令、完全访问风险弹窗、取消保留草稿及选中只读后消费草稿；未重新录制或弱化原快照。

首次新增浏览器用例将 Escape 发给只读 composer，而不是持有焦点的菜单输入，导致菜单冻结尚未解除、切换按钮禁用。将操作改为实际菜单输入后通过；未解除产品冻结规则。
