## 实际验证

新增用例位于 `apps/web/tests/qs/interaction-roundtrip.e2e.ts`，名称为 `applies numeric settings to their owners and restores inheritance through unset operations`。通过真实 QS 设置页面及 Host settings RPC，分别保存 Shell 的 timeoutMs=90000、maxOutputBytes=32768，以及 agent-loop 的 maxParallelToolCalls=3。逐次断言 namespace、当前 expectedRevision、完整字段路径、数值类型及 set 操作，随后读取真实 Shell.resolve 和 AgentLoop.config，确认保存结果进入能力所有者。

随后点击每个字段的恢复继承按钮并保存，断言发送 unset 而非零、空字符串或显式默认值；确认 Host 的 user 层已移除这些字段，所有者读值恢复到测试启动时的配置。Shell.resolve 仅生成执行参数，本用例没有执行命令，也没有调用真实模型。

追加真实拒绝与版本冲突：保存 timeoutMs=0 收到 Host 失败回执，页面保留 0 草稿且能力所有者仍读取 90000。放弃草稿后编辑 92000，再通过 Host 设置所有者写入 91000；浏览器仍携带编辑开始时版本，收到 settings/conflict，草稿保持 92000、有效配置保持 91000。等待镜像显示当前值，明确点击采用当前版本，再保存才成功变为 92000。此处没有 mock settings/mutate 响应，也没有以组件模拟冲突代替真实 CAS。
