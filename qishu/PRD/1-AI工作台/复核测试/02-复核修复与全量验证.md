## 不能混同的剩余问题

1. **Windows 符号链接权限**：第二轮全仓单元测试的 58 个失败中，57 个报创建符号链接 `EPERM`。NodeNext consumer 检查也在同一操作失败，已用只记录异常的临时 Node preload 定位到 `linkPackage`，日志 `qs-fix-nodenext-diagnostic2.log`。没有通过修改安全检查或改成复制文件规避符号链接语义测试。
2. **单元测试超时**：`scripts/client-build-environment.client.spec.ts` 的仓库版本/提交/dirty 元数据用例在全仓并发时超出 5000ms，独立复跑通过。已只为该真实多仓库 Git 用例设置 30 秒预算，所有行为断言保留，15 文件定向复跑通过；没有修改全局测试超时。
3. **ACP 链接检出问题**：`apps/cli/tests/profiles/acp/cordis.yml` 在 Git 中为 120000 符号链接，本机检出为只有相对目标路径的普通文本，加载器因根值不是数组报错。需要具备符号链接能力的正确检出；没有把链接替换为一份会漂移的配置副本。
4. **官方平台相关测试**：expected、Session/SDK 快照和部分 e2e 期待 bash、POSIX 文件权限或 POSIX 路径，本机为 Windows/pwsh；还存在 MCP 文本换行、资源路径及 PTC 调用 WSL bash 的差异。未刷新黄金文件、未放宽断言。并非全部失败都已证明只有平台原因。
5. **已修复的官方夹具问题**：ACL 未装 `SessionProjectionRegistry` 导致 executor 缺失，LSP 使用 URL.pathname 和不可执行 .bin shim；修复后 6 个真实进程用例通过。Preview 静态覆盖表的 Windows 路径及测试 Host 界面配置也已修复，真实 Chromium/Worker 用例通过（`qs-fix-preview-retest2.log`）。
6. **QS 测试覆盖缺口**：定向覆盖率明确不达标（行 58.73%，要求逐文件 100%），尤其是插件注入工厂、部分输入/菜单/登录/外壳分支及 Host 入口。行为回归通过不能代替逐文件 100% 门禁；没有增加全局排除或降低阈值。
7. **并发运行能力限制**：第三轮全仓覆盖率另有 4 个 worker 启动失败、11 个额外超时或进程错误；这些文件和元数据测试共 15 个文件以 `--maxWorkers=4` 定向复跑，373 通过、6 跳过。e2e 的 built-bin worker 启动失败后独立补跑，26 通过、1 跳过。没有把补跑拼装成一次全量绿灯；后续全量执行宜串行运行各大测试车道并根据本机进程容量设定 worker 数。
8. **尚未验收的 UI 维度**：原型逐像素比对、真实浏览器历史前插锚点/切会话滚动恢复、200% 缩放及完整键盘链路。已有组件和构建图用例不能替代这些人工/浏览器证据。
