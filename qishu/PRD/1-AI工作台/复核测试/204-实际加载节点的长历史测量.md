# 实际加载节点的长历史测量

日期：2026-09-24。现有 long-history 基准在首屏后只加载一页，日志事件总量不能代表界面已加载规模。本轮新增 QS_HISTORY_LOADED_NODES，通过正式分页按钮达到指定节点数量后测量；QS_HISTORY_SAMPLES 默认仍为30，允许至少6次测量。本次没有修改生产代码或设置未经校准的时间门槛。

执行：DSH_SNAPSHOT=replay、QS_HISTORY_SAMPLES=6、QS_HISTORY_LOADED_NODES=1000，运行 `node node_modules/vitest/vitest.mjs run --config qishu/config/vitest.long-history.config.ts -t '10000 durable events'`。结果1项通过、3项未选中，109.70秒，退出码0；原始日志 logs/repair-v1-history-1000-loaded.log。基准文件 lint 和 Host 类型检查通过。

环境：Windows 10.0.26200，Node24.18.0，Chromium149.0.7827.55，Core Ultra7 265KF。合成日志10002个持久事件、1579轮、21479110字节；每次独立 Host 和浏览器，视口1280×900。初始104个转写节点，分页后每个样本均1146个节点；每个样本执行20次 Chat→轨迹→Chat 往返。

舍弃首个预热样本后，5次样本中位数：打开历史1176.87ms，第一页170.65ms，追加加载至目标1208.85ms。5个样本共100次往返的合并中位数585.23ms；这些是同一场景内重复操作，不能解释为100次独立启动样本或据此泛化生产p95。计时包含 Playwright 操作、状态等待和双动画帧，不是纯渲染 CPU 时间。

每个样本测量后 DOM Nodes 为18582，退出后恢复547，与进入前相同；退出监听器179、进入前163，堆约41.8MB、进入前约28.6MB。DOM 回落不能证明所有缓存或监听器零残留，也不能直接把仍驻留的登录应用和服务算为泄漏。

结论：大规模已加载集合的往返确有可感知成本，需继续区分轨迹与 Chat 挂载、布局和事件投影的开销。该结果填补1000节点附近的实际加载证据，不覆盖10000个已加载节点、深宽树、连续流式或所有 W 面板，尚不宣布完整性能验收通过。

## 切换分段定位

以相同环境、日志、1146个已加载节点和6次独立样本重跑，分别记录进入轨迹、返回 Chat 的墙钟时间及 CDP ScriptDuration/LayoutDuration 增量。每段都等待双动画帧，比前一版多一次绘制等待，不能直接用往返总耗时对比优化收益。日志 logs/repair-v1-history-split.log，运行退出0；基准文件 lint 通过。

去除首个预热后，100次重复操作合并中位数：进入轨迹205.35ms，其中脚本41.12ms、布局22.72ms；返回 Chat 384.92ms，其中脚本167.34ms、布局42.80ms。不同指标各自取中位数，不能相加还原总时间；CDP脚本与布局也不是完整浏览器成本归因。

据此优先调查 Chat 重新挂载的脚本工作，而非先优化轨迹正文；轨迹 History 已在 details 展开后才挂载正文。当前只有耗时定位证据，尚未通过 CPU 调用栈锁定具体热点，也未据此改生产代码或宣称性能改善。

## CPU 调用栈定位

基准增加可选 QS_HISTORY_PROFILE_DIRECTORY，仅首个预热样本第一次返回 Chat 开启 CDP Profiler，其余样本不采样。相同1000节点目标及6个样本运行通过，118.20秒，日志 logs/repair-v1-history-profile.log；调用栈文件 logs/qs-history-profile/chat-10000-1146.cpuprofile。采样样本明确标记 profiled，不纳入普通耗时对比。

首个调用栈中，Transcript.tsx 的 useFollowTail 内 stick 函数有74次自身命中，按 timeDeltas 汇总约112630微秒；采样窗口总计1003008微秒。其命中数接近 program 的75次，高于垃圾回收20次和 appendChild 的12次。单次抽样存在误差，不把命中数当作精确函数耗时比例。

源码核对：stick 在挂载与 ResizeObserver 回调中读取 scrollHeight、写 scrollTop 并保存位置。同步几何读取触发布局是待验证的成本来源，因此不能把 ScriptDuration 全部归为 React 计算。下一步应比较滚动恢复时序与布局记录；不能直接移除跟随、历史锚点或视图返回位置恢复来换取更低数字。本轮尚未调整生产滚动机制，基准 lint 通过。
