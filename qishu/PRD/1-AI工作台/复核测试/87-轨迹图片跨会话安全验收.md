# 轨迹图片跨会话安全验收

日期：2026-09-23。本轮新增真实浏览器安全回归，不改动业务源码或官方原文件，未提交。

## 场景和结果

真实附件仓库保存一张图片，第一份会话历史引用该附件，第二份会话只有文本且未引用它。浏览器通过正常入口读取第一会话图片，记录实际附件 RPC 的地址与认证头；测试使用同一已认证连接，仅替换为第二会话身份，发起该图片读取。

Host 返回 HTTP 200 的 RPC 失败信封，错误码为 session/attachment-invalid，原因明确为 ATTACHMENT_NOT_REFERENCED。断言不是仅检查“请求失败”，也不是把未认证、接口不存在或参数格式错误当成授权成功。测试不记录认证头到日志。

随后通过侧栏切换第二会话，打开其请求轨迹，验证第一会话图片及原图弹层不存在，并展开核对第二会话自身文本。会话阅读偏好独立保存，新会话默认聊天；测试显式切入该会话轨迹，不假定跨会话沿用阅读偏好。

## 验证证据

- 定向真实浏览器媒体场景通过，另一个压缩历史场景未选中。该场景同时保留此前聊天媒体、未认证文件读取 401、轨迹图片加载、原图查看、缺失图片提示和折叠清理断言。
- Host/Client 类型检查、该测试文件 lint 通过。
- 证据：logs/repair-v1-trajectory-media-isolation-browser.log、repair-v1-trajectory-media-isolation-types.log、repair-v1-trajectory-media-isolation-lint.log。
- 本轮仅扩展端到端测试，没有重新跑 QS 单元全量；第 86 轮的 682 个用例和覆盖率结果保留其原始范围，不作为本轮新执行结果。

首次尝试使用数组编码 RPC 参数，返回 gateway/internal；查官方 Gateway 的 prepareInvocation 后改为具名 request 参数，最终明确命中附件引用授权拒绝。首次切换会话测试错误假定目标已选轨迹，修正为真实用户点击轨迹页签。没有修改生产错误处理或绕过鉴权以使测试通过。

## 保留范围

此场景验证单个有效登录上下文内的会话附件引用授权，以及切换后的可见隔离；不声称覆盖多用户身份隔离、全部并发迟到网络结果或独立附件插件热卸载。文件附件访问、轨迹定位和长历史性能等仍待完成，第二优先整体尚未验收。
