## 第二批补丁与不可用修复版本

定向锁定 undici 7.29.0、ip-address 10.3.1、nanoid 3.3.18、PostCSS 8.5.23、browserslist 4.28.7，均不跨已有主版本。frozen-lockfile 安装、81 文件 618 条测试及完整 build 通过；浏览器回归进行中。

- undici 高风险公告要求启用共享 cache interceptor；对 packages 与 apps 源码搜索未找到该调用，不能宣称普通 fetch 已构成跨用户缓存泄露。依赖仍由 jsdom/E2B/打包链带入，按修复版升级；[公告](https://github.com/advisories/GHSA-4cwx-7wf7-3272)。
- ip-address 经 MCP SDK 的 express-rate-limit 间接带入，前导零地址解析与原生解析分歧的修复见[公告](https://github.com/advisories/GHSA-mwp4-54f8-5fhr)；当前 MCP 客户端不是该 HTTP server，依赖存在不等于已证明此路径可利用。
- PostCSS/nanoid/browserslist 属 CSS 与 Babel 构建依赖。PostCSS 选择 8.5.23 而非只修高风险的 8.5.18，以覆盖 sourceMappingURL 的后续修复，见[公告](https://github.com/advisories/GHSA-fxqj-rqcc-2cmp)。nanoid 3.3.18 修复零大小自定义生成器死循环，见[公告](https://github.com/advisories/GHSA-2v37-7h3g-55p8)；browserslist 4.28.7 修复无界查询缓存，见[公告](https://github.com/advisories/GHSA-c83g-rgw3-j3cx)。未发现 QS 接收外部用户参数直接调用这些构建 API。
- extract-zip 公告写明 2.0.2，但 npm 官方源返回 ERR_PNPM_NO_MATCHING_VERSION、latest=2.0.1（日志 repair-v1-security2-resolve.log），因此移除不可安装 override，不能声称修复。当前唯一源码调用 apps/desktop/scripts/prepare-runtime.ts 先从 nodejs.org 下载固定版本 Node 归档并核验 SHA256，再解压，不接受任意用户归档；这降低攻击面，但不能替代依赖修复，也不覆盖本机缓存与供应链被修改的威胁。见[符号链接公告](https://github.com/advisories/GHSA-7pqw-9j4j-h8q3)。

第二批后 audit 为 7 high、20 moderate、3 low、0 critical，见 logs/repair-v1-security2-after.json。剩余 high：pnpm 四项、Vite 一项、extract-zip 两项。第二批锁文件另包含 browserslist 所需 baseline-browser-mapping 从 2.10.43 升至 2.11.25（新依赖下限 ^2.10.44）及 peer 快照引用更新。日志为 repair-v1-security2-tests.log、repair-v1-security2-build.log；构建依然提示部分大 chunk，不代表性能门禁通过。


第二批浏览器首轮 13/14 通过，失败发生在全屏几何回归跨断点后的点击：CSS 尺寸先更新，外壳 matchMedia 回调随后提交，几何断言不能证明回调已收敛。测试改为在跨越布局断点时等待外壳 compact 偏好落盘，再打开窄屏面板并断言 inert 已解除；1700px 未跨布局断点，不等待不存在的存储写入。第一次修正误等未初始化的存储也失败，已纠正。最终专项通过，定向 lint 通过，全部 QS 浏览器复跑进行中；日志 repair-v1-security2-browser.log、repair-v1-security2-panel-retry.log、repair-v1-security2-panel-final.log 保留失败与修复证据。没有 force 点击或更新快照消除错误。

## 文档站 Vite 修补验证

VitePress 1.6.4 自身依赖仍为 Vite ^5.4.14，其 plugin-vue peer 支持 ^5 或 ^6。定向 override 将此旧链升级为 6.4.3，不改变主应用 Vite 8；明确属于跨主版本兼容调整，而非单纯补丁。上游依据：[Windows 路径拒绝绕过公告](https://github.com/advisories/GHSA-fx2h-pf6j-xcff)。现有文档站 dev 命令绑定 127.0.0.1，不能把该路径误称生产 Web 已远程暴露漏洞。

锁文件解析与冻结安装通过。`pnpm run website:build` 成功（31.19 秒），2668 个内部 fragment 引用校验通过，201 个原始 Markdown 文件及 llms.txt 输出；仍有既有 caddyfile 高亮回退和大 chunk 提示。日志 repair-v1-vite-website.log。安装后的 Vite 6.4.3 临时开发服务器（端口 0、仅 127.0.0.1、不读取真实 env）首页 200、`/.env?raw` 和 `/.env::$DATA?raw` 均 403 且未返回虚拟测试值；finally 关闭服务器并验证路径在临时目录下后清理，日志 repair-v1-vite-deny-smoke.log。此验证不声称覆盖所有 Windows 8.3 别名变体或所有开发服务器配置。

最新 audit：2 high、17 moderate、3 low、0 critical，见 repair-v1-vite-audit.json；high 均为 extract-zip，因 npm 未提供公告指示的 2.0.2 而仍未修复。安全验收没有清零，后续中低风险仍需逐项分析。安装和文档构建成功不替代整个第二优先业务实现与性能验收。
