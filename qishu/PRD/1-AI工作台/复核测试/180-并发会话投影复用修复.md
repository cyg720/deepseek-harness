# 并发会话投影复用修复

日期：2026-09-24。针对 [179 同负载对照](179-第一优先与第二优先同负载对照.md) 中最大档打开中位数增加 26.17% 的问题，修正持久化服务身份与并发准备复用；完整验收仍在进行。

## 原因与修改

真实 Host 调用计数确认：同一 50,034 事件归档，第一优先恢复持久投影一次，未修复第二优先恢复三次，分别使用三个准备实例。单纯增加 I/O 后缓存复查仍恢复三次；Cordis 每次服务访问产生新的追踪代理，比较代理引用会把同一个服务当作不同持久化实例，缓存持续失效。

`SessionObservationReader` 使用 Cordis 已有 `symbols.original` 识别缓存所有者，保持所有真实 `stat/open/read` 操作通过追踪代理执行；完成各自 I/O、取消检查和实时挂载检查后，再查询同持久化实例、同修订的已完成准备缓存。未新增全局缓存、共享取消控制器或在途 I/O 合并，没有改变持久格式、输入验证、权限和历史内容。

保留独立 I/O 意味着并发冷磁盘读取仍可能多次发生，不能声称合并为一次磁盘读取。官方架构笔记中此前宣称已共享在途读取的表述已更正，并链接二开决策笔记；原笔记其他观察与投影职责保持有效，未归档。
