# 大工具载荷展开测量

日期：2026-09-24。针对 v1/R11，补充通用工具卡首次展开与重新展开的真实浏览器诊断。此记录不代表全部性能要求完成。

## 执行前测量卡

| 维度 | 固定选择 |
| --- | --- |
| 用户动作 | 进入合成历史，展开工具正文，再展开原始参数；输入草稿、收起、重新展开，最后退出。 |
| 工作负载 | 单个合法完成轮次、两步；未知工具 synthetic_payload；参数和结果各含 32 KiB、1 MiB、4 MiB 固定 ASCII 正文。真实字段及归档总字节另记录。没有用户资料或网络模型调用。 |
| 数据入口 | Session.append + AssistantStreamAccumulator 构造当前世代记录，官方 seeder 持久化，真实 Host/投影/传输和构建后的 QS 组件。不是直接注入 React 节点。 |
| 样本 | 每档6个独立 Host/浏览器世界，首个样本单列预热，其余5个用于探索中位数；不计算 p95 或声称 CI SLO。 |
| 计时 | Playwright 真实点击或填写开始到可见节点出现并经过两次 rAF；包含动作等待与本地传输，不含建档和首次打开历史，不等于显示器硬件显示。 |
| 主线程 | 各动作独立 PerformanceObserver 收集 longtask，结束时取未交付记录；包含最后一次阻塞，保留全部原始持续时间。 |
| 内存 | 工具关闭、展开、退出后分别 CDP 强制 GC，记录 JSHeapUsedSize、Nodes、JSEventListeners、TaskDuration。退出为即时观察，不证明全部延迟清理完成。 |
| 正确性 | 全部结果正文逐字比较，参数 JSON 全量等值，草稿可输入，收起后 pre 卸载；错误必须失败，不以截断换速度。 |
| 判定 | 手动诊断先记录分布与成本，不引入未经机器/CI校准的时间门槛；按测量决定是否修改生产代码。 |
| 排除 | 深层/宽工具树、非文本序列化、连续流式、大 DOM 历史、W 组面板、线上模型延迟。 |

测量入口：benchmarks/qs/tool-payload.perf.ts；配置：qishu/config/vitest.tool-payload.config.ts。执行 pnpm exec vitest run --config qishu/config/vitest.tool-payload.config.ts。初次类型检查发现遗漏必填 stream 及局部 process 名称遮蔽，已修正为真实累计器记录和 processRow；正式 typecheck 与定向 oxlint 均通过。首次测量前尚未修改生产代码。

## 测量修订与归因

初版通过全文定位器等待参数末尾标记，将浏览器自动化的巨型文本搜索混入动作耗时。保留 logs/repair-v1-tool-payload-browser.log、logs/repair-v1-tool-payload-break-all.log 与 logs/repair-v1-tool-payload-phases.log 作为诊断过程，不将其动作总时长与修订后的数据混合。

最终计时端点改为 CSS 定位第二个 pre 挂载，全文等值检查移到计时之外。另通过 CDP 分离 ScriptDuration、LayoutDuration、RecalcStyleDuration 和 TaskDuration；这些分类不保证互斥或加总为动作墙钟时间。PerformanceObserver 的 longtask 独立记录。输入耗时是详情展开完成后的输入响应，不代表能在主线程阻塞期间响应输入。

修订后的生产基线为 logs/repair-v1-tool-payload-final.log，3 个场景、18 个样本完成，70.14 秒。4 MiB 档参数展开中位数 841.27 ms，布局中位数 691.20 ms，脚本中位数 12.49 ms，说明主要成本不是 JSON.parse 本身。

## 受控改动

只对通用卡的原始参数 pre 添加 argumentsPre 样式：overflow-wrap: normal、word-break: break-all。允许在字符之间软换行，但不改变原文、JSON 格式化结果、复制内容、滚动范围、节点数量或折叠生命周期。文本结果、其他工具卡和非文本详情的样式保持原状。

受控 CSS 注入实验用于筛选断行假设，不能代替产品验收。最终通过实际 qs-ui-tool bundle 重建后运行同一测量入口，不注入实验样式；不增加缓存、虚拟化、截断或额外服务。

Host/Client typecheck 及定向 lint 在测量初版修正后通过；Windows 与 Linux 的 qs-ui-tool bundle 通过。生产样式修改后工具与转写回归为18文件、180项通过（logs/repair-v1-tool-payload-regression.log）。最新完整 QS Web 52项通过属于报告188，发生在本次样式修改之前，不冒称覆盖这次修改。

## 剩余限制

这是一项经过测量的局部改善，不能把仍存在的长任务称为已满足交互预算。大型正文展开成本没有由本次改动消除。宽/深工具树、非文本原始JSON、连续流式、1k/10k已加载DOM、各W面板与稳定内存释放仍需独立证据。小样本只用于探索，不能宣称p95达标。
