# 工作台折叠详情的合成性能测量

日期：2026-09-18。基础提交：`8cb7269009716c8d252704a306a569eb7bfb98d9`，测量对象为该提交上的当前未提交工作台代码；并非该提交的原始实现。平台：Windows x64，Node v24.18.0，React 18.3.1。没有读取真实用户会话、提示词、文件或凭证。

## 结论与优化范围

未知记录的详情关闭时，原实现仍执行 JSON 序列化并创建完整文本。采用生产 `ROW_COMPONENTS.unknown` 的合成组件测量后，仅将这部分工作延迟到展开时执行；收起时删除展示文本，再次展开读取当前数据。原始历史数据和展开后的完整内容保留，没有截断或缓存序列化结果。

关闭 100 条、每条 128 KiB 的合成记录时，序列化次数从 100 次降为 0 次，组件 SSR 中位耗时从 23.4803 ms 降为 0.3683 ms。这个结果只证明组件关闭详情的 CPU 工作被移除，不是浏览器端到端响应、首屏、滚动或输入延迟结论，也不是内存基准。没有据此引入虚拟列表、全局缓存或重写历史投影。

## 测量卡

| 项目 | 方法 |
|---|---|
| 用户路径中的位置 | 初次呈现尚未展开的未知工具/扩展记录；测组件生成关闭状态 HTML 的结束点 |
| 入口 | 生产 `ROW_COMPONENTS.unknown`；以真实 React `renderToStaticMarkup` 调用，经 esbuild 编译为 JavaScript 后在 plain Node 执行 |
| 工作负载 | 20 条 × 4,096 字节输出，模拟普通工具页；100 条 × 131,072 字节输出，模拟大结果尾部负载；固定合成 ASCII 文本，不使用私有数据 |
| 独立成本 | 同时报告记录数、单条输出字节、实际 JSON 序列化次数、最终 SSR HTML 字节；数据对象另有索引字段 |
| 时钟 | 每组预热一次，随后测 5 次同步渲染；包括 React 渲染、JSON 格式化和 HTML 生成，不包括构建、模块加载、合成输入创建、模型或网络 |
| 运行隔离 | before/after 分别使用新 Node 进程，顺序运行；其他智能体暂停 CPU 重活，但依赖安装后台仍在等待 I/O，存在主机噪声 |
| 内存 | 未测 heap/RSS/峰值；HTML 字节只是输出规模，不能当成内存占用。原始节点仍完整可达 |
| 阈值 | 手工诊断，没有加入时间门槛。小负载亚毫秒值方差较高，不用于 CI 预算或宣传端到端倍数 |
| 行为约束 | 关闭不序列化；展开显示完整 JSON；收起删除 pre；更新数据后重新展开显示当前内容 |

此诊断构建的是实际生产组件的测量入口，不是 Web 应用的已发布 bundle，也没有测 `dsh` HTTP、布局、绘制或事件响应。CSS 在 Node 测量中使用 empty loader；前后方法完全相同。首次展开的耗时没有测量，懒执行是延后工作而不是让大结果序列化变免费。

## 原始样本

单位为毫秒。下列值保留到小数点后 4 位；最终结论取 5 次中位数。

| 负载 | 原实现 5 次 | 修复后 5 次 | 原/后中位数 |
|---|---|---|---|
| 20 × 4 KiB | 0.3165, 0.3076, 0.3299, 0.4694, 0.4093 | 0.1074, 0.1094, 0.1282, 0.1712, 0.1670 | 0.3299 / 0.1282 |
| 100 × 128 KiB | 23.4803, 23.3554, 25.0474, 25.9462, 21.5654 | 0.3683, 0.5903, 0.5014, 0.2799, 0.2751 | 23.4803 / 0.3683 |

20 条负载每个样本序列化次数原为 20、后为 0，SSR HTML 原为 87,190 字节、后为 3,200 字节。100 条负载每个样本序列化次数原为 100、后为 0，SSR HTML 原为 13,133,590 字节、后为 16,000 字节。两个负载的中位数组件耗时比分别约为 2.57 和 63.75；不能外推为整个工作台的加速比。

## 回归与负向控制

`packages/qs/qs-transcript/tests/rows.client.spec.tsx` 使用 170,000 字符的固定合成载荷，实际渲染生产组件，通过 `toJSON` 计数观测序列化调用，不替换生产序列化逻辑。原实现运行该回归时，关闭状态的零调用断言失败，实际调用 1 次，证明测试能够捕获目标退化。修改后该文件 6/6 通过，同时断言展开内容与完整 `JSON.stringify(payload, null, 2)` 一致、收起不存在 pre、重新展开显示更新后的内容。

执行命令：`node node_modules/vitest/vitest.mjs run packages/qs/qs-transcript/tests/rows.client.spec.tsx`。此处是 DOM 行为验证，不是浏览器响应基准。浏览器验收及整个 QS 汇总由本轮修复记录统一汇报。

## 重现诊断

源码：`packages/qs/qs-transcript/tests/fallback.perf.client.tsx`。本轮使用已安装的 esbuild 0.28.1，没有为诊断新增依赖。先对修改前源码构建 `qs-fallback-before.cjs`，再对修复后源码构建 `qs-fallback-after.cjs`；两份产物存于系统临时目录。下面的构建命令生成当前代码的 after 版本，before 需要使用报告描述的关闭状态仍无条件渲染 pre 的原函数，而不能以 HEAD 代替整个未提交工作树。

```powershell
node --input-type=module -e 'import {build} from "./node_modules/.pnpm/esbuild@0.28.1/node_modules/esbuild/lib/main.js"; import {join} from "node:path"; import {tmpdir} from "node:os"; await build({entryPoints:["packages/qs/qs-transcript/tests/fallback.perf.client.tsx"],outfile:join(tmpdir(),"qs-fallback-after.cjs"),bundle:true,platform:"node",format:"cjs",tsconfig:"tsconfig.base.client.json",loader:{".css":"empty"},alias:{"react-dom/server":process.cwd()+"/node_modules/.pnpm/react-dom@18.3.1_react@18.3.1/node_modules/react-dom/server.node.js"},define:{"process.env.NODE_ENV":"\"production\""}})'
node "$env:TEMP/qs-fallback-before.cjs"
node "$env:TEMP/qs-fallback-after.cjs"
```

依赖版本目录是本轮实测值，升级后需按实际安装版本调整诊断命令。此文件不是新的持续集成性能门槛；如需引入浏览器预算，仍须通过正式 Web 测试配置在实际 CI 主机重复校准。

## 未扩大的范围

当前证据只支持移除折叠详情的无效格式化。超长助手输出、首次展开大结果、持续流式 Markdown、历史分页及多会话切换仍需要独立的浏览器测量，不能由本诊断宣称已优化或已通过性能验收。高风险依赖的处理有独立报告，本测量不承担依赖安全结论。
