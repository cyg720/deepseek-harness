# 双客户端提问竞争验证

日期：2026-09-23。延续 T42 跨视图交互验收，本轮只增加真实浏览器回归及快照，没有改动生产实现。上一轮焦点恢复已落地且测试通过，属于实际进展。

## 官方实现依据

api/gateway 的 startRemoteEvent 将待回答请求投递给所有已注册 Remote Event 客户端；新客户端加入时重放仍未结束的请求。receiveRemoteEventResult 接收有效结果后结束该请求；已完成事件或已被替换的 delivery 再返回结果时按幂等空操作处理。不能将它误当成只允许单一浏览器呈现的瀑布流。

## 真实场景

第一浏览器在 QS 提问卡填写 Blue 和原自定义文字，切换到请求轨迹，再经过官方界面往返 QS 轨迹，保持原答案草稿。第二浏览器使用独立上下文连接同一个真实 Host，通过界面选择同一会话，提交 Green 和 Answered by second client。

场景验证第一浏览器旧提问卡撤销、第二浏览器表单也消失；模型回放继续结束，切回聊天可以看到 DONE。Host 恰好产生一个 tool/result，解析后的答案只有 Green 和第二客户端的补充文字，不包含第一客户端未提交的 Blue。没有调用 Host 内部模拟回答或注入前端假的 pending 状态。外部模型使用既有 keyless 录制回放，真实 Gateway、Session 和交互服务执行。
