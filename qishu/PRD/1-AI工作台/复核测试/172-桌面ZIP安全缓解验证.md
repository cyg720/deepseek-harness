# 桌面 ZIP 安全缓解验证

日期：2026-09-23。状态：调用点防护、真实 ZIP 回归和实际运行时准备均通过；不能据此宣布依赖安全扫描通过。

## 可达性与措施

`apps/desktop/scripts/prepare-runtime.ts` 是仓库直接使用 extract-zip 的构建调用点。Windows 分支从固定 Node 版本下载 ZIP 与 SHASUMS，校验摘要后创建干净解压目录。新增 `scripts/qs/extract-runtime-zip.ts` 在库的 `onEntry` 回调拒绝 Unix 文件类型为符号链接的条目，早于创建链接或写入同名普通文件。macOS tar 路径保持不变。

[GHSA-jmr9-qjv8-65gv](https://github.com/advisories/GHSA-jmr9-qjv8-65gv) 与 [GHSA-7pqw-9j4j-h8q3](https://github.com/advisories/GHSA-7pqw-9j4j-h8q3) 均与 ZIP 符号链接有关。核查时 npm 最新 extract-zip 为 2.0.1，GitHub 公告未列修补版本。防护仅覆盖本调用点，不消除依赖公告；旧扫描所称 >=2.0.2 不代表该版本已经发布。

调用方必须提供刚创建的独占空目录，不能复用不可信目录。摘要校验只能证明归档与清单一致；若本地缓存的归档和清单均被改写，它不构成来源真实性保证。该措施也不是任意 ZIP 的通用安全证明。

## 证据

缓存 `node-v24.17.0-win-x64.zip` 共 2404 条目，无符号链接；SHA-256 为 `f2aa33b35b75aca5f3f7b85675a6f6423201053e9381911e64961f3bda2528ab`，与缓存 SHASUMS256 清单一致。此项为归档元数据及摘要证据；实际解压证据见下表。

新增 `apps/desktop/tests/qs/runtime-zip.spec.ts` 使用三个真实合成 ZIP：普通文件、越界链接、链接后接同名普通文件。已验证拒绝原因、目标文件不存在及外部哨兵保持不变；不依赖 Windows 创建链接权限。
