# 通知断线恢复与跨地址隔离验收

日期：2026-09-23。范围：T39 的真实浏览器断线恢复、两个 Host 地址之间导航及页面异常检查。第二优先整体尚未验收完成。

## 已验证行为

测试使用正式 QS 装配、真实 Host 作业服务与控制流，控制合成作业生产者的完成时机，不调用真实模型，也不读取用户会话。

- 浏览器离线且既有 WebSocket 载体断开后，作业区出现重连提示。Host 在离线期间完成作业，恢复后列表显示完成且不重放通知；随后在线新作业完成产生一次通知。
- 两个独立 Host 使用相同会话标识；浏览器从 A 导航到 B 后，A 的迟到失败不污染 B，B 的在线完成产生一次通知。返回 A 时能看见失败记录，但历史失败不重放通知。
- 两例结束前检查页面未处理异常，均为空。生产者、作业等待者、浏览器与 scaffold 在 finally 中清理。

## 证据限制

浏览器 setOffline 不保证已有 WebSocket 关闭；本例同时关闭真实载体后才等待生产控制流重连。早期只切离线的失败日志保留，不据此声称产品断线机制有缺陷。

跨 Host 用例通过页面导航创建新客户端世界，证明跨地址隔离，不证明同一页面内热替换连接服务的行为。该热替换场景、原型全状态、性能基准、安全余项及 D/W 最终逐项核验仍需继续。本批没有改动官方原文件，没有提交或推送 Git。
