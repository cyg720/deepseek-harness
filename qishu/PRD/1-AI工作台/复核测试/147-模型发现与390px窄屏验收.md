# 模型发现与 390px 窄屏验收

日期：2026-09-23。范围：模型设置中自定义供应商的真实端点发现、候选选择、保存刷新与窄屏使用。

## 验收方法

使用真实 Web scaffold、Chromium、Host RPC 及官方 pi-ai 模型发现适配器。只有外部模型列表端点由本机 HTTP 服务替代，端口由 listen(0) 分配，记录请求路径与认证头；测试结束关闭浏览器、scaffold、连接和服务器，不触碰用户真实凭据。模型列表首次返回 503，第二次返回两个模型及上下文/输出容量，其中一项名称为长连续字符串。

## 已验证

- 首次拒绝显示通用失败提示，不显示远端诊断原文；点击重试发出第二个真实 GET /v1/models。
- 未保存表单中的地址、协议和密钥进入实际适配器请求，两次请求均携带预期合成 Bearer 凭据。
- 筛选不存在的候选显示空态，清空筛选恢复候选；默认选中候选经明确采用后进入模型草稿，容量保持官方解析结果。
- 保存后刷新，两个模型、长名称及容量仍存在；重新发现时从 Host 凭据存储取密钥，已有模型复选框及采用按钮禁用，不能重复添加。
- 390×844 视口下，对话框左右边界处于视口内，scrollWidth 不超过 clientWidth 加 1px，长候选折行。截图人工查看确认内容在对话框内纵向滚动。

## 测试修正说明

最初点击设置失败，原因是测试在登录提交后立即判断导航按钮是否存在，漏等导航挂载，同时没有走窄屏默认收起后的展开路径。核对布局规则后，改为等待顶栏导航开关出现，再按真实状态展开导航。不是布局遮挡缺陷，没有修改业务 CSS，也没有用 force 点击绕过可用性检查。测试文案使用词典的实际字符串。
