# 审批跨平台快照与执行结果复核

日期：2026-09-24。本批修改 QS 自有浏览器测试及快照，没有改动官方原文件，也没有改变产品权限策略。总体审查状态见[审查结果 v2](../../../dev-components/第二优先开发计划评审/审查结果-v2.md)。

## 缺陷及调整

Linux 完整 QS Web 回归初跑 50 项，48 通过，2 项审批卡失败。预期将工具固定为 pwsh，而 Linux 真实调用为 bash。先对 bash/pwsh 工具身份按平台做严格断言，再仅将已断言的工具行换成快照占位符，共享其余完整卡片预期。最初的两套平台快照在完整运行中被 Vitest 判为另一平台的废弃快照，故不保留该实现；参数、审批按钮和提示断言仍完整。

原测试在待答卡检查前创建回合结束等待。快照失败后无人等待的计时器引出两个异步超时。将订阅放到待答卡检查完成后、提交回答之前；仍在动作前监听，避免错过结束事件。此调整覆盖本次发现的前置断言失败，不宣称所有其他提前退出路径的等待资源均已独立验收。

允许审批后的成功必须同时有真实工具结果及磁盘写入。新增断言按录制调用顺序核对 approval-write、approval-read，检查两者没有 error/isError；原有文件内容逐字比较保持。诊断初版误将两步回放当作一个结果，已依据原始录制修正，未修改录制内容。

## Windows 完整回归暴露的目录夹具问题

Windows 完整 QS Web 为 48 通过、2 失败；另外报告 2 个另一平台废弃快照。两项失败来自回退配置用例在自动选择原生目录后端时，错误等待网页目录对话框。官方 NativeDirectoryFlow 不渲染 DOM，而是打开宿主系统弹窗。

将回退配置用例分别运行 auto 和 browse：auto 验证真实模块图、官方入口及原生插件装配；browse 完成真实网页目录选择和草稿输入。没有把原生弹窗交互计为通过。Windows 原生弹窗的完整人工/桌面交互仍须独立验收。完整运行日志为 logs/repair-v1-qs-web-windows-reconciliation.log。
