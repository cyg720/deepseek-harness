# SDK 快照启动失败根因与剩余差异

日期：2026-09-24。结论：已修复 SDK 回放临时 JSONL 的路径转义错误；第二优先整体验收仍未通过。W11 延期，保留说明入口，不接入真实登录。

## 根因与修复

全量快照原结果为 100 失败、23 通过、10 跳过。其中 SDK 18 项均报 `cannot create effect on inactive context`。单独重放 text-turn 仍失败，排除了必须并发才能发生的假设。

诊断在忽略目录内用 Node preload 观察 Cordis 生命周期和错误日志，未修改 Cordis 或 SDK 产品代码。实际调用链为：SDK 临时回放 JSONL 直接插入 Windows cwd → 反斜杠破坏 JSON → llm-replay 加载失败 → Include 事务回滚并卸载 SDK 插件 → 等待 Loader 的 initialize 请求继续访问失效 context。最早异常为 `Bad escaped character in JSON at position 87`。失效 context 是后续错误，不能据此推断正常插件热重装有同一缺陷。

`snapshots/sdk/sdk.snapshot.ts` 将 cwd 先进行 JSON 字符串转义，再替换序列化 JSONL 中的占位符。修改只作用于临时回放副本，未刷新或改写任何已提交 Session，也未放宽断言或更改归一化器。此局部修复不承诺处理嵌套工具参数 JSON 的任意模板替换。

首次诊断 preload 使用相对 `tsx/esm`，子进程的临时工作目录无法解析该包；修正为仓库解析出的绝对文件 URL 后才获取有效诊断。NODE_OPTIONS 在命令结束时恢复原值。
