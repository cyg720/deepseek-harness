# 空草稿整队引导与菜单仲裁

日期：2026-09-23。范围：官方输入语义在奇术空草稿加速手势和命令菜单中的对应实现。

## 实现

绑定且忙碌的会话在空草稿按 Ctrl/Cmd+Enter，通过 conversationPresentation.submission.steerQueue 调用官方 InputHub 队列编排。普通空发送、未绑定、空闲、阻塞或不可引导子会话不触发。官方拥有逐项更新、顺序与失败处理，QS 不再另写循环。命令菜单对带 Ctrl/Cmd 的 Enter 同样先仲裁，消费按键后不发送；Shift+Enter、输入法和重复按键保护保留。

最初尝试直接调用 SessionInput 的内部成员，类型检查拒绝，因为公开接口不包含 snapshot 和 steerQueue。最终使用公开 state 读草稿，并由官方共享呈现入口代理队列动作，没有以类型断言绕过接口。官方 apply 与 README 配对文件登记于 88-共享整队引导入口登记.md，QS 自有类型和测试不计入官方文件清单。

## 验证

输入包、共享 Host 入口及官方共享呈现回归共 13 文件、87 项通过；输入包语句 538/538、分支 371/371、函数 173/173、行 390/390，四项覆盖率均为 100%。新增 DOM 分支覆盖普通空发送、两种加速手势、空闲、阻塞、未绑定；生命周期验证官方委托以及子会话能力，菜单验证修饰键仍由菜单消费。

真实浏览器在 156 的八种非空投递组合后，空草稿 Ctrl+Enter 将四条已持久排队消息移动到 next-step，接着再创建一条排队消息，用空草稿 Cmd+Enter 验证相同效果。两次空草稿操作均没有新增 /api/session/prompt；页面异常为空。只执行该命名场景，其余 19 项未重跑，不能将上一批完整 20 项结果当作本批全量结果。
