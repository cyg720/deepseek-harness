# 界面四配置与官方回退验收

日期：2026-09-24。发现并修复两份已有 QS 回退配置的遗漏，新增真实 Loader/浏览器验收。六项全部通过，类型检查及定向 lint 通过。本批没有修改业务服务或官方界面实现。

## 缺陷与修正

`qishu/dev-components/switch/01-switch-to-official.patch.yml` 使用旧的 mode 字段，未传入当前 defaultUi；实际启动落入工作台，官方入口等待超时。修改为 defaultUi: official、showOfficialUiEntry: false，保持 QS 插件装配但默认关闭开发者入口。

`02-disable-qs-rows.patch.yml` 只禁用了早期七行，后续 QS 插件及目录选择器动态呈现仍留在客户端模块图。修改为当前 Web bundle 的全部 32 个 QS 顶层行，并清空 directory-picker.additionalClientSurfaces 的 native/browse 两个附加列表；保留官方目录后端与官方呈现。使用范围限定为 Web profile，删除将此文件直接并入所有 profile 全局配置的建议。

修复前两项配置文件测试均失败：01 为官方入口超时，02 为实际模块图仍有 QS 插件。负向日志为 `logs/repair-v1-ui-config-negative.log`。修复后的测试直接使用交付给用户的两份配置，没有在测试中重新拼一份替代配置。

## 六项真实浏览器验证

| 场景 | 断言及结果 |
| --- | --- |
| official / false | 初始官方界面，无 QS 返回入口；刷新仍为官方。通过。 |
| official / true | 初始官方界面，唯一返回入口可进入 QS；刷新恢复官方。通过。 |

四配置使用每例独占临时 overlay，Loader、构建模块、HTTP、WebSocket 和浏览器均为实际实现。每例关闭浏览器、Host、临时目录；仅使用静态演示登录，不接真实身份认证。全部用例断言 pageerror 与 console error 均为空。关闭入口后的程序化切换拒绝仍由既有 qs-shell config 单元测试负责，本轮没有通过页面私有对象调用伪造真实用户操作。
