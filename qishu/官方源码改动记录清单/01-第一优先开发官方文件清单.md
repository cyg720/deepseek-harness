### 构建残留事件（已处置）

在把七包接进 Client 编译聚合的过程中，最初几轮 qs 包的 `tsconfig.json` 项目引用不完整（例如 qs-shell 通过转写契约引用了 `@deepseek-ai/dsh-client-ui-chat/client` 却没有引用 `packages/client/ui-chat`）。`tsconfig.base.json` 的 `paths` 把裸包名解析到源码，于是官方包源码被拉进 qs 项目的程序；这些文件既不在该项目 `rootDir`/`include` 内（TS6059/TS6307），TS 就按源码相对路径把 `.js`/`.d.ts`/`.map` 写在了官方 `src/` 旁边。

| 项 | 记录 |
|---|---|
| 现象 | 一次性出现 984 个未跟踪的编译产物，分布在 `packages/client/ui-*` 等官方包的 `src/` 下 |
| 性质 | 未跟踪的构建残留，**不是**官方文件的修改；已跟踪文件零改动 |
| 处置 | 用 `git ls-files --others --exclude-standard` 列出并逐一确认与已跟踪文件无冲突后删除（`rm -f`），随后补全七包 tsconfig 的 `references` |
| 复核 | 修复后全量 `tsc -b tsconfig.client.json` 前后对比 `*/src/**` 下的 `.js`/`.map`/`.d.ts` 集合完全一致；当前仅剩 5 个官方已跟踪的手写声明与 `apps/web/lib/`（被 `.gitignore` 的 `lib/` 规则忽略） |
| 回退 | 无需回退；若后续再次出现同类残留，按同一"列未跟踪→核对→删除"流程处置，不要用整目录 `git clean` |

### 官方共享接口的零侵入复核

首次实现时曾在 `GlobalStandardProps` 上增加四个**必填**成员（`useQsTheme`/`useQsUiMode`/`useQsAuth`/`useQsArchivedSessions`）。框架级接口加必填成员会让所有官方组件的 props 类型不再成立，`tsc` 报出 70 处官方测试文件错误。已改为：

- 主题座席移入 `root` 条目自己的 inject face；
- 归档集合座席移入 qs-sessions 的 `qs.nav` 条目自己的 inject face；
- 仅保留登录座席 `useQsAuth` 作为**可选**全局成员（它必须由 qs-login 跨插件发布，qs-shell 据此渲染"登录组件未加载"故障面）。

复核结果：改用上述方案后 `tsc -b tsconfig.client.json` 为 0 error，官方包 `src/` 与测试零修改。
