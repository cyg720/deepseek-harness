# 强制规则与编码约定

## 摘要

仓库不仅靠 TypeScript 编译约束开发，还使用目录规则、插件导出规则、文档和运行期关系检查。以下规则应进入开发者自查，不能用增加 any、关闭门禁、伪造快照或复制官方实现来规避。

## 目录

- 规则来源与适用范围
- 编码和类型
- 架构与状态所有权
- 文档、生成物与依赖
- 易混淆规则
- 特定目录的额外约束

## 规则来源与适用范围

根 [AGENTS](../../../AGENTS.md)适用于整个仓库；[packages/AGENTS](../../../packages/AGENTS.md)覆盖 qs 包；[client/AGENTS](../../../packages/client/AGENTS.md)的目录管辖并不因 qs 使用 React 自动扩张，但我们采用官方 Client 机制时，其协议规则和对应执行门禁仍须遵守。`dsh.client` 也会使 client 目录以外的包进入相关依赖检查。不要用“文件不在 client 下”绕过运行期限制。

进入更细的目录前查是否还有 AGENTS，例如 snapshots、SDK 或 vendor 的专门说明。Agent Notes 中已归档记录只供历史查证，不能作为当前规则或重新改写。

## 编码和类型

| 规则 | 实施要求 | 常见错误 |
|---|---|---|
| ESM | package 使用 `type: module`；源码本地相对导入用 `.ts` | 混入只能 require 的运行路径，或按旧 JS 工程省略扩展名 |
| 跨包引用 | 使用包名和已有公开子路径；同包测试可直接引用内部源码 | `../../另一个包/src` 绕过依赖和公开接口 |
| strict/noImplicitAny | 保持严格类型；确实无法缩窄的 any 说明原因 | 为临时接线把 pending、ctx、Remote 结果转 any |
| opaque id | 跨层不透明身份使用已有品牌类型和构造方式 | 用普通 string 混用 SessionId、消息 id、请求 id |
| 判别联合 | 闭集用 assertNever；声明合并可扩展集合有明确 fallback | 把新节点丢弃，或误认为所有 kind 都能穷举 |
| 运行期校验 | 配置、JSON、文件、wire、worker、持久化处校验 | 同进程已类型化值层层重复校验，真正的输入边界却未校验 |
| types.ts | 仅类型内容 | 在类型文件中创建 store、注册插件或产生副作用 |
| 函数插件导出 | named exports：apply/inject/Config 等；不要 default export | default 对象与命名导出混用导致 Loader 丢失 namespace |
| service 插件导出 | 按 service class 默认导出形式 | 机械套用函数插件规则 |
| JSDoc | 模块和 export 的非显然契约；函数参数、非 void 返回 | 只描述代码动作，遗漏失败、所有权、时序 |
| 注释和尾行 | 源码注释用英文，解释局部非显然规则；单个结尾换行 | 把中文评审流水和过时方案写进实现注释 |

## 架构与状态所有权

- 新行为优先放在插件扩展点，避免改 agent-loop。确需改 loop 时必须更新架构说明及相关 SDK/快照。
- 能力划分看 Service Definition、Provider、Consumer 三种职责，不能只为文件整齐增加服务和抽象。一个仅有内部调用点的方法未必应该公开。
- 注册是可撤销 effect，注册函数返回 disposer；测试要证明卸载后条目、监听和资源确实清理。
- 一次异步操作尽量由一个生命周期控制器/事务负责。增加独立布尔值、定时器或队列前说明独立所有者和结束条件。
- 模型可见内容必须可从 Session 日志重建；纯面板位置、折叠和主题等 UI 状态不写入模型日志。
- 业务状态由 Host/Client 模型层拥有；组件 store 保存视图/交互状态，不能复制 Session、连接或完整历史成为第二份权威。
- 配置错误应在能判断的最早时机报错；不能 silently skip 缺失服务、未知配置或失败调用。
- 可调部署选项放入校验后的 Config；协议常量、安全不变量和外部规格不应被随意可配置化。
- 公共方法需要的默认值由所属实现显式解析，不在深处执行时暗中使用 `?? default` 改变参数含义。

## 文档、生成物与依赖

行为变更同时更新所属 README/JSDoc。非平凡代码或架构决定需要相应 Agent Note；普通局部文档整理不应伪造一份“功能已实现”的记录。生成的 catalog、Remote 文件和网站投影由源文件及生成器维护，不手工修补产物让检查变绿。

使用维护中的依赖应能减少自有实现与测试，不能把依赖选择当成绕过现有 primitives 的理由。依赖清单、构建 external、运行期服务依赖是不同声明，见第 04 篇。增加第三方分发内容时核对仓库 notice 生成规则，不把 devDependency 等同于“不会进入浏览器分发包”。

## 易混淆规则

| 错误理解 | 正确判断 |
|---|---|
| 所有包必须 private | 当前 release member 要求 public 发布属性，实验包等另有规则；按实际门禁分类 |
| 类型能编译就可以接入 | 还需要组合、资源、服务和槽声明生命周期验证 |
| 加在 package.json dependencies 就能控制 apply 顺序 | Cordis 服务 inject 才负责运行期激活等待 |
| 声明 public 就已经发布 | 仅是清单属性，实际发布是单独操作 |
| API pre-stable 可以破坏旧数据 | 已发布 Session 数据有独立兼容义务，发行候选版本也不能随意丢弃 |
| 所有失败都用 catch | 有的方法抛异常，有的方法返回 RemoteResult，有的返回 void 并发布错误快照 |
| 测试只要覆盖率 100% | 仍需真实 Loader/产物/用户可见行为证据 |

## 特定目录的额外约束

以下约束只在相应工作涉及该区域时应用，不能把局部约定扩大为全仓规则。

| 区域 | 特别注意 | 所属规则 |
|---|---|---|
| experimental | 默认私有，显式发布例外不代表稳定；普通 release 包不得将实验包列为生产依赖，不能因实验标签降低测试要求 | [实验包规则](../../../packages/experimental/AGENTS.md) |
| schedule | durable 状态只来自 schedule/change；读决策先 flush；fork 不继承父会话活跃提醒；卸载不删 durable 记录，不唤醒冷会话 | [调度规则](../../../packages/schedule/AGENTS.md) |
| web provider | 携凭据请求禁止自动跟随 redirect；测试证明重定向目标未被访问；这不防止配置的初始 endpoint 本身不可信 | [Web 能力规则](../../../packages/web/AGENTS.md) |
| native/system | Node-API 和按平台产物；无安装期编译 fallback；锁和隔离能力缺失不能静默成功；独立版本与发布 | [原生规则](../../../native/system/AGENTS.md) |
| scripts | gate 用无 shell 的 pnpm 调用；路径入库规范成正斜杠；语法感知扫描防空集和意外缩窄，扫描边界改动要有正反例 | [脚本规则](../../../scripts/AGENTS.md) |
| benchmarks | 按用户路径组织，计时使用 plain Node 的构建 worker；固定合成输入，不用真实用户 Session 或网络；资源独占并清理 | [性能规则](../../../benchmarks/AGENTS.md) |
| profile tests | 跨包 shipped profile 测试留在应用层，包内 Loader fixture 留在包内；产品 overlay 不能伪装为测试资源 | [Profile 测试规则](../../../apps/cli/tests/profiles/AGENTS.md) |

快照工作区中的 AGENTS 是测试输入资产，描述被测试 agent 的场景指令；它们不是开发者应在仓库根执行的规则，索引中单独标明。
