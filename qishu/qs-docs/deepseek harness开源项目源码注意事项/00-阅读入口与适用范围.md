## 如何判断一条注意事项的约束力

1. **仓库强制规则**：根及适用子目录 AGENTS、执行门禁、实际公共类型和运行期校验。适用范围由目录或门禁选择规则确定。
2. **源码行为**：当前实现已经表达的行为；需要结合所用入口、错误返回方式、生命周期一起理解。源码阅读证据不等于浏览器或真实模型验收。
3. **官方实现惯例**：可复用的设计方式，不意味着复制某个文件的所有局部选择。
4. **qs 方案选择**：来自[第一优先计划](../../dev-components/第一优先开发计划评审/00-评审总纲.md)的产品与实现决策，例如静态登录、七包拆分和开发者界面入口；并非 DSH 已有功能。
5. **待验证事项**：缺乏运行证据或仍需确定的接线。应进入 M0/M1，不能写成接口已接通。

遇到文件互相矛盾，不按文件日期或“官方”字样猜测：核对当前声明、调用方、测试和门禁，记录差异并统一方案。根规则中对 `private` 的笼统描述与当前发布家族约束就需要按实际清单和门禁核对，见第 04 篇。

## 使用与维护

本目录是按用户指定位置保存的项目学习资料，采用编号中文文档。当前[双语范围规则](../../../docs/i18n/README.md)没有把这些非 README 的 qishu 文档纳入强制配对范围；若以后新增 README 或移入 docs，应重新判断配对和元数据要求。不能由此推断这些文件无需校验链接或事实。

升级上游、修改公共接口或调整发布组合后，先更新所属官方文档/类型，再更新本资料和 qs 计划。文件链接用于定位源码；符号名用于检索，避免把会漂移的行号当成长期接口标识。
