# 测试、门禁与提交验收

## 摘要

检查必须覆盖实际改动和真实入口。单测、覆盖率、Loader 组合、浏览器回放、真实模型和构建产物证明的是不同事项；命令退出成功不能替代“本包确实被扫描”的证据。

## 测试层级与归属

| 层级 | 用途 | 归属/要求 |
|---|---|---|
| 纯逻辑 | 状态迁移、格式、数据投影、取消归属 | 包根 tests，不放 src/__tests__ |
| 组件 | 用户可见行为、键盘、错误与加载态 | 真实 props 或官方测试 runtime；jsdom pragma 按文件指定 |
| Loader 组合 | 导出、依赖、配置、槽和实际数据通路 | 真实 Loader 启动；手工 ctx.plugin 的测试不能替代 |
| 构建产物 | public exports、client factory、资源、worker/bin | 明确消费 lib，不能只靠 tsx 的源码能力 |
| Session 快照 | 录制 Session 既是回放输入又是持久化输出期望 | 顶层 snapshots，遵守代际与 owner 规则 |
| 非 Session 期望 | ARIA、几何、纯 UI 或 CLI 输出 | 所属 app/package/script 的 tests/expected，不冒用 *.snapshot.ts |
| Web 浏览器 | 真实组装界面、样式和 keyless replay | 当前 vitest.web.config 的 include 范围 |
| 真实 API | 模型/provider 实际表现与外部副作用 | 有对应 key 执行；无 key 的 self-skip 不等于真实调用通过 |
| 性能 | 长会话、时间、堆和规模退化 | benchmarks 正式门禁；普通 perf 文件不自动成为 CI 门禁 |

产品可见插件需要非单元的真实组合测试。只 mock 外部或非确定性输入，让下游真实实现工作。外部副作用通过重读文件或独立查询验证，不相信模型说“已经完成”。

## qs 包的扫描差异

| 检查 | 当前源码选择范围 | 对 qs 的含义 |
|---|---|---|
| 默认 Vitest | packages/*/*/tests 等 | qs 包测试可被默认 lane 发现 |
| test:gui | packages/client 与 packages/host | 不包含 packages/qs；必须增加明确的 qs 测试执行 |
| 覆盖率 include | packages/*/*/src/**/*.{ts,tsx}，另有明示 exclude | qs 实现默认进入 per-file 100% 要求，不可用 exclusion 藏缺口 |
| Web lane | apps/web/tests 的 e2e/snapshot 和指定 inspector 场景 | 在 qs/tests 随手写浏览器用例不会自动被 Web lane 跑到 |
| Client 包/依赖检查 | client 路径及 dsh.client 选择规则 | qs 有 dsh.client，应逐项核实适用，不只按目录猜测 |
| UI i18n | 扫描 packages/*/*/src/client 下 TSX，并扩展相关 Client 根 | qs 出现页面源码后应验证实扫文件，不应认为只管 client 分组 |
| Client 域依赖图 | 当前 CLIENT_DIR 为 packages/client | qs 的包内域约束不能靠这条现有门禁自动证明；按实际拆分补验证或明确人工检查 |

若决定调整公共扫描配置，连同“新增错误样例确实被拒绝”的证据一起提交。不能只写一个新 glob 却不证明门禁执行到了。

## 命令选择与执行条件

下表是从当前 package.json/测试配置整理的执行菜单，不表示本轮都执行过；实际结果只记在第 12 篇。以改动选择最小充分集合，已经通过的检查不为提交动作重复跑。

| 目的 | 当前命令/入口 | 注意 |
|---|---|---|
| 包/工程结构 | pnpm run constraints | 分类、引用、清单等；失败要区分新问题与已存在问题 |
| Client 接入 | pnpm run verify-client-packages / verify-package-dependencies / verify-tsconfig-paths | 看真实扫描范围，不滥用 --fix |
| 类型 | pnpm run typecheck | 会先生成 Host 契约；不是只跑 Client tsc |
| 静态代码 | pnpm run lint | 公共命令带构建前置；纯文档扫描不是 TypeScript 行为测试 |
| qs 用例 | pnpm exec vitest run packages/qs | 骨架没有功能测试时不能宣称业务通过；不要 passWithNoTests |
| 定向覆盖 | 按 dsh-pre-push-checks 同时指定 tests 与受影响 coverage.include | 测试过滤不等于覆盖率过滤 |
| GUI 官方相邻面 | pnpm run test:gui | 不替代 qs 包用例 |
| 浏览器回放 | 设置 DSH_SNAPSHOT=replay 后 pnpm run test:web | 该命令先 build；不要 refresh 掩盖回归 |
| 真实 API | pnpm run test:e2e 的相关目标 | 不读取或打印真实 key |
| 完整构建 | pnpm run build | 产物测试前置；不是所有文档改动都需要产品全套测试 |
| 发布视图 | pnpm run hygiene 或相关 built 检查 | publint 和 NodeNext 需要真实产物 |
| 文档快检 | pnpm run test:docs | 不包含完整 doc-typecheck/站点构建 |
| 文档完整检查 | pnpm run doc-sync | 可能生成构建产物；需记录失败和环境限制 |
| Diff 格式 | git diff --check；提交前 staged 版本 | 不覆盖未跟踪文件正文，新增文档另做检查 |

PowerShell 设置环境变量需使用 PowerShell 语法，并在任务后恢复原值；不能直接粘贴 POSIX 的 `DSH_SNAPSHOT=replay command`。这里不替代具体场景的可执行脚本。需要稳定重放时，以对应场景和官方 launcher 为准。

## 并发资源与失败诊断

Vitest 文件、coverage partitions 与其他门禁可能同时运行在共享主机。端口用动态分配，临时目录隔离，子进程/环境修改/fake timer 在 finally 或 teardown 恢复；取消后等待实际静止。不能用固定 sleep 假装同步，也不能把“单跑通过”当成并发问题已解决。

错误记录包含命令、检出版本、运行环境、退出码和诊断。区分环境缺失、既有仓库故障和当前改动造成的回归；不通过关闭校验、修改标准答案或吞错获取绿色。

## 文档及提交要求

README、中英文对照与 i18n 记录按文档规则同次更新；注释中的事实和生成 catalog 也有 owner。非平凡变更更新所属 Agent Note，归档记录冻结不改。qishu 的非 README 学习文档并不自动受所有 Markdown 扫描覆盖，需要显式链接/格式检查。

GUI 行为 PR 按 record-browser-gif 要求附真实服务器和真实模型流程的 GIF；原型模拟、fixture 回放和截图不能冒充这类证据。本轮只写文档，不构成 GUI 行为 PR。

Git hooks 是窄检查：pre-commit 处理 staged 配对、lint、notice、空白和 vendor 约束；pre-push 运行 typecheck，不自动代做完整测试。只有用户授权的提交/推送才执行；提交分界按具体任务要求，保留已有工作区修改。
