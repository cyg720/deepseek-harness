# 七插件开发前检查清单

## 摘要

本清单把源码规则映射到第一优先的七个独立插件。框架创建只是 M0 的部分工作；正式编码前应确认接口、依赖、资源和验收归属，避免先画完页面再发现数据通路不成立。

## 七包职责与源码模板

| 包 | 本阶段职责 | 重点参照 | 不应承担 |
|---|---|---|---|
| qs-shell | root、布局、子槽、开发者切换控制器 | ui-layout、ui-slots、ui-renderer | Agent loop、真实授权、全部子包内部逻辑 |
| qs-login | 静态登录页、本地展示状态 | locale/store 和官方注册方式 | 伪装真实认证、保存密码 |
| qs-sessions | 列表/切换/创建/改名/归档/本地置顶 | session-controller Client、workspace-controller Client、ui-workspace | 第二份会话数据库、伪删除 |
| qs-composer | 未归属草稿交接与官方 InputActions 呈现 | ui-conversation input/contract/apply | 自建传输、绕过输入仲裁、第二套 Host 队列 |
| qs-transcript | Chat 节点显示、分页、滚动及交互宿主 | ui-chat target/source/节点、primitives | 每 token 重建全部历史、独立 Session 投影权威 |
| qs-approval | 审批请求卡片与回答 | PendingApproval、官方 listener | 再注册一份审批请求 owner、自动代答 |
| qs-questions | 批量问题/自由文本/plan-review 与回答 | PendingQuestion、QuestionAnswer、draft store | 按翻译文本猜协议、遗漏合法答案 |

## 各包必须确定的事项

### qs-shell

- 明确所有 children 槽的 kind/scope/owner，避免同一声明有两个 owner。
- 登录缺失显示组件故障，不静默绕过；服务恢复后可重新判断登录。
- root 内部故障、entry 故障、加载失败和依赖等待分别诊断。
- defaultUi/showOfficialUiEntry 验证真实配置传递和 patch 整值覆盖。
- 切换控制器独立于可释放 root；官方返回入口由仍存活的公共槽承载。
- 界面模式切换不能误接为卸载官方 listener；生成/pending 期间继续保持请求。

### qs-login

- 本地静态逻辑清楚说明不是真实认证；密码只用于当前输入交互，不持久化。
- 用户名、记住行为和登录状态分别确定存储策略；存储抛错有可用降级。
- 未登录时不挂载工作台视图子树；不宣称已阻止整个官方运行时的所有后台订阅。
- 表单校验、忙碌、失败、键盘和移动断点均进入组件测试。

### qs-sessions

- 使用官方列表与当前选择；归档集合、子会话、空会话显示规则明确。
- 新建和首次发送共用一致的结果未知策略，不让两个入口分别制造不同语义。
- 归档走公开工作区服务；“本地从列表移除”不是成功归档。
- 本地 pins 与服务端状态分开；重命名/归档失败不伪造成功。
- 运行中/队列非空/pending 的归档限制是 qs 交互政策，客户端检查不是 Host 原子锁。

### qs-composer

- 预分配品牌 SessionId 与本地 opId 各有用途，不把 opId 传给无参数 submit。
- 无会话、创建中、绑定中、阻塞、本地交接、延迟失败分别设计。
- 取消后迟到结果不选中、不发送；创建结果未知保留 id。
- 保留官方草稿和附件语义，失败不覆盖用户新输入。
- 运行中排队与停止分开；逐项引导不是排序；不展示整队暂停/继续。

### qs-transcript

- entry.inject.keyedHooks 与子槽 inject 区分；source/snapshot 身份稳定。
- target 尚未就绪时采用已验证空快照策略，不能直接解引用 undefined。
- unknown kind、工具兜底、interrupted、长 Markdown、历史前插均可显示。
- 交互宿主传完整 owner props，普通问题和 plan-review 都能选中。
- scrollTop/followLatest 按会话隔离，root 往返切换和分页后仍保持意图。

### qs-approval 与 qs-questions

- 按 sessionId + pending.key 隔离草稿、忙碌和错误。
- qs 卡片卸载不结束官方请求；真正 owner 卸载不伪装为普通视图切换。
- 双击只产生一次回答；失败恢复前核对当前 pending 仍有效。
- 审批只回答 allowed-once/rejected；缺详情不编造。
- 提问支持 selected/custom 和整批问题；按 intent label 选择批准项。
- 内部匹配 kind/id，界面自己的 copy 才用 locale。

## 跨包验收

M1 先做真实纵向链路：静态登录 → 新建 → 输入交接 → 发送 → 流式 → 停止 → 审批 → 提问，然后再扩展视觉。不能用七个孤立 demo 代替同一 Loader 组合。

| 场景 | 至少证明 |
|---|---|
| create 响应丢失 | 同一 sessionId 恢复，不产生第二个会话 |
| A 失败、B 已输入 | B 不被覆盖，不误归因到其他会话 |
| A→B→A | 旧操作代次不复活，滚动和草稿各归其主 |
| 奇术→官方→奇术 | 请求继续、返回入口可达、草稿保存、无重复注册 |
| qs HMR | 注册清理，官方请求存续，状态丢失范围符合约定 |
| 缺登录/缺服务/缺资源 | 分别得到真实可诊断结果，不全部包装成根故障 |
| 断线/重连/Host 重启 | 基线恢复、历史一致、未提交草稿不丢、不伪造投递 |
| 默认四种入口配置 | 初始界面和是否显示返回/切换按钮完全符合计划 |

## 暂不扩大的范围

静态登录不接真实登录接口；附件实传、模型设置和右侧业务内容按第一优先追踪表处理；本轮源码资料不授权直接进入这些功能。公共 framework 的新扩展、跨 feature 运行导出、额外队列协议都不能为赶工临时添加。
