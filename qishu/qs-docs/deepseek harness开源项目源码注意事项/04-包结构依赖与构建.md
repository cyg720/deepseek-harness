# 包结构、依赖与构建

## 摘要

新增一个目录不足以让插件进入产品。workspace 发现、TS project references、源别名、npm 依赖、浏览器模块图、Cordis 配置与产物资源必须分别接通。先让空壳遵守工程规则，再逐个接入功能。

## 包目录与发布分类

当前 workspace 通过 `packages/*/*` 发现普通包。因此七个 qs 包位于 `packages/qs/qs-*`，不是 `packages/qs/workbensh/<七包>`。qs 分组本身不需要成为第八个包。

包名使用 `@deepseek-ai/dsh-<name>`；client 分组的目录命名模式是 `dsh-client-*`，不应将它误套到已约定的 `dsh-qs-*` 名称。版本、repository.directory、exports、files 和 publishConfig 应与当前发布家族约束一致。

当前 qs 骨架与官方普通发布包均声明 `publishConfig.access: public`，不设置 `private: true`。根包和其他私有类别不同，实验包也有例外分类。以[工作区约束](../../../scripts/check-workspace-constraints.ts)和实际 manifest 为准；不要把某份旧说明里的“所有包 private”当成通用规则。此属性不授权执行发布。

## 三种依赖不能混淆

| 声明 | 对象 | 用途 | 不能替代什么 |
|---|---|---|---|
| npm dependencies / peers / devDependencies | 包及版本 | 安装、编译与各构建面的依赖分类 | 不保证槽先声明或服务先激活 |
| 插件 inject | Cordis 服务名 | 运行期服务等待和依赖生命周期 | 不让同步浏览器 require 等待模块下载 |
| dsh.client.external | 精确模块 specifier | 浏览器模块工厂需要共享身份的动态依赖 | 不是跨 feature 包获取组件和 helper 的后门 |
| dsh.client.inject | 包名信息边 | 检查展示、HMR 差异信息 | 不控制 apply 顺序 |
| slots.inject | 槽名 | 等待实际槽声明并跟随其生灭 | 不代替业务服务依赖 |

Client/Host 包的 Cordis peer 与 dev 版本保持一致。浏览器和仅类型关系通常属于 devDependencies；Host 值导入按分类策略决定 dependencies 或 peer+dev。不要机械地把全部 dsh-* 包放到同一 npm 字段。

Feature 插件之间共享类型可用 import type，共享行为用服务，共享 UI 用槽；静态基础 owner 如 client/store、ui-primitives 承担公共运行值。baseline externals 由官方平台表集中维护，不在每包重复声明 React/Cordis 等，也不允许通过配置 external 绕过 feature 边界。

## 源码和产物构建

当前工具要求由根 package.json 确定：Node `^22.19.0 || >=24.0.0`，pnpm `11.7.0`。不要把这个范围扩写成“任何高于 22 的版本”。Windows 与 WSL 分别安装依赖，避免共享另一系统的 native 二进制和链接。

| 文件/阶段 | 含义 |
|---|---|
| tsconfig.base.json | 源码 paths 与公共编译配置；不能加 include/files 缩窄所有继承者 |
| tsconfig.host.json | Host TS program，包含生成 Remote 所需的类型 |
| tsconfig.client.json | Client TS program，避免两端 Context 合并冲突 |
| 分 face 包根 tsconfig | 仅 solution；消费者引用对应 host/client 叶配置 |
| 普通 UI 插件 | 一个 Client 项目可同时产出空 Node loader 入口和 browser 入口，不因双入口就强拆两个 program |
| tsc | 将 JS 与声明输出至 lib/types 等声明位置 |
| Host tsdown/Typert | 先生成 Host 反射及 Host-for-Client Remote 契约 |
| Client tsdown | 从 tsc 产物生成浏览器工厂及 Node loader 产物 |
| Web build | Vite 构建壳与静态基础模块 |

浏览器动态 `lib/client.js` 是交给模块加载器的 factory 产物，不能当成普通 ESM 文件直接 import 来验证全部运行行为。共享 clientBundle 还负责 CSS 编译、外部模块处理和构建环境替换。

官方 typecheck 和 lint 公共命令会先生成 Host 契约。`*:contracts-ready` 只是已有前置产物的内部步骤，不能在干净 checkout 中用它省掉生成步骤后声称通过完整检查。

源码测试解析 workspace imports 到 src；产物冒烟才显式消费 lib。不要让同一测试进程混入两份模块单例。完整 build 还记录客户端公开环境与产物摘要；随后只重建某插件可能使先前完整构建记录过期，浏览器产物验收需遵守当前构建流程。

## 接入检查表

| 检查项 | 具体要求 |
|---|---|
| 包清单 | ESM、version、Cordis、main/types、exports、files、dsh.client.platform、bundle/watch |
| 入口 | Host 与 Client 分清；函数插件不添加 default；组件不通过 client 入口扩大公共导出 |
| TS | 正确基础配置、rootDir/outDir、所用 workspace project references、Client aggregate |
| 别名 | 通过官方路径生成器维护，不手改生成区后遗漏验证 |
| 组合 | 在 web-app patch 添加稳定 row id，并声明 resolver manifest 可找到的依赖 |
| 配置 | 用实际 Config 解析；测试整值覆盖和非法值 |
| CSS/资源 | CSS Modules 声明；所有相对运行资源被 files 覆盖；SVG/font 等不能只在开发目录存在 |
| 文档 | README 中英配对、Model Experience、Known Limitations；invariant 缺省原因按包实际职责说明 |
| 分组文档 | packages/qs/README.md 声明子系统归属并满足双语要求；FRAMEWORK.md 不能代替分组 README 门禁 |
| 测试 | tests 在包根；真实 Loader 组合、产物冒烟和浏览器场景各有归属 |

`./invariant` 只在独立观察值可能偏离时发布，用于检查包拥有的运行关系。不要为凑模板创建空检查、只验证服务存在、检查常量或忽略 reporter。

## 常见失败定位

- 找不到包：先核对 workspace 深度、包名和 resolver manifest，再看安装链接。
- TS 看不到服务：核对 type-only declaration merge 和正确编译 face，不用 any 掩盖。
- 插件持续 PENDING：查 inject 的服务，不靠调整 YAML 行顺序猜解法。
- 浏览器同步 require 报错：查 external supplier 和模块环，不把它当服务注入问题。
- 页面还是旧样式：检查真实服务器返回的产物、构建记录和 HMR，不只看 src 文件时间。
- 本地可用、打包丢资源：检查 files 和相对运行导入的发布闭包。
