## 易漂移事项

1. package 发布属性：旧文字中的 private 与当前 release member 门禁不同，按 manifest 分类核对。
2. 完整 typecheck/build 前置：Host 生成契约是当前 Client 编译的前提，不能长期记忆一条简化 tsc 命令。
3. UI hooks：标准 provide 的 hooks 与 entry 私有 keyedHooks 不同，后者不会自动出现在任意槽。
4. 请求判别值：PendingQuestion 同时覆盖 question 与 plan-review；不能只照功能名称写过滤器。
5. 返回方式：create/service archive 可抛错，rename/cancel 等返回 RemoteResult，submit 为 void；loadOlder 还需观察快照。
6. 扫描范围：test:gui 和 client-domain-graph 不自动覆盖 qs，与覆盖率/i18n 等扫描方式不同。
7. 样式 owner：官方 theme 规则与奇术品牌还原要形成明确映射，不能依靠无作用域全局 CSS。
8. 真实身份：本地静态登录不替换当前 authorization/connection 能力，开发者入口也不是用户角色鉴权。

## 后续维护

每次上游合并后，记录新 commit 并优先复查上述易漂移事项。公共类型改变时搜索所有 qs 消费者；更改计划后同步组件待办和验收矩阵，不能只在末尾追加“修正说明”而留下正文中的相反规则。

新增资料应链接到事实 owner，避免复制完整生成 catalog。源码规则、当前实现、产品选择和待验证项继续分开；运行失败保留命令和诊断，不把此前成功结果移植到新版本。
