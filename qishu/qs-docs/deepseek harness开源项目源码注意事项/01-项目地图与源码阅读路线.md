# 项目地图与源码阅读路线

## 摘要

DSH 是由 Cordis 组合的 agent harness。Agent、工具、模型、会话持久化、API 和浏览器表现都由插件承担。修改前先找“状态或行为由谁拥有”，再沿服务、事件和槽位查到消费者；不能把它当成一个入口文件控制所有业务的 React 应用。

## 项目分层

| 位置 | 职责 | 开发时的注意事项 |
|---|---|---|
| [apps](../../../apps/) | CLI、Web 构建壳、Desktop 等应用装配 | 新 Node 应用不能随意增加绕开 dsh 的执行入口；Desktop 有已定义的专用宿主架构 |
| [packages/core](../../../packages/core/) | Agent、Session、工具、system prompt 与默认 loop | UI 重写通常只消费这些能力，不修改 loop |
| [packages/boot](../../../packages/boot/) 与 [bundle](../../../packages/bundle/) | profile 初始化与有序配置层 | bundle 是安装/装配单位，功能插件是配置中的行；二者不能混用安装说明 |
| [packages/api](../../../packages/api/) 与 [typert](../../../packages/typert/) | Host controller、生成式 Remote、Gateway | 浏览器调用已有 Client 服务；新增 Host 方法需经过公开声明与生成管线 |
| [packages/client](../../../packages/client/) | Connection、模型适配、UI 插件、slot/render/store | 数据层、渲染基础设施、业务表现各有所有权 |
| [packages/host](../../../packages/host/) | Web 服务及宿主相关装配 | Web 资源、传输和服务启动不归业务组件管理 |
| [packages/interaction](../../../packages/interaction/) | 审批、用户问题、命令等交互能力 | UI 仅展示并回答已有请求，不能自己制造完成状态 |
| [packages/session](../../../packages/session/) | 日志持久化、投影、标题等 | 保持已发布 Session 数据可读取，不能用 UI 改动破坏日志 |
| [packages/llm](../../../packages/llm/)、[fs](../../../packages/fs/)、[shell](../../../packages/shell/)、[subprocess](../../../packages/subprocess/) | 能力定义与提供者 | 复用服务，不从组件直接连模型或启动进程 |
| [packages/qs](../../../packages/qs/) | 本项目七插件框架 | 目前只有工程框架，不能称为已完成工作台 |
| [vendor](../../../vendor/README.md) | 固定版本的 Cordis 等上游副本 | 按 manifest 和同步流程维护，不能当普通业务目录随意改 |
| [native](../../../native/README.md) 与 [python](../../../python/README.md) | 原生系统能力及 Python SDK/runtime | 平台、构建、发行和 SDK 兼容需要独立验证 |
| [scripts](../../../scripts/) | 生成器、门禁、构建、发布辅助 | 不手改派生目录来绕过源文件或生成器 |
| [snapshots](../../../snapshots/AGENTS.md)、[benchmarks](../../../benchmarks/) | 录制会话验收及性能门禁 | 快照不是随意放截图的文件夹；性能测试不是普通单测的替代 |
| [docs](../../../docs/AGENTS.md)、[website](../../../website/) | 文档事实及网站投影 | 网站不是另一份可独立漂移的正文 |

分组的完整扫描入口见[包分组索引](13-包分组与规则文件索引.md)。这里按职责组织，不声称每个分组都已逐行审阅。

## 启动与数据路径

### Web 启动

```text
dsh CLI → profile 与 bundle/patch 合成 → Host Cordis 插件树
  → client-modules 生成 WebBootGraph 和资源
  → 浏览器 __DSH_BOOT__ / 模块工厂注册
  → 浏览器 Cordis Loader 创建插件行
  → 服务依赖就绪后 apply
  → ui-renderer 渲染 root → 子槽 → 业务组件
```

“模块已下载”“模块工厂可执行”“服务已就绪”“槽已声明”“组件已渲染”是不同条件。看到 client.js HTTP 200 不能证明界面已经接线。

### 用户发送与模型输出

```text
组件动作 → 注册处注入的回调 → 官方 inputActions/ClientSessions
  → 生成式 Remote → Host session controller → Agent inbox/loop
  → 模型与工具 → 持久化事件及瞬时流
  → Remote follow/control → Client Session 模型
  → Conversation target → keyed source → 框架 hook → React
```

持久化输出和瞬时流是两条相关路径：断线重连需要由模型层恢复基线，不能只重播 React 内存中的 token。

### Desktop 例外必须按官方架构理解

[架构文档](../../../docs/architecture.md)定义了 Desktop 私有 Host 与打包 Node、管道传输和 `dsh-app://` 资源协议。不能把 Web 的 localhost 服务器启动方式生搬到 Desktop，也不能以 Desktop 内部启动方式为理由新增普通业务应用 bin。

## 阅读路线

| 目标 | 推荐顺序 |
|---|---|
| 建立全局认识 | 根 AGENTS → architecture → Cordis primer → development → testing |
| 增加 UI 插件 | packages/AGENTS → client/AGENTS → Web Client/Slots → 相近官方插件 apply/contract/component/tests |
| 改输入发送 | ui-conversation 的 contract/input → apply → input/facade → input/machine → session-controller Client → Host commands |
| 改流式显示 | conversation 文档 → ui-chat apply → snapshot/chat-nodes → 节点构建与行 renderer → 流式/分页测试 |
| 改审批或提问 | Host interaction 定义 → 官方 pending 类 → Client listener 与 domain registry → 组件/草稿 → 生命周期测试 |
| 增加 Host 能力 | service definition → provider/consumer → Remote 或工具注册 → 持久化/SDK影响 → 真实组合测试 |

## 影响范围判断

修改之前画出最短调用链，至少标出：用户动作、所属 session、服务方法、返回类型、数据权威、失败呈现、清理者、验证入口。若需要改公共 API，搜索所有消费者；pre-stable 不是“可以只改一个调用点”的许可。
