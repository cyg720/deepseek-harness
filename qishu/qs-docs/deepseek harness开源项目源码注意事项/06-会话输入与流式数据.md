# 会话、输入与流式数据

## 摘要

工作台应消费官方会话模型和输入机，避免维护另一份会话真相。本章按用户操作解释入口、结果、错误及恢复职责，尤其区分本地交接、远端接受和模型完成。

## 目录

- 会话模型与返回类型
- 首次创建和发送
- 草稿、停止与队列
- 流式、历史和滚动
- 连接恢复与并发隔离

## 会话模型与返回类型

Client 的主链为 ClientSessions → SessionManager → Session；Host 的 Session、Agent 不是同一个对象。通过 sessions.binding(id) 得到的 binding 包含可观察的 Session face。不能因 id 在 UI 文本中出现，就认为 binding、打开的数据和当前选择都已就绪。

| 操作 | 当前入口/结果 | 调用方责任 |
|---|---|---|
| 新建 | ClientSessions.create 返回 Promise<SessionId>，失败抛 SessionCreateError | 区分业务失败、传输未知与工作区挂接部分成功 |
| 选择 | sessions.open(id) 返回 void | 更新选择不等于所有历史加载完成；观察 openState 等状态 |
| 改名 | ISession.rename 返回 RemoteResult | 显式判断 ok，不能只 try/catch |
| 归档 | ctx.workspaces.archiveSession 返回 Promise<void>，服务将错误结果转异常 | 通过公开工作区服务接线，读取 archivedSessionIds 过滤列表 |
| 旧历史 | ISession.loadOlder 返回 Promise<void> | 同时观察 loadingOlder/openState，不能把 Promise 结束当完整成功凭证 |
| 输入提交 | InputActions.submit(): void | 由官方输入机仲裁、乐观交接与恢复，不 await 一个不存在的确认 |
| 停止 | ISession.cancel 返回 RemoteResult | 检查业务结果；待发队列不随当前轮停止而清空 |
| 队列行操作 | ISession.updateQueue(itemId, action) 返回 RemoteResult | 使用真实 occurrence id；行已消费或轮次已结束时处理失败 |

同名方法在底层 model、公开 service 和 UI navigation wrapper 上可能返回不同类型。接口表必须写出所用层。对归档而言，工作区 model 返回 RemoteResult，公开 service 再抛错；不要运行值导入 ui-workspace 内部 navigation 来绕开服务。

## 首次创建和发送

无会话时，session-maybe 只保证输入区能存在，inputActions 仍可能 undefined。qs 的未归属草稿是本地交互状态；已有会话草稿交给官方输入机。

计划中的流程应区分以下阶段：

1. 捕获本次草稿、操作代次和预分配 SessionId，暂时冻结本次交接。
2. 调 create，workspaceId/cwd 按所用公开入口的规则选择，不猜测同时传入的含义。
3. 明确成功后保留 id，确认操作仍有效，再选择会话并等待对应输入绑定。
4. 投递前重新检查连接、模型、pending、会话加载和操作代次。
5. setDraft 后 submit，由官方输入机负责后续提交仲裁与失败恢复。

| 创建结果 | 正确处理 | 禁止行为 |
|---|---|---|
| 明确未创建 | 保留草稿，解释业务错误，显式重试 | 仅凭网络错误断言不存在会话 |
| 结果未知 | 保留预分配 id；查列表/绑定，必要时以同一 id 与原参数幂等恢复 | 每次点击生成新 id，制造多个空会话 |
| 已创建但工作区挂接失败 | 从错误数据保留 sessionId，提示未分组 | 当成创建前失败再次创建 |
| 创建完成但操作已取消/已导航 | 结算原操作记录；不抢当前选择、不继续发送 | 丢失创建记录或迟到回调自动 open/submit |

Host create 支持调用方 id 的幂等创建/采用，但这不延伸为 prompt 或 submit 幂等。重新确认创建结果不能顺便重新投递已交接的消息。只比较当前 sessionId 也不够：A→B→A 后旧操作仍可能过期，需操作代次或等价生命周期状态。

## 草稿、停止与队列

官方公开 submit 固定走 queue 模式。输入机包含 claim/命令仲裁和 detached 普通发送；其 phase 可在远端完成前恢复。draft 清空、phase 回稳只能作为本地交接观察，不能当“模型已收到”或“任务成功”。promptError 为会话级错误，也不能可靠归因到某一条消息。

发送 A 后用户输入 B，A 延迟失败时，自建层不能 setDraft(A) 覆盖 B。官方 facade 内部保留 detached 草稿并处理恢复；qs 应显示可用错误信息，逐条失败卡/重试入口必须先证实有公开稳定身份支持。

停止当前轮后，Host 待发队列按 FIFO 继续。UI 文案须说明这一点。逐条引导是把指定待发消息交给当前轮，不是修改列表排序。没有已核对的公开整队暂停/继续接口，qs 第一优先不显示这类入口，也不建第二套本地队列。

IME 组合输入期间不提交；Enter/Shift+Enter、按钮点击、建议 chip 填草稿都应走同一业务入口。不能通过直接调用 prompt 绕过 InputActions 的命令、引用、附件和阻塞规则。附件仅占位是 qs 范围决策，不代表官方输入没有附件状态；切回官方后保留其已有草稿与附件。

## 流式、历史和滚动

ChatSnapshot 的 order 与 nodes store 是主要消费面；legacy 不是新转写主数据。每行通过 keyed source 读取其节点和 process 状态，未知可扩展 kind 需要安全兜底。

历史是持久化事件窗口，实时流含尚未落定的瞬时更新。重连可能整体替换当前窗口；分页会前插历史；流式生成可能同时推进。不要基于“只会 append”设计列表，也不要用数组下标作为消息身份。

- 自动跟随与用户上滚阅读是两种意图，不能每次增量强制 scrollIntoView。
- 按 SessionId 保存位置与 followLatest，切 A/B 不共享一个 scrollTop。
- 历史前插采用可见消息锚点，不能简单恢复旧绝对高度。
- 对长 Markdown、未闭合代码块、未知工具输出、interrupted/settled/running 状态分别验证。
- 不把每个 token 写成新的持久事件；当前 compact Assistant settlement 与瞬时 stream 已有所属实现。

## 连接恢复与并发隔离

Connection 管物理连接及 generation；每个逻辑 RemoteStream 和 Client model 管自己的基线/恢复。源码明确不存在一个万能 resync() 可以被任意 UI 调用。断开时可保留可读数据与草稿，但不得伪造当前在线或投递成功。

每个异步结果归属发起的 session/request；原会话状态应按原键结算，当前视图写入需校验导航代次。列表、页面、草稿、错误提示和滚动均有各自归属，不能只隔离消息文本。
