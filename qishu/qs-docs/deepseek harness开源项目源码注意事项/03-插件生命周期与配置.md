# 插件生命周期与配置

## 摘要

插件能否正常装载、卸载和重载，取决于依赖、注册和异步工作的所有权。页面显示只是生命周期的一部分。qs 工作台与官方界面共存时，这些规则比组件结构更重要。

## 目录

- Cordis 装载与导出
- 注册与清理

- Profile、Bundle、Patch
- 配置与官方界面切换

## Cordis 装载与导出

函数插件使用命名 apply/inject/Config；Service 插件按类的形式提供服务。不要混合两种导出方式。官方有 default export 使 Loader 丢失 inject 信息的[事故记录](../../../docs/postmortem/0001-acp-default-export-drops-inject.md)。

必需服务在插件的 inject 声明，服务缺失会使 fiber 等待，不是自动降级。可选服务通过 `ctx.get(name)` 读取，并设计缺失表现；只有读取一次不会自动解决服务后续出现或撤销的反应问题。缺失、迟到、恢复和卸载都要覆盖。

Host 与浏览器虽然都使用 Cordis Context，但服务集合与类型声明不同。例如两端都可出现 `sessions` 名称，不能据名称相同就把 Host 实现导入 Client。

## 注册与清理

| 资源 | 谁创建 | 结束时应证明什么 |
|---|---|---|
| 工具/适配器/菜单/槽贡献 | apply 或注册回调 | dispose 后注册消失，重载不重复 |
| 事件监听 | ctx.on 或 effect 内安装者 | 不再接收后续事件，迟到回调不修改已释放视图 |
| 定时器/DOM 监听/快捷键 | 所属插件或视图 effect | 退出对应生命周期时移除；没有隐藏界面仍拦键 |
| 异步操作 | 独立操作控制器 | 取消是否只提出请求、是否等待静止状态，二者分清 |
| 子进程/worker/流 | 发起者 | abort/kill 后等待实际退出，避免孤儿资源 |
| pending 请求 | 官方交互 domain | qs 组件卸载不代答；真正 domain 卸载按官方委托语义处理 |
| 跨槽 store | 当前 apply 的明确所有者 | 普通视图切换不意外丢失；插件卸载后的保留策略另行定义 |

一个 effect 内绑定相互依赖的资源，按明确顺序清理。不要在模块顶层注册监听、创建可变会话单例或依赖进程退出兜底。回调分发器要隔离单个监听异常，避免一个坏 listener 阻断后续消费者。

## 事件模式

事件的 dispatch mode 属于公共契约，不凭命名猜测。emit 用于通知；parallel、serial 等有各自等待和结果规则。waterfall 在本仓库是 around middleware，监听者收到 next；观察、包裹或继续处理时必须委托，主动终止才不调用 next。具体同步/异步返回由事件签名决定，不能把所有 waterfall 都视为普通数组变换。

新增 typed event 通过 declaration merging，并写 `@mode` 和 payload `@param`。需要 scoped-event 分析但 payload 不含作用域标识时，按仓库要求记录明确的 unsupported 原因。拦截权限决策必须在真正执行操作的位置生效，不能只在 UI 隐藏按钮或从 tool schema 删除字段。

## Profile、Bundle、Patch

当前架构中的配置顺序是：profile 列出的 bundle 顺序 → profile 自己的 patch → home 级 patch → 命令行指定的 overlay。后层可覆盖前层，但目标通过行 id 定位。

**patch 替换一行 config 是整值替换。** 不应假设只写一个字段会自动保留该行其余配置。新增开发者入口配置时，验证合成结果而非仅看 YAML 差异。

`!!js` 表达式允许在 plugin config 和 entry disabled 上按各自上下文解析；不是任意 metadata 的模板系统，更不是 `!js`。环境选择插件组合时使用 overlay。内置 profile 的 live reload 策略不同，不能把 Web 可动态改配置推导到 headless/SDK 的同一生命周期。

正常 Node 应用走 dsh profile。构建、测试工具和已定义 Desktop 私有宿主是明确分类的例外；不能借例外再增加业务可执行入口。

## 配置与官方界面切换

qs 计划的 `defaultUi`、`showOfficialUiEntry` 是拟实现字段，当前七包框架尚未接入。首先找官方 Host-to-Client 配置路径，测试默认值、非法值和完整 overlay 合成，再写用户启动说明。

构建时 `DSH_CLIENT_*` 与运行配置不同：前者进入公开浏览器产物，不可存秘密，修改后通常需要重建；后者是否重载取决于实际 profile 和插件生命周期。字符串 `false` 不能用普通 truthy 判断。

| 操作 | 允许的效果 | 不可错误宣称 |
|---|---|---|
| 运行期奇术/官方切换 | 释放并恢复奇术视图注册，保留控制器和指定 store | 已卸载全部奇术插件 |
| 调整 root priority | 改变候选胜出关系 | 所有监听、样式、store 已清理 |
| 停用七插件行 | 释放其 effect，官方继续运行 | 不重启/不重新装配仍能用已停用插件提供返回按钮 |

切换控制器不能属于它自己将释放的 root 子树；官方返回入口不能挂在已消失的 qs.* 槽内。普通视图切换不调用 cancel、answer、signOut。开发者配置是部署入口控制，不是按用户身份鉴权。
