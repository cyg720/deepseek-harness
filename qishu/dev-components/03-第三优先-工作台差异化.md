# 第三优先：工作台差异化

> **阶段目标**：从"能用的会话界面"升级为"工作台"——一屏多任务、资料随手可得、产品能力显性化。本阶段是产品辨识度的来源，但必须在第一、第二优先稳定之后做。
>
> **前置条件**：[第一优先](01-第一优先-最小可用工作台.md) 与 [第二优先](02-第二优先-转写与诊断.md) 已完成，且长会话、审批、提问路径都已验证过。
>
> **相关文档**：[遮蔽对照表](04-遮蔽对照表.md) · [第一优先开发计划评审](第一优先开发计划评审/00-评审总纲.md)
>
> 文档约定：本文件非 `README.md`、不带 `.i18n.yaml`，不在 DSH 双语语料库与 doc-sync 门禁范围内。

## 一、排序原则

1. **先补"干活必需"，再补"看着像工作台"**：右栏/文件/通知优先于设置页与皮肤。
2. **先复用官方数据面，再自建数据**：能通过保留加载的官方包拿到数据的（作业、调度、目标、轨迹）先接；需要自己走 Remote/同源路由的（第三方接口）后做。
3. **每加一个面板都要先问：它有官方行被我遮蔽了吗？** 有＝官方原本提供过能力，优先级提高；没有＝新增能力，可以缓。

## 二、组件清单（按开发顺序）

| 顺序 | 组件 | 作用（为什么值得做 / 不做的代价） | 对应官方原组件 | 数据来源 / 接口 | 前置 |
|---|---|---|---|---|---|
| **1** | **检查器 / 右栏** | 工作时不必离开界面：引用、附件、可交付物、文档预览都在手边；这是"工作台"与"聊天窗口"最直观的差别 | `ui-sidebar-right`、`ui-sidebar-documentpreview`、`ui-deliverables`、`ui-attachment`、`ui-reference` | 官方对应包保留加载后，先核实其是否暴露可复用数据源；否则自己走 Remote/同源路由 | 转写已稳定 |
| **2** | **通知与状态**（toast / 状态条 / 长任务进度） | 长任务的信任感来源：用户切走再回来能知道发生了什么、有没有失败 | `ui-message-feedback`（反馈类）、`ui-approval`（提示类）以及 `shell.overlay` 的原占用者 | 自建 `qs.overlay`（list）与 `qs.status`（list）槽 | 外壳骨架 |
| **3** | **工作区与文件视图** | 工作台的主场景入口：选目录、看文件、开 workspace | `ui-workspace`、`ui-sidebar-files` | 官方数据读取通道需先核实；否则走 Remote | 检查器就绪 |
| **4** | **多面板 / 多标签 / 可拖拽布局** | 一屏多任务是工作台的核心体验；也是后续所有面板的容身之处 | `ui-layout`（列几何与面板切换）、`ui-dockkit`（属 baseline，可直接用） | 自建布局 store（折叠、宽度、活动视图 key） | 1–3 完成 |
| **5** | **作业面板** | 把后台任务显性化：长命令、批处理、定时执行的进度与结果 | `ui-jobs` | 官方 `ui-jobs` 是 `ctx.jobs` 记录的只读投影：保留加载后先核实其可复用数据源 | 多面板 |
| **6** | **调度面板** | 把"按时自动跑"变成可见可管的能力 | `ui-schedule` | 同上（`ctx.schedule` 的只读投影） | 多面板 |
| **7** | **目标面板** | 把长周期目标（goal）的状态与推进显性化 | `ui-goal` | 官方 `ui-goal` 的动词走 `goal.*` Remote；模型侧上下文由宿主 GoalService 拥有 | 多面板 |
| **8** | **子代理面板** | 多 agent 协作时唯一能看清"谁在干什么"的地方 | `ui-subagent` | 官方 `ui-subagent` / `ctx.subagents` | 作业面板经验可复用 |
| **9** | **轨迹视图** | 调试与复盘：按请求/轮次回看 token 与上下文构成 | `ui-trajectory`（独立 target + 定义） | 保留 `ui-trajectory` 加载以复用其 target | 转写已稳定 |
| **10** | **设置页**（模型/供应商/权限） | 部署与自服务的必要面，但不阻塞任何工作流 | `ui-settings`、`ui-settings-general`、`ui-settings-models`、`ui-settings-plugins`、`ui-settings-plugin-inventory`、`ui-permission-presets`、`ui-model-selection`、`ui-agent-preset` | `ctx.settingsScope` 可用；命名空间读写走 settings 控制器 | 数据面稳定后 |
| **11** | **第三方接口面板** | 你的产品接入外部系统的入口（应用中心/授权中心等） | **无官方对应**（DSH 不带业务集成面） | 宿主同源路由（`ctx.webserver.register`）→ 第三方/`services/*`；密钥留宿主 | 登录票据体系 |
| **12** | **品牌标识** | 产品识别；成本极低 | `ui-brand-official` | 自建组件 | 随时 |

> 官方 `ui-cordis`、`ui-workflow-run`、`ui-skill`、`ui-plan`、`ui-commands`、`ui-input-trigger` 等行：不遮蔽也不需要重建它们的能力（你已按需保留加载），本表不重复列出。

## 三、明确先不做（三阶段之外）

这些不是"永不"，而是**在核心链路稳定之前做会亏**：

| 项 | 原因 |
|---|---|
| 多会话并排布局 | 官方会话座位按"当前会话"解析，未验证；先做扎实单会话 |
| 主题 / 皮肤系统 | 官方 `ui-theme` 的 `--dsw-*` 令牌仍在写入 `body`，直接用它，自建皮肤是纯成本 |
| 附件 / `@` 引用 / 富文本输入 | 属输入机的完整能力，先把 send / cancel / queue 做扎实 |
| 为每个工具写专属视图 | 通用工具卡覆盖多数场景，专属视图按真实痛点逐个加 |
| 停用任何官方行 | 省下的启动开销远小于连锁失败风险；遮蔽已让它们不显示（见 [遮蔽对照表](04-遮蔽对照表.md)） |
| 自建 i18n 多语言体系 | 等文案规模真实上来再做；先集中在一个字典文件，便于将来迁移 |

## 四、本阶段完成定义（DoD）

- [ ] 一屏内可同时看到会话 + 检查器 +（可选）作业面板，布局可保存
- [ ] 长任务有通知与状态反馈，切走回来能判断结果
- [ ] 工作区/文件视图可用，选择结果能带进会话
- [ ] 至少一个产品自有能力（作业/调度/目标/第三方接口之一）以面板形式落地
- [ ] 设置页可改至少一项真实生效的配置
- [ ] 新面板接入只需往 `qs.*` 槽注册，不必修改外壳
