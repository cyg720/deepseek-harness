# 第一优先：最小可用工作台（MVD）

阶段目标：通过奇术工作台完成新建或继续会话、发送、流式阅读、取消、审批与提问回答。登录仅为静态演示入口，不接入真实登录、身份系统、票据或认证路由。本文件定义范围，实际验收证据另行记录。

相关文档：[第一优先评审](第一优先开发计划评审/00-评审总纲.md)、[官方插件对应与整改验收](第一优先开发计划评审/12-官方插件对应与整改验收.md)、[界面切换配置](第一优先开发计划评审/10-界面切换与回退配置.md)、[第二优先需求](02-第二优先-转写与诊断.md)。本文仍遵守仓库文档、链接和事实核验规则；没有双语侧车不代表免除全部检查。

## 一、插件与座位分工

沿用官方一切皆插件的方式：九个官方呈现职责分别对应九个 QS 插件，另加自有登录，共十个包。服务保持唯一，不以复制 Session 控制器替换呈现。

| 官方职责 | QS 包 | 第一优先职责 |
|---|---|---|
| ui-layout | qs-shell | root、全局布局及顶层槽；不集中声明所有业务子槽。 |
| ui-brand-official | qs-ui-brand | 品牌呈现。 |
| ui-sidebar | qs-ui-sidebar | 侧栏骨架与导航槽。 |
| ui-workspace | qs-sessions | 会话列表、工作区关联、新建、切换、重命名及归档。 |
| ui-conversation | qs-composer | Stage、欢迎区、输入、队列及会话内容座位。 |
| ui-chat | qs-transcript | 转写、分页、阅读位置及现有待回答交互呈现宿主。 |
| ui-approval | qs-approval | 审批卡及回答。 |
| ui-user-questions | qs-questions | 提问表单及回答。 |
| ui-sidebar-right | qs-ui-sidebar-right | 右栏骨架。 |
| 无官方对应 | qs-login | 静态登录演示及退出展示。 |

顶层 qs.stage/qs.inspector 使用 root 座位；会话内容由 qs-composer 的嵌套座位提供，转写为 session，允许尚未选择会话的输入为 session-maybe。精确定义以对应包 SlotMap 为准，不把 root 全局改为 session。跨包使用包名及 ESM 导入，不使用 require。

当前待回答交互宿主位于 Transcript。第二优先增加 Chat/trajectory 切换前，必须按[跨视图交互方案](第二优先开发计划评审/09-编码前接线与范围冻结.md)完成 G09，不能卸载唯一回答入口后仍宣称满足第一优先。

## 二、组件与验收要求

| 组件 | 数据及实现边界 | 必须验证的行为 |
|---|---|---|
| 静态登录 | qs-login 的本地演示 gateway 与 store；不访问真实认证接口 | 初始演示页、校验、提交中、演示成功、退出、重新进入；不持久化密码。 |
| 外壳及会话座位 | 复用官方主题、注册生命周期和 QS 布局状态 | 折叠、宽度、恢复、窄屏；卸载释放；无当前会话时不调用仅限 session 的 hook。 |
| 会话列表 | 官方会话与工作区数据面，qs-sessions 呈现 | 新建/切换/重命名/归档、失败恢复；旧请求不污染新会话。归档不称永久删除。 |
| 输入及队列 | 复用 SessionInput、inputActions 和官方接受/队列语义 | 发送/取消/排队、编辑/移除/引导、IME、重复点击、断线及迟到响应；断言真实答案与消息载荷。 |
| 助手流式转写 | 官方 chat 投影与节点类型，包括 assistant-step；不直接展示内部系统事件 JSON | 增量输出、刷新恢复、主动发送跟随、手动阅读保护、分页锚点及未知内容限制。 |
| 审批 | 官方 pending interaction，qs-approval 单一回答者 | 放行/拒绝、提交中、失败重试、已回答及切换隔离；实际 Host 继续执行。 |
| 提问 | 官方 pending interaction，qs-questions 单一回答者 | 单选/多选/自由填写、合法答案载荷、提交失败保留输入；实际 Host 继续。 |

## 三、静态登录边界

流程为演示页 → 本地演示校验 → 工作台 → 退出后回到演示页。沿用现有演示实现，不新增认证路由、SSO、Cookie、401 拦截或 services/authority 接入；演示账号不是真实身份。

登录页面只控制可见内容，不保护 Host RPC、文件读取或 agent 操作，也不承诺登录前不存在数据连接。记住用户名与记住凭证分开，密码和秘密不进入持久化存储。退出清理本地展示状态；不得承诺取消 Host 任务、撤销权限或清除服务端会话。再次进入从官方权威数据恢复。

本阶段不验收公网或多人身份隔离。未来真实认证需要独立需求和 Host 强制授权设计，不能以静态登录或“同源”作为安全依据。第二优先的第三方系统授权也不由静态登录提供。

## 四、完成定义与证据

- 静态进入与退出可用；未进入时工作台内容不出现在画面，明确这是展示要求。
- 新会话与已有会话都能发送，助手流式内容与真实会话一致；取消、队列与历史阅读不互相干扰。
- 真实 Host 回放至少完成一次审批及一次提问；失败重试、重复回答和切会话有断言。
- 默认 QS 界面使用 QS 呈现；开发者官方入口按配置显示，切回官方是合法功能，不能以“全程不出现官方 UI”否定切换测试。
- 两种 defaultUi 与两种 showOfficialUiEntry 组合分别验证；入口开关不等于 Host 权限。
- 测试、逐文件覆盖率、构建、浏览器、HMR 和在线 API 分别记录结果；历史证据及仍待复核项见[基线核查表](第二优先开发计划评审/10-全量问题处置与核查清单.md)。

## 五、范围之外

不接真实登录；不做多会话并排、自建主题系统、完整上传与 @ 引用编辑、富文本编辑器替换。第二优先承接工具诊断、命令、检查器、文件、布局、作业、调度、目标、轨迹、设置及第三方集成的独立需求。保留官方服务和开发者官方界面，不通过全局停用官方插件破坏依赖声明。
