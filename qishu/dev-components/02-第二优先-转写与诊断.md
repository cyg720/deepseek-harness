# 第二优先：转写、诊断与工作台差异化（二合一）

> **阶段目标**：让用户看清 agent 在做什么、为何慢、为何失败，并在同一工作台内查看资料、后台任务和配置；覆盖原第二优先的 7 项和原第三优先的 12 项需求。
>
> **前置条件**：[第一优先](01-第一优先-最小可用工作台.md) 的核心会话、审批、提问链路稳定。本阶段内部先完成转写诊断，再接工作台面板，保留原先的技术依赖，不要求一次性并行开发所有功能。
>
> **评审入口**：[评审总纲](第二优先开发计划评审/00-评审总纲.md)；[编码前接线与范围冻结](第二优先开发计划评审/09-编码前接线与范围冻结.md)；[遮蔽对照表](04-遮蔽对照表.md)。状态：已按用户授权进入实现与复核阶段，尚未整体验收；不接真实登录。当前未闭环项见[实施复核 v2](第二优先开发计划评审/审查结果-v2.md)；[报告173](../PRD/1-AI工作台/复核测试/173-最终门禁复跑与未闭环项.md)保留其当时的门禁结果，不作为后续修复后的唯一状态。全量处置见[问题核查清单](第二优先开发计划评审/10-全量问题处置与核查清单.md)，九组新增视觉规格见[状态与字段规格](第二优先开发计划评审/11-原型状态与字段规格.md)。

## 一、排序与插件原则

先补信息密度最高的工具、过程、错误，再完善连续历史、命令和上下文，随后接检查器、文件、布局、任务和设置。先复用官方数据与服务；每新增视图都核对官方被遮蔽的能力及注册单元。官方几个呈现插件就逐项对应几个独立 QS 插件，官方包内子插件保持对应注册与生命周期；纯服务、布局库不复制，不建立空插件。自有第三方集成另列插件且不冒称官方能力。

## 二、转写与诊断需求 D1–D7

| 顺序 | 组件（对应 chat 节点 kind） | 作用（为什么必须 / 不做会怎样） | 对应官方原组件 | 数据来源 | 验收标准 |
|---|---|---|---|---|---|
| **D1** | **工具调用卡**（`tool-call`） | agent 的行为几乎全部经由工具（读写文件、执行命令、搜索、子代理）。不做它，转写几乎是空的——**信息密度最高的一行**；也是用户判断"它到底改了什么"的唯一依据 | `ui-tool`（各工具专属视图）、`ui-chat` 的 tool 定义与渲染 | `useChat` → tool 节点（先只读 `node.data`；工具专属视图是第二层） | 一次读写文件、一次执行命令都能正确显示调用参数与结果 |
| **D2** | **轮次/步骤进度**（`turn-process`、`turn-tail`） | 长任务里唯一能回答"它现在在干什么、为什么慢、第几步了" | `ui-chat`（turn-process / turn-tail 定义与渲染）、`ui-conversation`（Turn/Step 坐标） | `useChat` | 一个多步骤任务能看出步骤推进与当前步骤 |
| **D3** | **错误与重试**（`turn-error`、`model-retry`、`turn-max-tokens`） | 把"卡住"与"失败"区分开；没有它问题不可诊断 | `ui-chat`（turn-error / retry / turn-max-tokens 定义与渲染） | `useChat` | 构造一次失败与一次重试，界面能明确区分并显示原因 |
| **D4** | **历史分页**（`loadOlder`） | 长会话的可用性边界；越晚做越容易返工（滚动锚点、虚拟列表、prepend 时的跳动） | `ui-conversation`（分页与会话骨架） | `loadOlder`（会话作用域） | 长会话滚到顶能拉取更早历史；前插时已有行不闪烁、不跳动 |
| **D5** | **排队与中途引导**（队列快照 + user/steering 历史） | 这是 DSH 的差异化能力（`followup` / `steer`），不接就等于丢掉产品特性：用户无法在 agent 工作时补话或改方向 | `ui-conversation`（inbox/队列 + 输入机）、`ui-chat`（inbox 定义与渲染） | `inputActions` + Session 队列快照 + `useChat`（user/steering） | 忙碌时补一条消息 → 出现在队列并可见；steer 生效 |
| **D6** | **上下文压力与压缩**（`compaction`、`manual-compaction` + 压力投影） | 长会话里用户唯一能理解"回答为什么变差/变了"的线索；也是排查成本的主要来源 | `ui-chat`（compaction / request-prompt / system-message 定义与渲染） | token-meter 压力投影 + Chat 压缩节点 | 触发一次压缩后界面有可见记录；上下文压力可见 |
| **D7** | **命令与斜杠**（`command` 节点 + 命令面板） | 效率面：让高级操作不必点鼠标；也让产品能力（工具、模式、预设）可发现 | `ui-commands`（命令目录服务 + 面板）、`ui-input-trigger`（输入触发） | 保留 `ui-commands` 加载以复用其目录服务 + `useChat`（command 节点） | 输入 `/` 能列出命令并执行；执行结果在转写中可见 |

D1 的工具专属呈现遵循 ui-tool 的八个内置子插件；先做关键读写/命令摘要，其余必须有对应可读摘要或明确限制。D4/D5 的按钮分页、锚点及队列动作已经存在，本阶段做增强与真实 Host 闭环。D6 不用轮次累计 token 冒充上下文压力。

## 三、工作台差异化需求 W1–W12

| 顺序 | 组件 | 作用（为什么值得做 / 不做的代价） | 对应官方原组件 | 数据来源 / 接口 | 前置 |
|---|---|---|---|---|---|
| **W1** | **检查器 / 右栏** | 工作时不必离开界面：引用、附件、可交付物、文档预览都在手边；这是"工作台"与"聊天窗口"最直观的差别 | `ui-sidebar-right`、`ui-sidebar-documentpreview`、`ui-deliverables`、`ui-attachment`、`ui-reference` | 官方对应包保留加载后，先核实其是否暴露可复用数据源；否则自己走 Remote/同源路由 | M3 转写与命令稳定 |
| **W2** | **通知与状态**（toast / 状态条 / 长任务进度） | 长任务的信任感来源：用户切走再回来能知道发生了什么、有没有失败 | `ui-message-feedback`（反馈类）、`ui-approval`（提示类）以及 `shell.overlay` 的原占用者 | 自建 `qs.overlay`（list）与 `qs.status`（list）槽 | 外壳骨架 |
| **W3** | **工作区与文件视图** | 工作台的主场景入口：选目录、看文件、开 workspace | `ui-workspace`、`ui-sidebar-files` | 官方数据读取通道需先核实；否则走 Remote | 检查器就绪 |
| **W4** | **多面板 / 多标签 / 可拖拽布局** | 一屏多任务是工作台的核心体验；也是后续所有面板的容身之处 | `ui-layout`（列几何与面板切换）、`ui-dockkit`（属 baseline，可直接用） | 扩展既有 QS 布局 store；复用 dockkit 公共布局能力 | 公共槽骨架先在 M0 验证；W1–W3 接入后再验完整布局 |
| **W5** | **作业面板** | 把后台任务显性化：长命令、批处理、定时执行的进度与结果 | `ui-jobs` | 官方 `ui-jobs` 是 `ctx.jobs` 记录的只读投影：保留加载后先核实其可复用数据源 | 多面板 |
| **W6** | **调度面板** | 把"按时自动跑"变成可见可管的能力 | `ui-schedule` | 同上（schedule 客户端镜像的只读投影） | 多面板 |
| **W7** | **目标面板** | 把长周期目标（goal）的状态与推进显性化 | `ui-goal` | 官方 `ui-goal` 的动词走 `remote.goals.*`；模型侧上下文由宿主 GoalService 拥有 | 多面板 |
| **W8** | **子代理面板** | 多 agent 协作时唯一能看清"谁在干什么"的地方 | `ui-subagent` | 官方 ui-subagent / sessions 的子代理目录及导航 | 作业面板经验可复用 |
| **W9** | **轨迹视图** | 调试与复盘：按请求/轮次回看 token 与上下文构成 | `ui-trajectory`（独立 target + 定义） | 保留 `ui-trajectory` 加载以复用其 target | M3 转写与命令稳定 |
| **W10** | **设置页**（模型/供应商/权限） | 部署与自服务的必要面，但不阻塞任何工作流 | `ui-settings`、`ui-settings-general`、`ui-settings-models`、`ui-settings-plugins`、`ui-settings-plugin-inventory`、`ui-permission-presets`、`ui-model-selection`、`ui-agent-preset` | `ctx.settingsScope` 可用；命名空间读写走 settings 控制器 | 数据面稳定后 |
| **W11** | **第三方集成延期说明入口** | 用户已明确本期延期真实集成，保留可见说明 | **无官方对应** | 本地说明，不发第三方业务请求，不采集凭证 | 本期验说明入口；后续接入另审真实认证和授权 |
| **W12** | **品牌标识** | 产品识别；成本极低 | `ui-brand-official` | 自建组件 | 随时 |

### 范围与事实校正

- W1 包含已有附件、引用、文档和可交付物的查看及打开；新增附件上传、完整 `@` 引用编辑和富文本输入仍不纳入本期。ui-reference 的已有触发贡献保持唯一，具体展示接线先通过 M0。
- W2 复用已有 qs.overlay、qs.status 和审批插件；ui-message-feedback 是消息/会话反馈，不是通用通知总线，需独立对应其真实反馈职责。通知只能依据真实事件，不承诺浏览器关闭后的系统推送。
- W3 扩展 ui-workspace 已有对应包 qs-sessions，不创建第二份工作区插件；目录选择器的浏览器/原生分支在 M0 核对，重写哪个呈现插件就逐项对应。
- W4 为同一当前会话的多面板、多标签和拖拽布局；多会话并排仍后置。ui-dockkit 是可复用布局库，不是待复制的业务插件。
- W5/W6 以官方实际公开能力为边界。jobs 和 schedule 的界面是只读目录；调度创建、暂停、删除等管理动作若要新增，须先核对 Host 能力并评审接缝，不能把只读目录验收成全部管理功能。
- W7 保留官方 goals 动作及权限；W8 保留子代理 one-shot、可续聊及父会话不可用限制；W9 是独立 trajectory target 的视图，不用 Chat 列表假冒轨迹。
- W10 ui-settings 提供唯一 settingsScope 服务；设置外壳对应 ui-settings-general，其余呈现插件独立对应。模型/供应商/权限/插件清单/代理预设均有任务和验收，不因“至少改一项设置”而省略其他模块。
- W11 已按用户 2026-09-22 的明确答复延期，本期只保留说明入口，不接真实登录或第三方业务。目标系统、操作范围、认证票据和授权/撤销规则属于后续接入前置，不再阻塞本期；说明入口不能计为真实集成交付。
- W12 复用已有 qs-ui-brand，验收品牌标识，不新建第二个品牌插件。

## 四、最终 Chat kind 与数据约束

| 最终 kind / 数据 | 归属 |
|---|---|
| assistant-step、user、steering、context、system-prompt | 保留第一优先能力、流式及默认折叠。 |
| tool-call | D1；根及 subCalls 来自官方投影。 |
| turn-process、turn-tail | D2；进行中、结束、部分输出及收尾不重复。 |
| turn-error、model-retry、turn-max-tokens | D3；失败、重试、截断分别呈现。 |
| compaction、manual-compaction | D6；自动/手动、失败及缺窗。 |
| command | D7；客户端 action 未必生成持久化行，不伪造日志。 |
| inbox | 定义层 publication 为 none；D5 使用官方队列和 user/steering 历史。 |
| unknown / 未识别扩展 | 安全有界兜底，不能静默丢失。 |
| contextPressure / contextBreakdown | token-meter 独立投影；估算、组成、轮次消耗各自标明。 |

适配层按所属插件就近维护；跨插件只用公开类型、服务及槽。不扫描完整事件窗口来渲染每一行，不深层导入官方私有组件，不重复注册官方 target 或业务服务。最终字段以[源码核对](第二优先开发计划评审/02-接口与官方源码核对.md)为准。

## 六、合并后完成定义

范围约束：调度默认只读，时间标明浏览器时区及 UTC；jobs 不伪造百分比或结果正文，无关联结果保持明确限制与未满足项；Goal 分开显示持久 phase 和实时 activation；跨 Chat/trajectory 仍必须能回答审批/提问。通用设置包含功能插件贡献的各行，不能只实现七个空壳。静态登录不提供第三方授权，W11 按已批准的延期范围验收说明入口。

- [ ] D1 工具参数、结果及子调用可读，包含关键工具摘要。
- [ ] D2 多步骤任务能看到真实进度与结束原因。
- [ ] D3 失败、重试、截断可区分，部分输出保留。
- [ ] D4 连续向上分页，前插和内容展开不抢夺阅读位置。
- [ ] D5 忙碌时排队、编辑/移除和 steer 有真实 Host 证据。
- [ ] D6 自动/手动压缩有记录，上下文估算明确来源与缺值。
- [ ] D7 命令可发现、可执行、需确认时不绕过确认。
- [ ] 未知节点有安全兜底，已实现消息、审批和提问不退化。
- [ ] W1/W4 会话、检查器及可选任务面板同屏，布局可保存并支持窄屏恢复。
- [ ] W2 长任务状态、结果通知及消息反馈可见且与真实状态一致。
- [ ] W3 工作区/文件视图可用，选择结果关联正确会话。
- [ ] W5–W9 作业、调度、目标、子代理、轨迹各自独立可用；保留原“至少一种工作台能力落地”的最低线，但不以此免除其余列明任务。
- [ ] W10 全部列明设置视图按部署能力可用；host/isLoopback 模式对可写 namespace 验真实持久写入及读回，memory 模式验持久化不可用/只读提示与零写请求，不能报告虚假保存成功。独立 Remote 和本地偏好另验，权限与秘密处理合规。
- [ ] W11 说明入口可打开、关闭并明确延期状态；没有授权按钮、凭证采集和第三方业务请求，不宣称真实集成完成。
- [ ] W12 品牌显示一致；新增面板经 qs.* 扩展槽接入，外壳不内置面板业务。
- [ ] 所有原条目在追踪表都有插件、任务、验收及状态；官方/QS 双界面、卸载重装、质量与性能检查通过。

## 七、评审与开发顺序
