# 第一优先：官方插件对应与整改验收

日期：2026-09-20。用户要求：除自有登录外，按官方插件职责逐项对应开发。包名保留已有消费者使用的名称；判断标准是实际注册、组件归属和生命周期，而不是名称是否带 ui 前缀。

## 当前对应关系

| 官方界面插件 | QS 插件 | 第一优先职责 |
|---|---|---|
| ui-layout | qs-shell | root、布局几何、顶层槽、全局样式和开发者界面切换 |
| ui-brand-official | qs-ui-brand | 独立品牌标识与名称，布局只提供槽位 |
| ui-sidebar | qs-ui-sidebar | 左导航骨架、导航空态、用户区与 qs.nav 子槽 |
| ui-workspace | qs-sessions | 会话列表、新建、切换、重命名、归档和本地置顶 |
| ui-conversation | qs-composer | Stage、欢迎区、输入、发送、停止、队列及会话子槽 |
| ui-chat | qs-transcript | 消息行、流式、转写视口、分页、锚点和阅读位置 |
| ui-approval | qs-approval | 审批呈现与官方回答动作 |
| ui-user-questions | qs-questions | 用户提问和方案审阅的呈现与回答 |
| ui-sidebar-right | qs-ui-sidebar-right | 第一优先右栏骨架、标签和空态 |
| 无：自有新增 | qs-login | 静态登录演示；不承担后端认证 |

官方源码依据为 packages/client 下各对应包的 Client 入口。特别是 ui-workspace 拥有会话浏览界面，ui-session 是复用的座席服务；ui-chat 的 ChatView 与 apply 持有转写视口和滚动位置，因此该职责保留在 qs-transcript。不能只依据旧需求表将滚动全部迁入 ui-conversation。

“一一对应”覆盖第一优先实际重写的界面职责，不宣称已经实现所有官方功能。官方 renderer、slots、locale、theme、Session、命令与模型服务仍复用，不为凑包数建立空替身。第一优先的模型标签是只读消费，不包含模型选择 UI；合并第二优先的工作区浏览和诊断内容不属于第一优先。

## 代码整改

- 新建 qs-ui-brand、qs-ui-sidebar、qs-ui-sidebar-right 独立包；各有 Client apply/inject、locale、类型声明、独立测试与可释放注册。
- 从 qs-shell 移出 SideNav 与 RightPanel 及其样式。布局通过 owner props 传递 hidden、user、selected、setSelected，右栏不创建第二份布局 store。
- Stage、WelcomePane 及样式移入 qs-composer；该包独立声明 qs.stage.body、qs.stage.transcript、qs.composer。qs-shell 不再直接注册会话内容。
- qs-transcript、qs-sessions 分别等待会话和左栏声明，不依赖包加载顺序；声明卸载后贡献跟随撤销。
- 登录、审批、提问及其业务动作保留；官方界面仍加载，切换不重建后端状态。

## 槽归属

| 声明者 | 自有子槽 | 贡献方 |
|---|---|---|
| qs-shell root | qs.gate / qs.chrome / qs.sidebar / qs.stage / qs.inspector / qs.status / qs.overlay | 登录、布局自身、左栏、会话、右栏 |
| qs-shell 的 qs.chrome entry | qs.brand.mark / qs.brand.name | qs-ui-brand |
| qs-ui-sidebar 的 qs.sidebar entry | qs.nav | qs-sessions |
| qs-composer 的 qs.stage entry | qs.stage.body / qs.stage.transcript / qs.composer | 欢迎区、qs-transcript、输入区 |
| qs-transcript 的 qs.stage.transcript entry | qs.stage.transcript.row / qs.stage.interaction | 本包基础行、审批、提问 |

父声明者必须是实际 renderSlot 宿主。不得让布局代管其他插件的子槽，或通过跨包组件值导入绕过注册。

## 验收与范围

依次核验独立加载/等待、卸载/重装、全部插件组合、构建后的 Web 装配，再验收登录、新建及既有会话发送、流式、审批提问、阅读位置和官方界面切换。缺少父插件时应等待声明而非重复声明；完整发布装配必须包含全部十包，不能把等待状态当成功页面。

实际执行结果记录在 [本次整改测试报告](../../PRD/1-AI工作台/复核测试/17-第一优先官方插件对应整改与验收.md)。本页不以“代码已调整”代替测试完成。
