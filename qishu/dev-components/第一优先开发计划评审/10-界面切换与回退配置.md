## 一、目的与范围

开发者可以从奇术工作台切换到官方界面，体验和使用当前安装版本的官方功能，再返回奇术工作台。普通启动不显示界面切换入口。该功能属于第一优先的开发者能力，不新增第八个插件包，不复制或分叉官方界面。

“最新功能”来自更新仓库、官方插件及其依赖，并完成构建与兼容验证；切换按钮不下载更新，也不承诺未来全部官方功能自动兼容。正常用户路径仍为奇术界面，只有显式配置或开发者操作选择官方界面。

## 二、启动配置

拟在 qs-shell 的配置中声明以下字段，启动时校验。下例为设计示例，不是当前可执行配置：

```yaml
config:
  defaultUi: workbench
  showOfficialUiEntry: false
```

| 字段 | 类型与默认值 | 含义 |
|---|---|---|
| defaultUi | workbench / official，默认 workbench | 本次启动的初始界面 |
| showOfficialUiEntry | boolean，默认 false | 是否启用开发者双向切换入口及动作 |

| 启动组合 | 初始界面 | 页面入口 |
|---|---|---|
| workbench + false | 奇术工作台 | 两边均不提供切换入口；普通启动默认值 |
| workbench + true | 奇术工作台 | “切换到官方界面”，切换后显示“返回奇术工作台” |
| official + true | 官方界面 | “返回奇术工作台”，返回后可再次切到官方 |
| official + false | 官方界面 | 无切换入口；供明确选择官方界面的独立启动 |

运行期所选界面仅保存在当前浏览器页面的内存 store；刷新按 defaultUi 初始化，不读取旧 localStorage、URL 或历史偏好覆盖启动配置。配置关闭时，切换动作也拒绝执行，不只是隐藏按钮。此配置是部署级入口控制，不是用户角色鉴权；同一服务若需要按用户区分权限，应另接真实身份授权，静态登录不承担此职责。

开发者通过启动时的 patch 或显式环境变量选择配置。M0 负责确认宿主配置传到客户端的官方路径、环境变量布尔解析和启动命令；无效枚举、无效布尔值必须报错，不能把字符串 false 当成 true。本文不新增未经验证的 CLI 参数。切换模式本身无需重启；改变启动配置后的加载行为在 M0 验证，验收时通过重新启动确认配置生效。

## 三、插件实现与状态所有权

qs-shell 持有配置与开发者切换控制器。控制器生命周期独立于奇术 root 的视图注册；不得为了切换界面卸载控制器或清空其 store。官方插件组合保持加载，官方界面直接使用官方 AppFrame 与扩展槽。

- 奇术模式注册其 root 及自建子槽；切到官方时释放奇术视图注册，由官方 root 候选显示。返回时重新注册奇术视图；qs.* 贡献通过 slots.inject 随声明恢复，不重复安装。
- 返回入口不能挂在将被释放的 qs.* 子槽内。M1 需验证官方可用的公共扩展槽，在官方界面贡献开发者返回按钮；不修改官方 AppFrame，不向其 DOM 强行插入按钮。入口位置与槽选择须在 M1 定稿后再做 M2 视觉实现。
- 布局、草稿、提问表单与滚动状态存放于各自插件 store，而非会被切换卸载的 React 组件。会话草稿由官方输入机持有；奇术未归属草稿由 qs-composer 持有。两种界面的独有草稿不强制相互转换，但必须保留。
- 切换不调用 cancel、answer、signOut，不清会话与队列，不卸载官方请求持有者。当前会话继续使用官方选择状态，pending 由当前显示的界面呈现并处理。
- 首次创建/交接等本地冻结操作尚未完成时，切换按钮暂禁用并显示原因；用户可先取消尚未提交的操作，再切换。已开始的模型生成不阻止切换。
- 奇术 CSS 限定在奇术根内，portal 归属对应应用根；奇术视图快捷键、事件及弹窗随视图清理，不能污染官方界面。保留必要的状态 store 不等于保留视图副作用。
- 重复点击、HMR、切换失败均需收敛到一个可用界面；出现错误时显示原因与重试，不静默宣称切换成功。M1 验证恢复路径，M4 检查重复注册和订阅泄漏。

## 四、与彻底停用的区别

开发者切换保留奇术状态和控制器，用于体验官方功能，不属于“彻底卸载”。独立启动时停用全部七个奇术插件仍保留为故障排查方式；这时没有返回按钮，需要以奇术组合重新启动。仅调整 priority 不代表副作用已清理，禁止使用与官方相同的优先级造成冲突。

[官方启动模板](../switch/01-switch-to-official.patch.yml) 使用 defaultUi: official 与 showOfficialUiEntry: false；[停用模板](../switch/02-disable-qs-rows.patch.yml) 停用当前 Web bundle 的 32 个 QS 顶层插件，并清空目录选择器动态追加的 QS 呈现。模板仅用于 Web profile，不放入所有 profile 共用的全局配置。四配置启动/刷新和两份模板的真实浏览器证据见 [187](../../PRD/1-AI工作台/复核测试/187-界面四配置与官方回退验收.md)；此证据不替代全部热卸载、发送冻结和异步竞争验收。

## 六、验收标准

1. 四种配置组合均符合第二节；非法配置报错，旧浏览器状态不能改变启动默认值或开启隐藏动作。
2. 开发者从奇术切到官方再返回，无需重启服务；同一页面始终只有一个主界面，返回入口可达，无重复注册。
3. 官方会话列表、发送、流式、停止、设置、审批与提问可用；官方版本更新后重新执行该组回归，不以奇术覆盖范围限制官方功能。
4. A 会话生成中切换，任务继续；pending 切换后仍可作答且不能重复提交；不改变登录状态或主动结束任务。
5. 普通草稿、未归属草稿、提问草稿和滚动位置切回后符合各自持久化约定；本地冻结操作期间不能跨界面重复提交。
6. 官方界面不受奇术 CSS、弹窗、快捷键污染；切换错误可恢复；多次切换与 HMR 后没有重复订阅或残留视图。
7. 关闭开发者入口的正常交付界面不增加此按钮；彻底停用七插件的启动验证与双向切换验证分别记录，不能互相替代。
