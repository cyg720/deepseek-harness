## 二、插件划分：7 个插件包（按官方模式）

第一优先按**一个组件一个插件包**落地，全部位于 `packages/qs/`，各自是完整的官方形态 client 插件（`dsh.client` + `./client` 导出 + lazy-CJS bundle）。

| # | 组件 | 包目录 | 包名 | 包内主目录 | 说明 |
|---|---|---|---|---|---|
| 1 | 外壳骨架 + 座位 | `packages/qs/qs-shell` | `@deepseek-ai/dsh-qs-shell` | `src/client/shell/`、`styles/`、`components/` | root 抢占（负优先级）、声明**全部** `qs.*` 槽、布局 store、根错误边界与故障页、**`--qs-*` 令牌与全局样式契约宿主** |
| 2 | 登录页 | `packages/qs/qs-login` | `@deepseek-ai/dsh-qs-login` | `src/client/login/` | 登录页、auth store、`AuthGateway` 接缝 |
| 3 | 会话列表与切换 | `packages/qs/qs-sessions` | `@deepseek-ai/dsh-qs-sessions` | `src/client/sessions/` | 列表/切换/新建/重命名/归档/本地置顶 |
| 4 | 输入与发送 | `packages/qs/qs-composer` | `@deepseek-ai/dsh-qs-composer` | `src/client/composer/` | 提交/停止/队列、建议 chips、附件占位 |
| 5 | 助手流式输出 | `packages/qs/qs-transcript` | `@deepseek-ai/dsh-qs-transcript` | `src/client/transcript/` | 按 kind 行渲染、keyed 订阅、历史分页、输出渲染策略 |
| 6 | 审批 | `packages/qs/qs-approval` | `@deepseek-ai/dsh-qs-approval` | `src/client/approval/` | 审批卡 + `callId` 详情解析 + 安全兜底 |
| 7 | 用户提问 | `packages/qs/qs-questions` | `@deepseek-ai/dsh-qs-questions` | `src/client/questions/` | 提问表单 + plan-review |

**与官方模式的一致性**：官方自身就是按这个粒度拆包的（`ui-layout` / `ui-conversation` / `ui-chat` / `ui-tool` / `ui-approval` / `ui-user-questions` 各自独立），所以"一节一包"是官方惯例，不是特例。

**命名规则**：目录名必须与包名后缀一致（`scripts/gen-tsconfig-paths.ts:104` 才免写别名），且目录名跨组唯一。已核实 `qs-shell` / `qs-login` / `qs-sessions` / `qs-composer` / `qs-transcript` / `qs-approval` / `qs-questions` 全部空闲；**不能**用 `shell`、`session` 等裸名（会与 `packages/shell/shell`、`packages/core/session` 的包名冲突，生成器会硬报错）。

**接线成本（必须进预算）**：每个包 3 处仓库注册 ⇒ **21 处**（`tsconfig.client.json` references、`webpack-app/cordis.patch.yml` 行、`web-app/package.json` 依赖），外加 7 份 README 三件套、7 条 Model Experience 白名单、7 次门禁接入。清单见 [09](09-自动化验收与工程接入清单.md) 第四节。

**两条硬约束（决定包间协作方式）**

1. **禁止跨包运行值导入**：bundle 纯净度门禁只放行 baseline 模块表、`dsh.client.external` 显式请求、inline-safe 白名单与生成式 `/remote`；我们的 `@deepseek-ai/dsh-qs-*` 都不在其中，而 `dsh.client.external` 按仓库规则**不是功能插件之间的依赖机制**（`packages/client/AGENTS.md` 第 77-81 行）。因此 `qs-transcript` **不能** import `qs-shell` 的组件。
2. **共享通过两条正道**：① **全局样式契约**——`qs-shell` 注入 `--qs-*` 令牌与通用类名（`.qs-btn`、`.qs-card`、`.qs-field`…），其它包只用类名与变量，不 import 任何东西；② **槽协作**——`qs-shell` 声明顶层 `qs.*` 槽，`qs-transcript` 声明自身行与交互子槽，其余 6 个包用 `ctx.slots.inject(key, () => ctx.slots.register(...))` 等待声明后贡献（官方同款做法）。类型共享走 `import type`（被擦除，不受门禁限制）。

**加载顺序**：由槽声明等待保证——`qs-shell` 未声明前，其余包的 `slots.inject` 不会安装，无需额外排序；`dsh.client.inject` 只用于预检展示与 HMR 差分。

**家族文档（已更新）**：`packages/qs/workbensh/README.md` 已删除（A 方案知识现全部沉淀在本评审包内），`packages/qs/styles/` 已移到 `qishu/styles/`。因此 **M0 要为 `qs-shell` 新写一份 `README.md`**（含门禁要求的 Model Experience 与 Known Limitations 章节，内容可从本评审包的 [00](00-评审总纲.md) / [01](01-组件方案与待办分解.md) 提炼），并按三件套补齐 `README.zh.md` + `README.i18n.yaml`；空的 `packages/qs/workbensh/` 目录在 M0 一并删除。

| 1 | 遮蔽与回退 | root 注册在**负**优先级遮蔽官方；**回退 = 卸载/停用插件行**（首选），或把 priority 改为**正数**让官方胜出。**禁止**写"改回 0"（同优先级抛错）。回退必须实测：卸载后自建 `qs.*` 槽与注册完整清理、官方恢复 |

## 五、完成定义（DoD，v2）

- [ ] 未登录只渲染登录页；登录成功自动进入工作台；登出回到登录页且状态干净
- [ ] **默认奇术路径**下官方 UI 不出现；开发者显式切换按 [10](10-界面切换与回退配置.md) 验收；**异常路径**下显示自建故障面（根错误边界），不出现"悄悄变回官方 UI"的未定义行为
- [ ] 回退实测通过：停用插件行后官方 UI 恢复，且自建槽与注册无残留

- [ ] 助手流式可见；历史与实时一致；pending 与错误可辨；无会话时有欢迎区与可用输入

- [ ] 键盘可达、焦点可见且弹窗关闭后恢复、移动抽屉可关、流式输出有播报、200% 缩放可用、reduced-motion 生效

## 八、执行方式

1. 按 M0→M4 推进；**M1 结束必须回写 [05](05-接口核对表.md) 的实测结论**，未打勾不得进入 M2。
2. 每个组件开工前从 [01](01-组件方案与待办分解.md) 复制其待办清单，逐条勾选。
3. 每个里程碑产出验收记录（截图/GIF/命令输出）到本目录 `验收/`。
4. 代码与本目录文档冲突时：**先改文档再改代码**；接口类冲突以 [05](05-接口核对表.md) 实测为准。

## 开发者官方界面入口（第一优先）

保留官方界面供开发者体验和使用当前安装版本的官方功能。qs-shell 新增 defaultUi 与 showOfficialUiEntry，普通启动默认奇术且关闭入口；开发者显式开启后可在两种界面间往返切换，无需重启服务。此项纳入 M0 配置、M1 接线、M2 视觉、M3/M4 组合验收，不增加插件包。配置、返回入口与状态保持以 [10-界面切换与回退配置](10-界面切换与回退配置.md) 为准；“正常路径官方不出现”仅指默认奇术路径。该功能待实现，不代表已有 CLI 参数。
