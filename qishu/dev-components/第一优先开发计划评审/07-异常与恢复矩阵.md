# 异常与恢复矩阵（第一优先）

> 2026-09-20 插件结构修订：第一优先按九个官方界面插件逐项对应，另加自有登录，共十包。现行职责、槽归属及验收见 [12-官方插件对应与整改验收](12-官方插件对应与整改验收.md)；本文件中旧七包结构表述不再作为实施依据。

> 每个场景定义：触发 → 期望行为 → 界面 → 数据 → 验证方式。**连接类、取消反馈类、跨会话隔离类不得当作打磨项后置。**

### 兜底分层（T1a/T1b/T2/T3–T6：不再笼统承诺"异常都是自建故障页"）

| 层 | 场景 | 谁接住 | 界面结果 | 依据 |
|---|---|---|---|---|
| **T1a** | **子插件**（qs-transcript / qs-sessions / … 的 single・keyed・list 条目）渲染抛错 | **框架 entry 级错误边界**（先于我们的根边界） | 该 entry **退位（abdicate）**，其余部分继续渲染；界面表现为"这一块缺失"。**每个包自己要在组件内兜底**（局部错误 + 空态），不能指望根边界 | `ui-renderer/src/client/scoped-slots.tsx:745-756` |
| **T1b** | **chain 条目**（`qs.stage.interaction` 的审批/提问卡）渲染抛错 | 框架 entry 级错误边界，**但 chain 不退位**（`abdicate: spec.kind !== 'chain'`） | 该位置显示框架错误面，**不会换下一个候选**；**请求仍 pending** ⇒ 卡片必须自带错误提示 + 重试 | 同上 `:750-756` |
| **T2** | **root occupant 内部**（qs-shell 的组件树）渲染抛错 | 我们自己的**根错误边界** → 自建故障页 | 显示自建故障页（重试渲染 / 重新加载 / 诊断信息），**不回落官方 UI** | 本包设计 + 原型 `system-fault-*.png` |
| **T3 注册失败** | `qs-shell` 的 `apply` 抛错（注册前） | 无 | **官方接管**：root 取下一个候选（官方 `AppFrame` 仍在）——这一条**有源码保证** | `scoped-slots.tsx:903` |
| **T4 依赖等待** | 我们的某个包 `inject` 的**必需**服务缺失 | 无 | **不是官方接管，也不是报错**：该 fiber **一直 PENDING**，对应部分永不出现。⇒ 真正必需的官方服务（如 composer 的 `conversation`）仍声明依赖，由真实组合保证齐全并检查等待状态；只有可选服务（如 shell 的 `qsAuth`）使用可选读取与显式故障呈现，不得为避免 PENDING 隐藏必需依赖 | Cordis fiber 语义 |
| **T5 模块组合失败** | 我们的 `client.js` **缺失/畸形**（构建未产出、声明错误） | `client-modules` 激活期**同步抛错**，fiber FAILED | **没有 UI 兜底**：组合在激活期就失败，**根本不会进入 root 选举**。⇒ 靠**发布前检查**（构建产物存在性 + `pnpm run build` 校验）与**配置回滚**，不能承诺 React 回退 | `client/modules/src/index.ts:478-483` |
| **T6 浏览器加载失败** | 脚本 404 / 网络失败 | 浏览器 | 页面可能白屏（`__DSH_BOOT__` 有 row 但脚本取不到）⇒ 同样靠发布前检查与缓存/回滚策略 | `client-modules` bundle 路由 404 语义 |

- **T2 的可测性**：注入一次渲染异常（测试用），断言出现自建故障页且**焦点落在标题**；原型 `system-states-report.json` 的 "root fault focus, retry preserves draft…" 即此行为的验收基准。
- **T1 的验收**：故意让 qs-transcript 抛错，断言**其余面板仍可用**、缺失块有局部提示。
- **T3 的验收**：在注册 root 前注入 apply 错误，断言官方候选显示且诊断可定位；不以此证明 T4。
- **T4 的验收**：移除一项真正必需的官方服务，断言对应 fiber 等待且组合诊断可定位缺失依赖，验收判失败；恢复服务后再次验证。正常交付组合不允许因缺依赖持续 PENDING，不能将其记为成功回退。
- **登录缺包验收**：独立移除、延迟提供和恢复 qs-login，缺失期间显示组件加载故障；恢复后重新解析 auth，未登录时不得挂载工作台。
| 39 | 回退（**三种操作分别验收**，见 [10](10-界面切换与回退配置.md) 第四节） | ① 不注册自建 root（`defaultUi: official`）：官方显示、依赖槽的贡献等待；② 停用全部 7 行：自建副作用全部释放、官方正常；③ priority 改正数：官方显示但**自建注册仍在**——**不得**据此断言"无残留" | 官方 UI | 仅 ② 会清理状态 | 手工 + 断言 |
| 40 | 登出 | 卸载工作台树、清登录态与本地布局缓存（用户数据如置顶可保留） | 登录页 | 不残留会话订阅 | 手工 + 单测 |
| 41 | 200% 缩放 / 字体回退 | 不溢出、控件可达 | — | — | 手工（[08](08-视觉差异清单与新增交互稿.md) 环境） |

## 组合状态补充

| 触发 | 呈现与恢复 | 必须验证 |
|---|---|---|
| 首次发送等待中断线/模型不可用 | 解冻并保留输入；不继续客户端投递 | 恢复后仅一次发送，已创建则复用会话 |
| 未提交草稿遇断线/模型阻塞 | 保留草稿，显示原因，禁止客户端投递 | 恢复后显式重发；无整队暂停/继续入口；Host 已接收队列独立运行 |
| A 已本地交接，输入 B 后 A 失败 | 显示失败，B 不变；恢复由官方输入机负责 | 延迟、乱序失败与跨会话归属 |
| 引导点击后当前轮恰好结束 | 显示不可引导，保持任务 | 不伪装成排序成功 |
| 归档时运行中/队列非空/pending | 提示先处理；不归档、不停止、不代答 | 确认前重新检查；远端竞争按快照收敛 |
| A 上滚阅读、切 B、A 后台生成 | B 使用自身位置，返回 A 保持阅读位置 | 主动回到最新才恢复跟随；历史前插不跳动 |

## 开发者界面切换异常

| 场景 | 处理 | 验证 |
|---|---|---|
| 首次本地创建/交接未完成 | 暂禁用切换，提示等待或取消尚未提交的操作 | 不跨界面重复投递 |
| 返回入口注册失败/切换失败 | 显示故障原因并允许恢复；不能标记成功或留下空白主区 | M1 注入失败，M4 回归 |
| 生成中或 pending 时切换 | 保持任务与请求；由当前界面呈现 | 官方/奇术往返且只答复一次 |
| 配置关闭但有旧浏览器状态 | 按启动配置显示；无入口，切换动作拒绝 | 默认值与四种组合测试 |

上述切换属于 [10](10-界面切换与回退配置.md) 的开发者能力，不等同于停用七插件排查。
