## 一、必须知道的硬约束：per-file 100% 覆盖率

实测 `vitest.config.ts`：

- `:206` → `coverage.include = ['packages/*/*/src/**/*.{ts,tsx}']`
- `:355-362` → `thresholds: { perFile: true, statements: 100, branches: 100, functions: 100, lines: 100 }`

**含义**：`packages/qs/qs-*/src/**`（7 个包）的**每一个文件**都必须 100% 覆盖，否则 `pnpm run test:coverage` 失败。

> **定位（v2 修订）**：这是**成本项/预算项**，不是最大的产品风险——真正的风险是"覆盖率满了，但启动、会话绑定与协议接线仍不通"（评审已确认 6 处接口误读）。因此先用 M1 纵向链路实测接口，再补齐覆盖率；也**不**通过新增 vitest exclusion 压缩工期。

三种合规手段（按推荐顺序）：

| 手段 | 说明 | 要求 |
|---|---|---|
| ① 结构性达成 | 把逻辑抽成纯函数 / store / adapter，组件只做渲染；用官方 `@deepseek-ai/dsh-client-test-runtime` 以真实 props 驱动组件 | 首选；M0 就建立骨架 |
| ② 带理由的忽略 | 真正不可达的防御分支用 `/* v8 ignore -- <理由> */` | 理由必须真实，禁止裸 ignore |
| ③ vitest exclusion | 在 `vitest.config.ts` 的 exclude 列表加条目 | 最后手段；改的是仓库公共配置，需在评审时单独批准 |

## 二、测试分层

| 层 | 对象 | 工具 | 覆盖要求 |
|---|---|---|---|
| L1 纯逻辑 | `auth-store`、`layout-store`、`pins-store`、`adapter.ts`、校验函数、IME 守卫 | vitest（node 环境） | 分支全覆盖（含存储不可用、未知 kind、空输入等边界） |
| L2 组件 | 每个 `.tsx`：三态渲染、键盘、aria、断点分支 | vitest + jsdom（文件首行 `// @vitest-environment jsdom`）+ `client-test-runtime` | 每个组件的默认/空/加载/错误/禁用路径 |
| L3 集成（**v2 升级**） | 在真实 **Loader 组合**内装载本包：root 遮蔽生效、`qs.*` 槽与 `session-maybe`/严格 `session` 座位均可渲染、`useChat`/`inputActions`/pending 可达、发送→流式→停止、审批与提问答复 | 组合测试（`docs/testing.md:31` 要求覆盖 shipping Loader composition）+ `pnpm dsh web` | 每个里程碑一次，不止"每条一次" |
| L4 手工验收 | 1:1 视觉、断点、主题、动效、touch | 浏览器 + 原型并排比对 | 按下节矩阵 |

> 注意：`pnpm run test:gui` 只跑 `packages/client` 与 `packages/host` 两个路径，**不包含** `packages/qs/*`。7 个包的测试需显式跑（`vitest run packages/qs`），或在评审时决定是否把 `packages/qs` 纳入 `test:gui` 脚本。

## 组合状态回归与当前原型依据

- [ ] M1：发送 A 后输入 B，A 延迟失败不覆盖 B；连续发送的乱序失败不重复创建会话。
- [ ] M1：create/open 等待期间发生断线、模型不可用或导航变化，不错误投递。
- [ ] M1：Host 创建成功但响应丢失，恢复/重试使用同一预分配 sessionId，只存在一个会话；恢复创建不自动重复 submit。
- [ ] M1：创建明确失败、结果未知、挂接失败分别呈现；取消/登出/导航变化后迟到结果不抢选中项、不发送。
- [ ] M1：真实审批和提问分别通过 chain owner props 命中；keyed hooks 从 entry.inject 提供，单节点增量可见。
- [ ] M0/M1：登录缺包、延迟加载与恢复加载；注册抛错与必需服务缺失分别注入，不将依赖等待认定为成功回退。
- [ ] M3：连接、模型或 pending 阻塞时保留未提交草稿，恢复后由用户重新发送；不显示整队暂停/继续，Host 已接收队列按官方语义执行。
- [ ] M3：逐条引导成功进入当前轮；当前轮结束竞争失败保留任务。
- [ ] M3：运行中、队列非空、pending 时归档受限，空闲时可归档。
- [ ] M3：A/B 独立滚动与跟随意图，结合后台生成、历史前插验证。

会话原型入口为“交互演示 → 发送与恢复”。专项脚本为 `../../PRD/1-AI工作台/prototype/validation/conversation-state.cjs`。原型使用本地计时器及模拟状态，不证明 DSH 接口接通。截图状态和本轮检查结果以 [组合状态修订记录](../../PRD/1-AI工作台/prototype/validation/2026-09-17-组合状态修订.md) 为准；旧截图中的“优先处理”和归档自动停止不作为当前行为基准。
