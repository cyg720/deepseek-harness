## 三、跨组件验收场景（必须在 M4 全绿）

- [ ] 空环境启动 → 静态登录 → 创建并选择会话 → 首次发送
- [ ] 创建响应丢失后按同一预分配 sessionId 恢复，仅一个会话；取消或导航后迟到结果不 open/submit
- [ ] 真实 pending 经 chain owner props 命中，审批/提问可见；keyed hooks 在 entry.inject 注册
- [ ] 登录缺包/延迟/恢复；必需服务缺失与注册抛错分别验证
- [ ] 阻塞时保留草稿，无整队暂停/继续入口；逐项操作与 Host 队列一致
- [ ] 流式生成中停止 → 当前轮结束且队列行为与文案一致
- [ ] A 会话发送后切到 B，再回 A：草稿与输出不串、滚动位置正确
- [ ] 审批：允许 / 拒绝 / 请求撤销 / 快速重复点击
- [ ] 提问：多问题、自由回答、多选 + 自由回答、仅批准的 plan-review
- [ ] 回答中切换会话、HMR 重载后回到同一请求仍可作答
- [ ] 历史分页与实时增量同时发生
- [ ] 断网、重连、Host 重启
- [ ] root 故障注入 → 自建故障页（不回落官方 UI）
- [ ] 分开验证运行期切换、优先级改选、停用七插件：前者保留状态，改优先级保留注册，仅彻底停用要求释放全部自建注册与副作用
- [ ] 真实构建产物加载（CSS / SVG / locale）

## 四、工程接入清单（M0 逐条勾）

### 4.1 每个包通用的 12 项（× 7 个包）

对 `packages/qs/{qs-shell,qs-login,qs-sessions,qs-composer,qs-transcript,qs-approval,qs-questions}` 各做一遍：

- [ ] **package.json**：`publishConfig.access: public`（当前仓库按目录判定发布家族，禁止 private: true；仅声明包格式，不执行发布）；`version` 与根一致；`type: module`；`main`/`types`；`exports` 含 `"."`、`"./client"`、`"./src/*"`、`"./package.json"`；`dsh.client: { platform: 'web' }`（可带 `inject` 信息边）；`files` 覆盖 `lib/client.js`、`lib/index.js`、`lib/types/**/*.d.ts` 与资源；`scripts.bundle`/`watch`
- [ ] **tsconfig.json**：`extends ../../../tsconfig.base.client.json`（**v3 修正**：`packages/qs/qs-shell/` 到仓库根是三级；对齐 `packages/client/ui-theme/tsconfig.json:2` 的写法）；`references` 指向所用官方包
- [ ] **tsdown.config.ts**：`clientBundle('@deepseek-ai/dsh-<包名>', ['lib/types/index.js'])`
- [ ] **别名**：目录名与包名后缀一致（`qs-*`）；`pnpm run gen-tsconfig-paths`
- [ ] **客户端聚合**：`tsconfig.client.json` 加 `references` 条目
- [ ] **Web 组合行**：`packages/bundle/web-app/cordis.patch.yml` 加 `dsh.client` 行（建议集中放在 `qs-shell` 之后，便于阅读）
- [ ] **Web 依赖**：`packages/bundle/web-app/package.json` 加依赖（保证 profile 可解析）
- [ ] **文档三件套**：`README.md` + `README.zh.md` + `README.i18n.yaml`，并用 `pnpm run verify-translation-pairing --write packages/qs/<pkg>/README.md` 记录 hash
- [ ] **Model Experience 白名单**：`scripts/verify-package-readme-model-experience.ts` 的 `SENTENCE_MODEL_EXPERIENCE` 增一行（否则短句形式被门禁拒绝）
- [ ] **依赖分类**：`@deepseek-ai/cordis` 同时进 `peerDependencies` 与 `devDependencies`；其余 `dsh-*` 开发依赖；浏览器第三方库进 `devDependencies`
- [ ] **资源发布**：`files` 覆盖全部相对导入的资源；`publint` 通过
- [ ] **仅类型跨包**：不出现对其它 `@deepseek-ai/dsh-qs-*` 的运行值导入（构建纯净度门禁会拦）

### 4.4 测试归属与扫描配置（v3 新增，避免"命令绿但测试没跑"）

| 测试类型 | 放哪里 | 由哪条命令执行 | 依据 |
|---|---|---|---|
| L1 纯逻辑 / L2 组件 / L3 组合 | `packages/qs/<pkg>/tests/**/*.spec.{ts,tsx}` | 默认 lane（`vitest run packages/qs` 或全量 `pnpm test`） | `vitest.config.ts:121-122`（`testIncludes` 覆盖 `packages/*/*/tests/**`） |
| **L4 浏览器/可视快照** | **必须放 `apps/web/tests/**`**（`*.e2e.ts` / `*.snapshot.ts`） | `pnpm run test:web` | `vitest.web.config.ts:26-30` **只扫** `apps/web/tests/**` 与一个 inspector e2e；**放在 `packages/qs/**` 的浏览器用例不会被执行** |

| L6 真实构建产物 | 手工核对清单（构包 + 手验） | `pnpm --filter … bundle` + 手验 | [03](03-测试与验收方案.md) |

**若要把浏览器场景放进 `packages/qs/**`**：需要改仓库配置 `vitest.web.config.ts` 的 `include`（新增 glob），属仓库改动，**须在评审中单独批准**；默认方案是"浏览器场景放 `apps/web/tests/`"。

**L3 组合测试的三个输入必须写明**（否则"组合测试"是空话）：
1. **加载的 overlay**：新 UI 组合用 `packages/bundle/web-app/cordis.patch.yml` 的实际 QS 插件行（当前 32 个顶层插件，目录选择呈现另由动态分支追加）；对照（官方）组合用 `../switch/02-disable-qs-rows.patch.yml`。
2. **Session 回放来源**：`pnpm run test:snapshot` 所依赖的录制父/子会话（`snapshots/**`），以及 `DSH_SNAPSHOT=replay` 的可燃/只读语义（`docs/testing.md:14-15`）。
3. **断言面**：槽注册与座位、`qs.*` 单一贡献者（或 chain 接管）、登录切换、发送→流式→停止、审批与提问答复。
