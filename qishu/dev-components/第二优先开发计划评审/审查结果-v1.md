## 4. 已确认问题及整改要求

优先级：P1 为阻止当前相关能力验收的问题；P2 为需修复的业务/工程质量缺陷。未发现足以定为 P0 的已验证事故。以下不以扫描器猜测代替缺陷证据。

### R01 / P1：整体交付范围明显不足

位置：[里程碑与插件任务](03-插件划分与组件待办.md)、[正式右栏](../../../packages/qs/qs-ui-sidebar-right/src/client/RightPanel.tsx) 第 46 行、[转写行注册](../../../packages/qs/qs-transcript/src/client/rows.tsx) 第 151–162 行。

事实：右栏只渲染空态；D6/D7 及多数 W 组插件未创建；M0 消费者仍不齐。影响是用户无法在 QS 中使用计划承诺的第二优先主体功能。验收必须按第 3 节逐项补齐，或取得明确范围缩减；不能以 M1 小范围交付充当二合一整体交付。

### R02 / P1：过程内容被隐藏，但展开按钮可能永久禁用

位置：[process-row.tsx](../../../packages/qs/qs-transcript/src/client/process-row.tsx) 第 63–74 行；[process-fold.ts](../../../packages/qs/qs-transcript/src/client/process-fold.ts) 第 93–99 行。

隐藏条件仅看轮次结束、answerAnchorSeq 和序号范围；展开条件却只看 tools/messages/agents 计数。一次模型先重试、随后直接成功回答的轮次可以没有工具和中间回答计数，但有外部 model-retry/context 过程记录。这些行被折叠隐藏，按钮却 disabled。独立探针以 hasExternalProcess=true、三项计数=0 重现该矛盾。

官方 [ChatNodeSeat](../../../packages/client/ui-chat/src/client/chat/ChatNodeSeat.tsx) 使用 hasExternalProcess/inlineReasoning，并检查 historyIncomplete；QS 也未保留历史窗口完整性保护，窗口只有答案而过程控制行未加载时存在缺少展开入口的额外风险。后者尚未单独跑分页浏览器复现，不与已确认前者混淆。

修复：统一隐藏与可展开判据，使用官方过程呈现事实；历史不完整时不要隐藏不可恢复内容。回归需覆盖“零工具零中间消息但有重试”“不完整历史”“展开后切会话及卸载重装”。

### R03 / P1：命令中的敏感值直接出现在折叠摘要

位置：[tool-view-model.ts](../../../packages/qs/qs-ui-tool/src/client/tool-view-model.ts) 第 74–88、108–116 行；[tool-tree.tsx](../../../packages/qs/qs-ui-tool/src/client/tool-tree.tsx) 第 64、98–101 行。

summaryOf 对 bash/pwsh 优先取 description，否则直接返回完整 command；不存在敏感字段处理。合成命令中的 `Authorization: Bearer review-only-placeholder` 在未展开工具详情时即被摘要显示。已用负向断言复现，未读取或记录真实密钥。

这违反计划“摘要不自动展示完整 Authorization/凭证”的要求；会增加共享屏幕、截图及录制时的意外泄露。此证据不是后端越权读取或已发生外泄。修复应优先采用安全描述，限制自动展示高风险命令片段，对已知敏感字段遮罩；原文显式展开，且不承诺自由文本能完美脱敏。不得修改真实工具参数或模型日志来掩盖 UI 问题。

### R04 / P2：每个收尾行订阅整张 Chat 表并重复扫描

位置：[process-row.tsx](../../../packages/qs/qs-transcript/src/client/process-row.tsx) 第 103–104 行；[turn-view-model.ts](../../../packages/qs/qs-transcript/src/client/turn-view-model.ts) 第 136–142 行。

每个 TailRow 为 failed 和 truncated 各调用一次 useChat selector，再对 nodes.values() 执行 some。没有相应诊断的正常会话每次扫描遍历全部 N 个节点，T 个收尾行需 2×T×N 次节点种类读取。选择结果稳定只能减少组件重绘，不能免除 selector 内扫描。

独立生产函数工作量探针固定 T=N/10：100 节点为 2,000 次，1,000 节点为 200,000 次，10,000 节点为 20,000,000 次。该测试验证访问次数，不是浏览器延迟基准，不能据此声称卡顿多少毫秒。官方 nodes.values() 有数组缓存，但没有消除每行 some 的全量遍历。

修复方向：按 turn 建立一次性的诊断索引/可订阅投影，或消费已有位置索引；避免每行全表订阅。需用同一长会话固定输入比较 CPU、selector 次数、首屏、流式及展开响应，再决定是否需要虚拟列表。

### R05 / P2：todo_write 失败详情被专属卡吞掉

位置：[todo.tsx](../../../packages/qs/qs-ui-tool/src/client/toolviews/todo.tsx) 第 48–62、74–91 行。

todoCardModel 只解析请求参数，不检查结算 isError、content、error；只要 todos 参数合法，就渲染计划清单。负向 DOM 用例提供失败结果与明确错误正文，页面却仅出现请求中的 completed 内容，错误正文不见。外层仍有失败状态点，不能把该问题夸大为整张卡显示成功；真实缺陷是用户无法获知失败原因，且参数计划缺少“未应用”的区分。

官方 [todo-row.tsx](../../../packages/client/ui-tool/src/client/tool/toolviews/todo-row.tsx) 保留 toolRowModel 的 output/errorSummary。QS 应在失败/中断时回落通用错误详情或显式展示错误，区分请求计划和生效状态。成功、失败、中断及带合法参数的拒绝均需断言实际 DOM。

### R06 / P2：历史问答无法严格配对时硬编码“回答 0”

位置：[ask-question.tsx](../../../packages/qs/qs-ui-tool/src/client/toolviews/ask-question.tsx) 第 137–141 行。

两条问题与一条非空答案无法一一配对时，模型直接返回 answered:0；合法 JSON 但部分/扩展历史结果因此被误报为无人回答。该探针属于历史载荷降级验证，不声称正常 Host 总会产生不完整结果。官方 [ask-question-row.tsx](../../../packages/client/ui-tool/src/client/tool/toolviews/ask-question-row.tsx) 会独立计算可解析回答数量，并把配对失败和数量分开。

应统计可验证的非空回答，或明确显示“无法完整解析”并保留原文；不能把未知伪造成 0。补齐缺条目、重复 id、未知 id、空答及无法解析场景。

### R07 / P2：图片获取 URL 成功后，资源失败/解码失败没有提示

位置：[read-image.tsx](../../../packages/qs/qs-ui-tool/src/client/toolviews/read-image.tsx) 第 83–97 行。

ImageBody 只处理 loadImage promise 的 reject；img 没有 onError。URL 成功返回后若图片损坏、实际请求失败或解码失败，用户只能看到坏图。审查 DOM 用例对 img 派发 error 后，未出现预期 alert；原有测试只覆盖装载函数拒绝及迟到结果，不覆盖资源元素失败。

增加 img 失败状态、可见说明及必要重试策略，保持会话切换/资源更换后状态重置；保留既有授权装载能力，不自行拼文件 URL。

### R08 / P2：最终答案步骤被当作当前进度来源

位置：[turn-view-model.ts](../../../packages/qs/qs-transcript/src/client/turn-view-model.ts) 第 35–46 行。

step 取 data.answerStep。官方 [turn-process.ts](../../../packages/client/ui-chat/src/client/conversation-nodes/turn-process.ts) 在没有最终回答时显式给 answerStep:null；它不是活动步骤编号。因此长任务运行时可以只看到轮次及累计活动数，看不到计划 D2 要求的“当前步骤推进”。当前测试还把 answerStep:null→step:null 固定为正确行为，没有验证多步骤运行中的真实坐标。

应消费现有当前 Turn/Step 投影，明确区分当前步骤和最终答案步骤；不要用工具计数推算。用至少三步真实记录驱动测试，验证运行、等待重试、结算三阶段。

### R09 / P2：国际化门禁失败，存在协议常量误识别

命令 `node --import tsx scripts/verify-client-ui-i18n.ts` 退出 1，报告 7 项：process-row.tsx:115 的 `ms`；tool-view-model.ts:88 的 description、command、path、pattern、url、query。

后六项是协议参数键，不应翻译，不能将扫描结果机械当作六条用户文案缺陷。需要用门禁支持的精确约定/窄例外消除误识别，并处理单位表达。禁止整体关闭国际化检查或把 wire key 翻译成中文。常规 Oxlint 通过不覆盖此独立检查。

### R10 / P1：新增 M1 缺少足够的正式装配、回放与原型验收证据

工具 lifecycle 测试使用 SlotTestRuntime 人工声明槽并挂载，能证明登记和 disposer，却不能单独证明 Loader/真实 Host/实际工具行为。已有 apps/web/tests/qs 回归覆盖第一优先交互，transcript-disclosures 仅粗粒度检查过程存在；没有针对八类工具卡、模型重试链、过程失败与完成折叠、新图片失败等新增验收断言。当前 snapshots/web 与既有 QS 浏览器测试没有对应新增内容差异。

### R11 / P2：大载荷的展开预算与懒计算仍未证明
