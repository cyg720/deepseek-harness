## 安全检查

1. 工具参数、结果、错误、命令输出均为不可信文本；用现有安全 Markdown/文本渲染，不添加任意 HTML 注入或 eval。
2. 未展开的敏感参数不预先大规模格式化；摘要不自动展示完整环境变量、Authorization、凭证等。字段遮罩不能宣称能识别所有自由文本秘密；诊断原文查看须显式展开，新增导出不在本期。
3. 本地媒体和文件入口沿用官方同源权限通道；不拼接任意浏览器 file URL，不绕过 Host 策略。
4. “重试模型”与“再次执行工具”不可混用；任何命令的权限、确认和审批仍由官方服务负责。
5. UI 隐藏和静态登录不是后端授权；切回官方也不改变 Host 信任边界。

## 性能验证方案

先测量再决定优化，禁止把虚拟列表作为本期无条件前置。建议样本：100/1,000/10,000 个已加载节点；少量超长文本；多层工具子调用；连续流式增量；多次前插与 20 次切换。通过生产投影或合法合成记录构建，不把伪造 React 数据当唯一性能证据。

固定机器、浏览器、viewport、构建模式及 fixture；预热后至少 5 次用于探索中位数，保留原始样本。需要 p95 门槛时至少采集 100 个可比较样本并报告离散性，未达到样本量只记观察值、不承诺稳定性。观察首批可读时间、输入到菜单延迟、流式 render 次数、主线程长任务、DOM 数与订阅/内存释放。用相同负载对比第一优先基线及第二优先结果。

建议先以稳定场景中位数退化不超过 20% 作为调查触发线，具体预算在 M0 测量后确定，不能把未经测量的数字写成已满足的 SLO。单行更新若造成全表订阅或 JSON 全量序列化，应先修订阅/懒展开；只有实际 DOM 数成为瓶颈才设计虚拟化，且重验焦点、复制、锚点与搜索。

- D/W 对应的全部 QS 包分别有真实 Cordis 入口、明确注入依赖、独立注册和测试；只有组件目录或空入口不计为插件完成。

- 分别卸载和重装 qs-ui-tool、qs-ui-commands、qs-ui-input-trigger，确认视图消失/恢复、注册数不累加，官方服务实例不被销毁。卸载基础 qs-transcript/qs-composer 时，依赖者按注入生命周期撤销，不残留不可用入口。
- qs-transcript/qs-composer 增强前后的相同夹具验证草稿、发送、审批/提问、分页和主动跟随；断言每次操作的实际 Host 请求次数，防止新旧入口同时生效。
- 构建产物证明 D/W 所有新增及扩展包均被发现和装配，源码测试通过不能替代模块发现验收。官方入口与 QS 入口使用各自视图、共享唯一业务服务；关闭全部 QS 后官方仍正常工作。
