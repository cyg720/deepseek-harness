# 插件划分与组件待办

> 二合一范围：D1–D7 转写诊断与 W1–W12 工作台差异化统一纳入第二优先。官方→QS 映射以 03 为准；底层服务与库保持唯一，不能按页面合并插件。

本文保留原任务划分，“新增”描述相对第一优先的增量，不代表当前尚未创建。2026-09-24源码已包含34个QS包，各包生命周期及八个工具子插件的本轮证据见[报告190](../../PRD/1-AI工作台/复核测试/190-插件及工具子插件生命周期复核.md)；存在源码或测试不等于所有业务、原型和真实浏览器场景已验收。新增包放 `packages/qs/`，官方呈现对应包命名为 `@deepseek-ai/dsh-qs-ui-*`，自有集成包单独标识，沿用官方 Host/Client 分面、Cordis apply/inject、声明合并、locale 与 disposer 规范。用户要求按官方插件职责一一对应，不以现有七包限制数量。

## 官方与二开插件对应表

D 组涉及五个官方界面包，使用两个已有对应包并新增三个独立 QS 包；W 组的逐项映射和任务在下文追加。一个节点种类不是一个插件；官方包内的子插件也不能退化为巨型条件组件。

| 官方插件及依据 | 对应 QS 独立包 | 重写职责 | 继续复用 |
|---|---|---|---|
| [ui-chat](../../../packages/client/ui-chat/src/client/apply.ts) | qs-transcript | 转写视口、历史滚动分页、行分派、助手/消息/过程/收尾、错误重试、压缩和命令结果呈现 | 官方 chat 定义、折叠投影、节点与 location 类型；不重复注册 chat target |
| [ui-conversation](../../../packages/client/ui-conversation/src/client/index.ts) | qs-composer | 会话内容骨架、输入和队列视图、上下文压力呈现、输入扩展槽 | SessionInput、Session 控制器、token-meter 投影及既有发送协议 |
| [ui-tool](../../../packages/client/ui-tool/src/client/apply.ts) | qs-ui-tool | tool-call 树及工具专属展示子插件 | 官方 ToolCallBlock 与结果元数据、执行/权限服务 |
| [ui-commands](../../../packages/client/ui-commands/src/client/index.ts) | qs-ui-commands | 命令选项弹层、确认与焦点接线 | commandUi 目录、贡献和 popup controller；不重复注册命令源 |
| [ui-input-trigger](../../../packages/client/ui-input-trigger/src/client/index.ts) | qs-ui-input-trigger | 候选菜单、输入触发桥与键盘仲裁接线 | inputTriggers controller、检测和选择事务 |

此处“替换”指 QS 页面使用对应 QS 插件重写的界面。官方页面及其服务仍加载，支撑开发者切回官方；不全局停用官方包，也不创建同名服务争夺提供者。直接实例化另一份 CommandUiRuntime/InputTriggerService 不属于本方案。若将来要求彻底不加载官方 UI 包，需另审服务与视图分离，不能宣称本阶段已经完成。

## 官方子插件逐项对应

ui-tool/apply.ts 通过 `ctx.plugin()` 挂载八个内置视图：bashToolviewSample、readToolview、readImageToolview、fileMutationToolview、searchToolview、webToolview、todoToolview、askQuestionToolview。qs-ui-tool 在 `src/client/toolviews/` 下逐项提供 QS 对应子插件，用独立 apply/注册及 disposer 接入 QS 工具子槽。它们属于同一个 npm 包，不虚增八个包；重写视图时保留官方注册器的匹配语义。

读写/编辑/命令优先完整实现；图片、搜索、Web、todo、ask-question 同样必须有对应插件与可读摘要或明确限制，不能用空 apply 冒充完成。ask-question 工具历史卡不拥有待回答交互，仍由 qs-questions 回答。官方新增子插件时更新对应表及回归清单；工作台面板由 W 组独立对应插件实现，不并入工具卡包。

ui-chat 的节点定义与渲染注册按源码区分；M0 枚举 apply 引用的注册单元及 key，为每个本阶段渲染注册单元建立 QS 对应，不把定义文件数当插件数。ui-commands/input-trigger 内的服务插件保留唯一官方实例，QS 只重写其呈现与接入。
