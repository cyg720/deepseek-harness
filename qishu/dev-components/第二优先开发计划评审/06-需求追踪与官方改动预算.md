## 最小改动官方代码的预算

**本轮评审不修改任何官方源码。** 未来实现在本次第一优先整改的对应关系上按 D/W 完整对应表新增或扩展 QS 界面包，目标不新增官方业务代码修改；这是一项设计目标，不是已经证明的零改动承诺。

| 文件/类别 | 是否预计需要 | 触发条件与用途 |
|---|---|---|
| `packages/qs/**` | 是，自有文件 | 转写、面板、命令桥、设置、已确认集成、样式、字典、测试及包 README；不进入官方改动清单。 |
| `apps/web/tests/qs/**` | 是，自有文件 | 第二优先真实浏览器验收与 owner-local 期望；不因位于 apps 下就登记为官方文件。 |
| `apps/web/tsconfig.json` / `tsconfig.host.json` | 可能 | 新增含 Host 的浏览器测试若不被当前编译配置覆盖，须分别排除 Client、纳入 Host。 |
| `pnpm-lock.yaml` | 可能 | 新增对应包及 manifest 中已核实的服务依赖时按包管理器更新；不能仅加 TS 类型导入而遗漏装配注入依赖。 |
| slot catalog / module graph / config catalog 及配对记录 | 可能 | 新槽、声明或源码引用改变后按官方生成器更新；不手写生成产物。 |
| Web bundle / resolver manifest / 根 tsconfig paths 与 references | 预计需要核对并调整 | 所有新增包必须进入实际模块及编译装配；优先修改 QS 自有配置。官方文件确需改变时登记路径、必要性和原因，不再按“不新增包”预算。 |
| 官方 ui-conversation、ui-input-trigger、ui-commands 的公开面 | 待 M0 证实 | 仅当现有公开 controller/state/作用域事件无法保持输入语义时提出；先记录缺口、受影响消费者、测试，禁止把包内 ComposerKeyboard 直接公开给 QS。 |
| agent-loop、Session 格式、后端命令策略 | 不计划修改 | D/W 官方能力以表现层及已有服务接入为主；W11 的 Host 接入另审，不因此改 agent-loop 或 Session 格式。 |

任何实际改动官方原文件，都同步[官方源码改动清单](../../官方源码改动记录清单/总览-官方源码改动列表.md)，按现有用户规则就地添加中文用途说明；严格 JSON/生成文件按登记例外处理。记录中必须区分候选与已发生改动。

## 工程约束

- 文件新增在官方目录下时放 `qs/` 层；已有 `packages/qs/` 不重复嵌套。
- ESM、相对导入 `.ts`、跨包用包名；UI 文案走所属 locale 字典。
- Slot 注册、controller 订阅、观察器及定时器都有卸载清理；不得通过隐藏 UI 保留重复全局键盘监听。
- host/client 编译分面、源码测试与 lib 构建分开；不在 src 旁生成 `.js/.d.ts/.map`。
- 公共 API 必要变更更新全部消费者、README 和 JSDoc；非机械变更同步 QS Agent Note，先检查既有记录是否已经覆盖。
- 覆盖率欠账和失败项原样列出；不为这批计划开门禁白名单。
