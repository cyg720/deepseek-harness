第一优先为九个官方对应插件加自有登录。根据[覆盖率修复验收](../../PRD/1-AI工作台/复核测试/19-QS剩余九个覆盖率修复验收.md)，47 个测试文件、263 条测试通过，89 个 QS 源文件四项覆盖率均为 100%；Host/Client 类型检查、contracts-ready lint 与 34 项 doc-sync 通过。原“50/53 个未覆盖文件”欠账已关闭，不能继续当作当前基线。上述为已提交修复的覆盖率证据；本轮相关源码回归见报告 30，不等同重新执行全量覆盖率。

真实 Host keyless 浏览器及构建在报告17有通过证据；报告19未重跑浏览器或证明最新全量构建。报告18的全量类型检查 OOM、两项环境门禁、真实源码 HMR 和在线 API 分别按 10/E01–E08 记录，不能统称从未通过或全部通过。第一优先已有分页、锚点、阅读位置、队列和基础转写，按增量扩展，不重建 SessionInput。

| 决策 | 合并方案 |

| 官方改动 | 业务源码零新增修改是目标；装配及公开 API 缺口逐文件评审、登记，不承诺未经验证的零改动。 |

## 工期与编码前确认

旧 22–37 人日只覆盖 D 组，不适用于合并后的总范围。暂按 D 组 22–37、W1–W4/W12 18–30、W5–W9 15–25、W10 10–18、全阶段额外回归 8–12 人日估算，合计 73–122 人日；已有组件复用程度须在 M0 校正。这是工作量范围，不是日历承诺；W11 的系统数量/授权开发、未明确的调度写操作、官方 API 扩展与完整编辑器不包含在估算内，不能据此承诺整个阶段完成日期。

估算可信度：以上是未校准的早期区间，不作为排期/承诺基准；10–18 对应 W10 设置，W11 单列“待目标系统确认，无估算”。没有第一优先实际工时记录，不能用源码行数反推人日，也不将包含服务/测试的官方文件量全算重写成本。M0 按“包 × 子注册/组件”重估：分别登记现有复用、新视图（含完整轨迹、tab 标题及文档分派）、公开接入改造、装配、测试/覆盖率、视觉验收、风险和工时依据；数据不齐留未估算。整体验收与逐包测试分列防止重复累计，必要官方改动成本不继续隐藏在粗区间内。

计划默认与外部输入分开：10 的 P-B01–P-B09 明确只读调度、部署矩阵、布局 owner、通知范围、设置字段、引用限制和时区；W11 目标系统/真实授权与视觉签收仍需外部输入。具体公开 API、生效时点和持久化粒度待 M0 验证。包数量以实际呈现插件注册清单为准，不能由页面数或七个设置导航名称决定。
