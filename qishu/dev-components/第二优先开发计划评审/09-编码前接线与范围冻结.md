# 编码前接线与范围冻结

## 使用范围与放行条件

本文件补足[组件计划](03-插件划分与组件待办.md)的技术前置。具体接口方案、槽名、目录装配和预览 ID 规则以 [12](12-M0接口定型与验证.md)为定型依据；下文描述各工作包需要解决的问题。未新增生产接口。源码事实以本地提交 `906b6de1e2` 及当前工作树为依据；实施前记录实际提交和相关未提交差异。负责人按任务角色分配，不虚构已经承接的人员。

每项验证须交付源码定位、公开接口和注入依赖、正常与失败载荷、真实 Loader 装配测试及结果、影响的官方文件清单。候选接口未编译和运行前不能记为可用；需要新增 UI 插件运行值导出时遵循官方审批规则，不以深层导入替代。只有依赖项全部通过的组件可以进入正式编码，其他组件保留阻塞；文档完善不等于技术阻塞解除。

## G01：右栏复用必须包含座位生命周期

[官方控制器](../../../packages/client/ui-sidebar-right/src/client/service.ts)要求已挂载的 binding；未挂载时导航抛错。会话 store 的 adoption 回调在[官方入口](../../../packages/client/ui-sidebar-right/src/client/index.ts)内部创建，不是任意 QS 组件可取得的公共工厂。

首选验证官方服务能否通过最小公共的座位接入方式承载 QS 呈现：明确谁创建和接纳 store、谁 bind/unbind、谁将布局提交同步到 Tab domain、谁释放资源。官方与 QS 同时加载时同一会话不允许两份竞争的业务布局状态。QS 外层列宽与内部资源标签状态分别列 owner；若共享状态无法成立，先提出最小官方接缝及消费者迁移方案，不复制 controller 或依赖隐藏官方 DOM 维持服务。

必须验证直接以 QS 启动且未先打开官方页面的冷路径，以及官方→QS→官方、切会话、关闭最后一项、插件卸载、失效资源。记录资源 pin/释放与订阅次数，不能只确认点击没有抛错。

呈现选择已定：QS 自有 tab 正文/标题/文档子槽，重写文件和文档呈现，复用官方资源类型、读取、Tab domain 与唯一状态服务。官方 sidebar.right.pane.tab、sidebar.right.pane.tab.title、sidebar.right.tab.document 属官方父 entry，QS 不直接接管它们；若选择原样复用官方 tab 视图才需要其合法宿主，那是另一方案，不纳入本计划。M0 验证 tabInfo、地址、标题、pin 与生命周期如何通过公开接入供 QS 使用，不能把“复用数据”写成“现有 tab 自动显示”。

## G02：反馈与命令的呈现落点

[官方反馈入口](../../../packages/client/ui-message-feedback/src/client/index.ts)私有持有每会话 FeedbackSurface，`/feedback` action 打开同一实例；[命令服务](../../../packages/client/ui-commands/src/client/service.ts)拒绝同名重复 decoration。读取两个 feedback Remote 不足以复用官方弹层状态。

M0 优先设计由官方单一状态 owner 提供注入服务或回调，使 QS 按钮和命令打开同一个会话反馈界面。服务名和注入方法按 12/G02 定型，实际新增接口仍待生产实现，不运行值导入私有类，不覆盖或重复注册 `/feedback`。若确需调整官方源码，先列最小变更、官方消费者和回退测试。

命令清单逐条记录名称、贡献者、执行类型、参数/确认、可见条件、状态 owner、QS 呈现落点和依赖阶段。重点核对裸 `/feedback`、带参反馈、`/goal`、模型/权限命令以及仍保留加载的其他贡献。没有可见落点的命令必须标出限制和阻塞；不得无提示打开被遮蔽的官方弹层。目录可用与整个命令功能可用分别验收。

popup 未决、风险确认、claim 交接或本地提交期间禁止界面切换和重复提交。复用 [qsShell.setLocalFreeze](../../../packages/qs/qs-shell/src/client/ui-mode.ts)，但它是单一 reason，不是多持有者锁：由 qs-composer 的同一编排 owner 汇总输入与命令状态后唯一写入；命令插件只贡献自己的状态，不能各自 finally 清空全局冻结。关闭/失败/卸载只释放自身原因，其他未决操作仍冻结；普通未 claim 的候选浏览不冻结，Host 后台运行不永久冻结。T15/T16/T34 增加两个并发原因依次解除及迟到回包断言。

## G04：六类文档预览对应与安全范围

[官方预览入口](../../../packages/client/ui-sidebar-documentpreview/src/client/index.ts)注册 Text、Markdown、HTML、Image、PDF、Code 六类实现。它们分别列入 qs-ui-sidebar-documentpreview 内部贡献清单，不新增六个 npm 包。六类都需有对应呈现或经确认的可见限制，不默认删除某类。

| 类型 | 开发前必须定型的输入及行为 |
|---|---|
| Text | 编码、分页、截断、行范围与取消；缺页不伪装全文。 |
| Markdown | 安全渲染、链接/相对资源策略；文档内容不能获得宿主执行能力。 |
| HTML | 对齐官方隔离 iframe 策略；脚本、相对静态资源、导航/外链、字节和资源数量限制逐项核对，禁止同源父页面直接注入。 |
| Image | MIME/格式支持、授权读取、失效、大小限制及 URL 生命周期。 |
| PDF | 二进制读取、查看器能力、失败/大文件限制、切换和释放。 |
| Code | 语言识别、文本降级、长行/大文件、行号定位；不执行代码。 |

安全基准参考[HTML iframe](../../../packages/client/ui-sidebar-documentpreview/src/client/html/HtmlBody.tsx)及[资源打包](../../../packages/client/ui-sidebar-documentpreview/src/client/html/pack.ts)。逐类记录读取通道、分块/全文选择、取消、错误、限额来源和清理行为；不凭 UI 摘要声称已经实施 Host 限流。

## G05：斜杠与引用的范围隔离

官方 [ui-reference](../../../packages/client/ui-reference/src/client/index.ts)注册 `@` 来源，[触发控制器](../../../packages/client/ui-input-trigger/src/client/controller.ts)不只服务 `/`。本期仍不实现完整 @ 编辑，不得为 QS 停用共享来源或修改全局检测，影响官方功能。

计划选择新增最小公开接入能力：按当前输入消费者限制可参与的 trigger/source，QS 仅开放 `/`，普通 @ 保留文本；官方消费者保持原行为。当前 registerSource/sessionOf、InputTriggerSource 与 plain/claimed/frozen guard 没有“仅 /”能力，G05 是新增接口设计和验证任务，不再验证一个不存在的现有过滤开关。接口按 12/G05 的 acquireConsumer 租约设计，须覆盖检测、候选、键盘仲裁、pick、程序化打开与异步失效，卸载恢复官方默认；不能只隐藏 @ 菜单、先 track 再 dismiss 或全局注销来源。不新建第二份业务服务/controller，不临时改写草稿修订号。该方案有必要官方改动预算，尚未实施。

官方界面携带已有结构化引用的草稿切入 QS 时，必须先证明可无损展示、提交和切回；无法保持语义时保留原草稿并提供可见限制，禁止自动扁平化、丢引用或误发。限制方案纳入产品确认和原型，不把“禁止全部界面切换”作为默认解决办法。

## G06：扩展行分派与卸载

[当前分派](../../../packages/qs/qs-transcript/src/client/adapter.ts)将固定名单外的 kind 归为 unknown；新增 keyed 注册不会自动改变它。[Goal 定义](../../../packages/client/ui-goal/src/client/goal-command-input.ts)发布的是 `command-input`，需单列。

拟议采用注册可用性驱动的分派：保留真实 kind，当相应 QS 行贡献可用时选择该 key，否则使用 unknown；通过 apply 注入受支持的注册快照和订阅，不让组件访问 ctx。M0 核对 slots 公开查询及类型声明能否实现，不能猜测方法名。匹配注册的增删必须触发重算，插件卸载后既有行可降级、重装后恢复。不得要求每新增面板插件都修改转写内部固定白名单。

上述是对现有 RowKey 联合、NATIVE_ROW_KINDS、组件映射与入口注册循环的一次显式改造，不能只加一个 keyed 注册就声称生效。M0 须列这四处变更和跨包扩展类型策略；后续呈现插件仍要声明合法 key/负载，不意味着任意未知类型零声明可用。command-input 的专属呈现归 W7/C15，M1–M3 在对应插件未挂载时走 unknown 是阶段性预期；不能据此把全阶段命令验收标为完成。

## G07：通知的权威来源与去重

2026-09-23 实施：作业通知已接入官方共享来源及奇术 toast，控制基线在 ready 前同步投影，容量由外壳配置约束。阶段证据和未完成的真实断线、跨 Host 组合见 [167 记录](../../PRD/1-AI工作台/复核测试/167-任务通知接线与基线发布验收.md)，不据此放行完整第二优先。

qsToast 只展示提示，不是任务事件源。M0 对每类通知列出实际 Session/jobs 来源、完成/失败的稳定身份、连接代次及首次读取语义。拟议只对本客户端已观察到的终态转换主动 toast，初始快照和重连全量恢复不重放历史通知；切回通过权威任务结果显示状态。

通知范围及已读策略采用 [10](10-全量问题处置与核查清单.md)的 P-B05 计划默认；技术任务列跨工作区/Host 隔离、可配置去重保留上限和退出清理。不以扫描所有历史记录推导新的通知，不自动把第一条终态快照当新完成。消息反馈、任务状态、系统连接提示分别拥有数据，不能借 toast 建第二份任务状态机。

## G08：分页失败必须有公开可观察结果

[官方 loadOlder](../../../packages/api/session-controller/src/client/sessions/session.ts)在内部处理失败；[QS 接入](../../../packages/qs/qs-transcript/src/client/index.ts)又将返回值 void 化。只有 hasMore/loadingOlder 不足以区分失败与成功，外围 try/catch 和固定超时均不能补足权威错误。

选择 12/G08 的 historyLoad 公共状态方案，QS 只订阅，不复制分页执行器；loadOlder/loadThrough 保留 Promise<void>。字段和状态转换已列于 12，仍是拟新增 API。loadThrough 同类路径也要检查，不仅修一个按钮。

成功但无新增节点、hasMore=false、取消/失效代次、真实失败分别定义；有更多但无进展时停止自动拉取并提供说明/手动重试，避免 observer 空转。失败保留已加载历史与锚点，暂停自动重试，用户重试才恢复；切 Session/连接代次后旧结果不设置新视图错误。记录官方公开类型与所有消费者的候选改动，再登记必要 diff。T41 必须通过可控真实拒绝路径，不能只测试 mock 主动 throw。

## G09：待回答交互独立于可切换转写视图

当前 [Transcript](../../../packages/qs/qs-transcript/src/client/Transcript.tsx)渲染 qs.stage.interaction；Chat 卸载时交互可能一起消失。拟将该槽声明与唯一渲染点迁移到 qs-composer Stage 下的稳定 session 座位，位于 Chat/trajectory 内容切换之外。转写不保留第二个 render；qs-approval/qs-questions 继续各自插件贡献，不把审批业务并入 Composer。

迁移同时更新 SlotMap 声明归属、inject 依赖、pending owner 参数和第一优先对应文档；无当前会话不挂 session 座位。第一优先现状与拟议迁移分开描述。维持官方 pending 数据源、请求身份及既有回答动作，跨视图保存未提交答案；会话切换后迟到回包不得影响新卡。T42 覆盖轨迹中审批/提问、失败重试、卸载/重装、别处已答与浏览器焦点；状态条只定位唯一回答区。

## G10：目录双入口与原生流程

[官方 owner 参数](../../../packages/client/ui-workspace/src/client/contract/slots.ts)在 conversation.hero.workspace.directoryFlow 与 sidebar.workspaces.directoryFlow 两处使用 open/busy/onPicked/onCancel/onError。[浏览式](../../../packages/client/ui-directory-picker-browse/src/client/index.ts)与[原生](../../../packages/client/ui-directory-picker-native/src/client/index.ts)都承担此流程，原生无 DOM 不能据此遗漏。

拟由 qs-sessions 分别拥有欢迎区/侧栏对应 qs.* 流程槽，沿用 root scope 与官方 owner 参数语义；确切名称见 12/G03，正式代码须声明 SlotMap。两个选择器按官方对应职责独立接入，复用 uiWorkspace 与官方平台选择策略，不同时启动两个 picker、不重复注册宿主 provider。新建目录与选中确认区分权限与副作用。

默认 Web 静态 YAML 没有两个 picker 客户端行不等于未加载：[directory-picker-auto](../../../packages/host/directory-picker-auto/src/index.ts)按 [resolve](../../../packages/host/directory-picker-auto/src/resolve.ts)选择 backend，再通过 loader.create 同时装载 BACKEND_PACKAGES 与 SURFACE_PACKAGES。M0 必须检查运行时 Loader 树、动态行和两个面，而不只检索静态 roster；browse 不仅用于测试，native 也不只在桌面版。QS 两个对应呈现候选保留，按实际能力挂载，不重复 Host provider。

同一时刻只激活一个发起流程，每次 open 有实例身份；取消、异常和成功至多结算一次。关闭/新入口/切工作区后旧结果不回写新实例。通过能力判定选择本机浏览式、远端 Host 浏览式、原生；具体分支证据及不可用提示按 P-B02/T43，禁止把浏览器本机路径当远端路径。

## G11：作业结果与 Goal 激活

[SessionJob](../../../packages/api/session-controller/src/types.ts)仅给出 id/kind/label/status/detail?/startedAt/finishedAt；status 包含 running/stopping/completed/killed/failed。不增加假的百分比、通用 result 或取消接口。结果定位必须证明 JobId 与已有持久结果的正式关联；若没有关联，展示“未提供结果正文”与返回所属会话入口，并将精确定位保留为未满足项，不用字符串猜测身份。C10 的“切回查看结果”也按此条件验收，不能以作业 completed 等同结果可读。

[Goal 类型](../../../packages/goal/goal/src/types.ts)持久 phase 为 active/paused/blocked/complete，activation 为进程本地 armed/disarmed，GoalProjection 不包含 activation。复用官方 Goal 实时来源及重连代次处理，不能自行从日志造 activation。roundsStarted/maxGoalRounds 是轮数，非任务完成百分比。编辑/pause/resume/clear 继续使用官方 ref 与权限条件，active+disarmed 不等同正在自动继续。T44/T45 验证缺字段、断线、无目标、blocked 原因、激活加载和冲突。
