## 范围和证据等级

本文件定型第二优先的新增接入方案，源码基线为 `906b6de1e2` 与本地工作树。按继续推进 M0 的要求，公共接口和部分 QS 接线已经进入实际源码；真实登录未接入，第二优先业务插件并未全部安装。当前实现与验证以[实际接线验收](../../PRD/1-AI工作台/复核测试/31-M0实际接线验收.md)为准；[前轮记录](../../PRD/1-AI工作台/复核测试/30-M0与原型补全验收.md)仅证明当时的既有能力、隔离探针和原型。

## G01：共享右栏接入

现有 [ui-sidebar-right](../../../packages/client/ui-sidebar-right/src/client/index.ts)在 apply 内创建唯一 controller、store handle、adoption 和 tabInfoFactory。公开的 bind 不负责创建 store，QS 不能仅调用 bind 或复制 store 工厂。选择在此 owner 中新增 `sidebarRightPresentation` 注入服务，不新增运行值工厂导出。

已实装服务提供：`store`（与官方座位相同的 session StoreDecl handle）；`seat(sessionId)`（返回现有 SidebarRightInjected）；`tab`（复用官方两个正文/标题 children 的声明注入对象）。类型通过原包 `/client` 类型导出，Context 服务声明由原包维护。官方座位与 QS 座位都使用此服务，不向 QS 暴露私有 adopted Map。QS 使用同一个 handle，保证会话实例复用和原 adoption 回调执行；资源 retention 继续由唯一 TabDomain 管理。

`seat` 只组装注入值，bind/unbind 仍由实际可见座位的挂载/更新/卸载负责。界面切换先释放旧绑定再挂新绑定；拒绝用 display:none 保留两份活跃绑定。业务标签保持 session scope，QS 列宽/移动端展开仅是 qs-shell 展示偏好。零标签保留官方 guide 约束，不能用空布局绕开现有导航假设。

正式改动候选：ui-sidebar-right 的 `src/client/index.ts`、`shell/SidebarRight.tsx`（若需剥离官方视图参数）、对应 contract/types、QS 右栏入口和双方测试。不改导航算法、资源寻址或 pin 实现。冷启动、官方→QS→官方、A→B→A、旧 unbind 晚于新 bind、关闭最后标签、卸载重装都要检查 store 身份、订阅及 pin 计数。

## G02：反馈服务与命令落点

选择在[反馈 owner](../../../packages/client/ui-message-feedback/src/client/index.ts)提供 `messageFeedbackPresentation`，其 `actions(sessionId)` 返回已有 MessageFeedbackInjected，`dialog(sessionId)` 返回已有 FeedbackDialogInjected。两方法都调用 owner 内同一个 surfaceFor；官方按钮、QS 按钮、官方弹层、QS 弹层和 `/feedback` 共享 FeedbackSurface，不再次 decorate，不导出私有类。

## G04：预览身份与安全

选择复用官方 documentPreviews 元数据，QS 不调用 register 注册六个副本。六个 QS 正文贡献使用官方相同 definition.id，但只注册到 qs.sidebar.document.body，因此不会触碰官方正文槽。官方包新增只读 `documentPreviewIds` 常量导出（text/markdown/html/image/pdf/code），由原六个定义共用；QS 禁止 deep import 私有 PLAIN_BODY_ID 或手抄包名字符串。

候选选择为官方注册快照按文件后缀排序后，与 QS 当前有效正文 key 的交集；有效 key 用 slots.entriesOfSlot 派生，订阅 slots.subscribe，不能把每次新数组当 useSyncExternalStore 的稳定 snapshot。变更时缓存交集，保持同版本引用稳定。用户选择 rendererId 不再可用时降到可用 Text；Text 也缺失则显示“查看器未加载”，不空白、不往共享数据回写 rendererId。呈现选择按 session/资源/界面分别存储，不能改变官方当前 viewer。

第三方只有官方正文贡献时，QS 显示不可用说明，不静默声称支持；补 QS 对应注册后自动进入候选。官方卸载元数据时对应 QS 候选同步失效；每个异步读取按资源身份、viewer、连接代次核对，关闭取消读取并释放对象 URL。验证同 ID 重复注册拒绝、两个槽相同 key 共存、外部 priority 排序、卸载选择兜底和官方候选不受 QS 影响。

Text/Code/Markdown 采用 text-pages，Image/PDF/HTML 按原定义 loading 取值，不用扩展名猜模式。HTML 复用原隔离与资源打包策略；正式六类验收还需恶意内容、资源上限、字节/MIME、取消和 URL 清理证据。原型 PDF 为页面示意，不能算真实 PDF 引擎通过。

## G05：同一控制器的消费者策略

已在 InputTriggerServiceContract 新增 `acquireConsumer(actx, policy): { controller, release }`，policy 为只读允许 trigger/source 集合，缺 source 限制表示该 trigger 的所有来源；官方调用允许全部，QS 仅允许 `/`。此接口已实装，sessionOf 保留仅作控制器解析，不再允许输入组件绕过消费者策略驱动 track/pick。

每 Session 仍只有一个 controller。可见输入挂载获得独占租约；第二个活跃输入租约报接线错误，不能后写覆盖前者。release 比较 token，旧 release 不清除新租约；切换时 abort fetch、清 hit/menu/header/launcher 并递增 consumerEpoch，不改用户草稿修订号。检测、track、toggleSource、pick、键盘仲裁、lexicon 与异步候选提交统一检查有效 policy 和 epoch；任何禁用来源不参与 matchSpace/matchEnter。全局 source roster 保留。

改动候选：ui-input-trigger 的 client/contract.ts、service.ts、controller.ts、公开类型入口，官方 ui-conversation 输入接线、QS composer 及相应测试。需要可控 Promise 验证旧 @ 返回晚于 QS /、旧 pick 晚于界面切换、source 卸载、无租约和双租约。已有 service 测试不能证明新租约实现已存在。

结构化草稿选择可见限制方案：QS 保留原共享草稿与引用身份，显示概要并禁编辑/发送；普通 @ 文本仍可编辑。官方入口关闭时给配置说明，不自动开启入口。禁止把引用扁平化或在切换时清空。

## G06–G09：行分派、通知、分页和待回答区

G06 使用 slots.entries 的稳定快照和 slots.subscribe，在注入层派生可用 key；遇到 abdicated entry 时用 entriesOfSlot 的有效贡献判定。一次性移除 RowKey 固定封闭联合、NATIVE_ROW_KINDS 判断、组件映射限制及入口固定循环，改为可合并类型表和真实 kind 分派。unknown 始终作为 owner 兜底，command-input 在 Goal 呈现未加载前保留降级。插件变更重算，不在组件里访问 ctx。

G07 只通知已经打开/订阅且有权限的会话中本客户端观察到的非终态→终态；key 为 Host/工作区/Session/JobId/终态，连接代次用于拒绝迟到回包。初始/重连首批仅基线，不 toast；内存已读按通知 key 保存，退出清除。配置 maxEntries 与 ttlMs 在实现前提供 schema，默认值需实测，不在插件常量里隐藏部署选择。无正式结果关联时只返回会话并显示限制。

G08 选择向 SessionSnapshot 增加只读 `historyLoad` 判别联合，保留 loadOlder/loadThrough 的 Promise<void>，避免全调用者改返回协议。状态为 idle/loading/succeeded/failed/cancelled；活动及终态包含 requestId、connectionEpoch、kind=older/through，可选 targetSeq；succeeded 带 progressed 与 hasMore，failed 只提供失败判别，由 UI 映射本地化通用提示，不携带原始异常或凭证。错误由当前内部 catch 写入并发布，finally 只收尾所属请求；重复调用不启动第二任务。连接重置取消旧请求并清显示错误，旧 catch 不覆盖新代次。QS 订阅状态，progressed=false 或 failed 时暂停自动拉取并提供手动重试。

候选源码为 api/session-controller 的 client SessionSnapshot 类型、client/sessions/session.ts、历史加载测试及 QS transcript 数据注入。扫描所有 loadOlder/loadThrough/snapshot 构造消费者，更新 fixture；不复制执行器。T41 必须通过实际 Remote 拒绝路径；拟议状态联合的探针不能代替该用例。

G09 将 qs.stage.interaction 的 children 声明与唯一 render 从 Transcript 迁至 Stage 的固定 session 宿主；保持原槽 kind/owner 和 approval/questions 注册协议。结构为标题→视图标签→可切换阅读区→pending→composer。Chat 视图卸载不销毁 pending，Session 切换才替换该作用域。本轮原型验证布局、失败留答案和切视图；正式测试继续覆盖真实 RequestId、别处已答、迟到响应、焦点恢复。

## G10：目录装配定型

选择扩展官方 directory-picker-auto 的配置，新增可选 `additionalClientSurfaces: { native: string[]; browse: string[] }`，默认两组空数组。auto 仍只运行一次官方 resolve，依次加载选中的 Host、原官方 Client、附加 Client；任一步失败逆序回滚，卸载等待全部 Fiber 结束。配置读取使用项目既有 Config/schema 规范；不得在 QS 重写平台探测。

QS profile 层填写 native 对应 qs-ui-directory-picker-native，browse 对应 qs-ui-directory-picker-browse；两个 resolver manifest 都声明候选包依赖。每次只加载匹配分支，QS 两包只贡献自己的 qs.* 流程槽，不重复 Host provider。原生/浏览式固定部署关闭 auto 并显式组成同一分支的 Host+官方 Client+QS Client 三行，避免自动和固定两套同时挂载。

动态名称的依赖检查同步扩展 verify-cordis-config，验证附加项真实可解析，重复项/与原 surface 同名配置拒绝。候选官方改动：directory-picker-auto/src/index.ts 与 Config、包 README/测试、QS profile 所在装配文件及 resolver manifest、必要静态校验脚本；正式改动才进入官方源码改动记录，二开文件不进入该清单。

目录流程的实例身份由 qs-sessions 持有，两入口互斥，取消/错误/成功至多结算一次；旧系统弹窗回调只能结束旧实例。native 等待可无正文但有取消/错误提示；browse 的 path/list/create 复用 uiWorkspace。真实 Loader 测试须覆盖 native、browse、附加加载失败、固定组合及卸载，不能仅断言 YAML 字符串存在。

## G11、性能和正式放行

Jobs 保留官方五态和真实字段，无通用 result 的提示是已选限制，不表示“精确结果定位”已完成。Goal 持久 phase 与实时 activation 分开，rounds 是轮数而非完成比例，更新必须带官方 ref。相应原型与字段见[11](11-原型状态与字段规格.md)。

Jobs 使用已实现的 `ISessions.control.state` 读取 loading/ready/reconnecting/failed/disposed 和已接收基线计数，使用 `control.retry()` 请求终止失败恢复。会话目录 phase 和 jobsBySession 缺键仍不能替代这一状态。唯一 SessionControlOwner 继续使用官方 createSessionControlStream，载体中断自动重连；终止失败合并重试并等待旧实例静默后再替换，卸载和旧实例回调不能启动或污染替代流。retry 的 Promise 只证明替代流已启动，就绪以真实基线为准；处置失败拒绝且不打开竞争流。
