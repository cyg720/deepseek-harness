# 遮蔽对照表：官方行 ↔ 你必须自建的组件

> **用途**：`packages/qs/qs-shell` 以 `root` 遮蔽（**负** `priority`）方式让官方 UI 全部不渲染。本表记录**每一行官方 client 插件原本提供什么、遮蔽后你必须自己实现什么、对应哪一优先级**，既是开发清单，也是"欠债核对表"。
>
> **相关文档**：[第一优先](01-第一优先-最小可用工作台.md) · [第二优先](02-第二优先-转写与诊断.md) · [第三优先](03-第三优先-工作台差异化.md) · [第一优先开发计划评审](第一优先开发计划评审/00-评审总纲.md)
>
> 文档约定：本文件非 `README.md`、不带 `.i18n.yaml`，不在 DSH 双语语料库与 doc-sync 门禁范围内。

## 一、铁律：遮蔽 ≠ 停用

| | 遮蔽（本方案采用） | 停用（`disabled: true`，本方案禁止） |
|---|---|---|
| 做法 | 注册 `root` 且 priority 更小，官方 `AppFrame` 不再渲染 | 在 patch 层把官方行 `disabled: true` |
| 官方界面 | 完全不出现（它的槽没人渲染） | 完全不出现 |
| 数据面 | **完整存活**：`ctx.uiConversation`、chat target、会话 hook、审批/提问管道都在 | **一起消失**，必须自己重写事件折叠与流式装配 |
| 启动风险 | 无 | 高：槽声明随声明者消失，仍在加载的注册者会在**加载时抛错** |
| 升级维护 | 官方增删行都不影响你 | 必须持续维护停产清单 |

**具体依赖链（为什么停用会炸）**：`ui-layout` 声明了 `main` 槽 → `ui-conversation` 注册进 `main` 并声明 `main.conversation` → `ui-chat` 注册进 `main.conversation` 的子槽。停掉其中任何一个声明者，后面仍在加载的注册者立刻失败。

## 五、核对方法（每加一个组件都走一遍）

1. **打开官方 roster**：`packages/bundle/web-app/cordis.patch.yml` 中的 `dsh.client` 行（当前 45 行）就是"官方原本提供什么"的完整清单。
2. **判断一行是数据面还是视觉面**：在其源码里查 `provide`、`events.register`、`views.register`、`registerPendingInteraction`、`remote.$on` —— 命中即为数据面（必须保留加载）；只有 `slots.register` 的是视觉面（遮蔽即可）。
3. **确认你的实现在对应位置**：表 B 的每一行都必须能在你的组件清单里找到归属；找不到就说明有官方能力被遮蔽后无人接管（例如"审批没人呈现"这种会阻塞 agent 的缺口）。
4. **回退验证（已修订）**：**停用/卸载插件行**（首选），或把 `root` 注册的 `priority` 改为**正数**（不同优先级共存、最低者渲染 ⇒ 官方胜出）。**禁止改回 `0`**：官方默认即 0，同优先级注册会直接抛错（`ui-slots/src/index.ts:839-841`）。回退后必须确认自建 `qs.*` 槽与注册已完整清理、官方 UI 恢复且无残留冲突。
