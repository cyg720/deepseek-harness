## 待核验项目配置

| 配置项 | 用户提供的基线 | 核验/决策要求 |
|---|---|---|
| 持久化 | JPA，PostgreSQL 15+ | 核验具体依赖和部署版本，不自动升级 |
| 表名/列名 | tb_<module>，lower_snake_case | 核验现有命名；与 Java/API 显式映射 |
| 主键 | BIGSERIAL + GenerationType.IDENTITY | 保持已批准约定；不因偏好自动替换 |
| 短字符串 | VARCHAR(64/128) | 具体长度由业务语义决定，不机械二选一 |
| 描述/备注 | TEXT | 明确输入长度及内容类型，不能默认无限接收 |

## 错误码：用户给定，待仓库核验

以下是业务 code，不是 HTTP 状态码。不得因为数值相同而混淆。

| code | 名称 | 用户给定含义 |
|---|---|---|
| 200 | SUCCESS | 操作成功 |
| 400 | PARAM_ERROR | 参数校验失败 |
| 401 | PARAM_MISSING | 缺少必要参数 |
| 1001 | UNAUTHORIZED | 未登录/登录过期 |
| 1002 | FORBIDDEN | 无权限 |
| 2001 | NOT_FOUND | 资源不存在 |
| 3001 | DUPLICATE_KEY | 唯一性冲突 |
| 3002 | DATA_IN_USE | 被引用不能删除 |
| 5000 | BUSINESS_ERROR | 业务处理失败 |
| 9999 | INTERNAL_ERROR | 内部错误 |

并发版本冲突等新增场景不得直接编造一个“项目已有”的错误码。
可标注“拟新增，码值待分配”，并关联 Q 编号。
无权访问与资源不存在是否统一对外表示，应依项目的信息披露策略决定。

## URL 基线

| 动作 | 用户给定方法和路径 |
|---|---|
| 分页 | GET /api/<module>/page |
| 详情 | GET /api/<module>/{id} |
| 新增 | POST /api/<module> |
| 编辑 | PUT /api/<module> |
| 删除 | DELETE /api/<module>/{id} |

不要为遵循另一种 URL 风格而静默破坏现有客户端。
需要调整时，分别列当前契约、目标契约、调用方影响与兼容方案。

## 不再作为无条件默认的旧规则

- 所有模块同时编辑都后写覆盖。
- 所有时间字段均默认当前时间。
- 所有接口必须具有同一种异常测试组合。
- 幂等意味着响应内容、状态码或请求日志完全相同。
- CREATE TABLE IF NOT EXISTS 等价于迁移成功或已有结构正确。
- 只检查登录态即可代表完成权限控制。
- 必须生成全部 CRUD 接口、建新表或绘制状态机。

上述事项须按语义和风险作显式决定，而不是默认使用相反的另一套规则。
