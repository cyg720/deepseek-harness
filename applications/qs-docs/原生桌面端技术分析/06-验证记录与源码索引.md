## 3. 本机环境处理

为越过开发项目准备问题，本次把两个目标不存在的依赖 junction 备份到 `node_modules/.desktop-analysis-stale-links-20260913`。原位置在 `node_modules/.pnpm/node_modules/@deepseek-ai` 下，名称分别为 `node-addon-landlock-run-linux-arm64`、`node-addon-landlock-run-linux-x64`。

这项操作只处理已确认失效的本地依赖链接，没有修改桌面源代码、包清单和锁文件。源码构建产生了常规 `lib`、Web `dist`、构建记录和 `.desktop-build` 中间文件；未签名打包失败时，准备脚本会清理失败的生产 runtime 目录，因此不应把残留 tarball 或 Node 可执行文件当成成品。

本次没有安装系统 Python/MSVC、没有安装测试安装器、没有对外上传。用于验证的 Electron 下载子进程已停止，未留下需要用户关闭的桌面窗口。

## 4. 报告自身验证

报告的 Markdown 正文处于用户指定的 `applications/qs-docs` 下，采用中文分篇，不是新增 npm 包 README 或上游双语参考页。现有双语检查的源码范围没有将这些分篇报告列为强制翻译对。

报告自身检查覆盖：七篇 Markdown 是否存在、链接与手工锚点是否有效、所引用源码是否存在、代码块围栏是否完整、文件末尾是否只有一个换行、HTML 是否包含全部章节，以及离线阅读页面的宽窄视口布局。结果文件保存在 `validation` 下。

全仓库快速文档检查的两类失败是：已有 Agent Note 引用已不存在的 PRD v3.0 文件；已有 `applications/PRD/2-授权中心/README.md` 缺少双语配对。没有为消除这些无关错误修改用户的 PRD 工作区。

全仓库 `doc-sync` 的结果为 32 通过、2 失败；`lint` 退出码为 0。报告目标路径的 `git diff --check` 通过；由于报告是新建文件，还额外执行了报告自身的换行、围栏和链接检查，避免仅依赖 Git 对未跟踪文件的检查范围。

报告的环境探测结果见 [environment.json](validation/environment.json)，结构与链接结果见 [report-validation.json](validation/report-validation.json)，源码摘要见 [source-evidence.json](validation/source-evidence.json)。HTML 阅读器由独立的无界面 Edge 进程检查，详情见 [browser-validation.json](validation/browser-validation.json)。这些文件是本次验证输出，不是产品运行配置。

离线阅读版已在 1440×1000 和 390×1000 视口验证：七章齐全、页面无 JavaScript 错误、无 HTTP(S) 网络请求、整页无水平溢出，目录锚点和明暗切换有效。截图为 [报告桌面视图](validation/report-desktop.png)、[报告窄屏视图](validation/report-mobile.png) 与 [安装包教程视图](validation/report-packaging.png)。
